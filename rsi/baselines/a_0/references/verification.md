# 核验清单

核验的目标是**换一条路线确认**，不是把同一段代数重新抄一遍。按题目实际涉及的知识选择检查项；综合题可以同时执行多组检查。

## 选核验路线

优先顺序（不是硬性顺序，按题目可用性选择）：

1. **代回原题**：把答案代回原方程、原不等式或原始几何关系。
2. **检查定义域与排除值**：分母不为零、偶次根号下非负、对数真数为正、反三角函数范围、几何对象非退化。
3. **逆向检查变形**：平方、去分母、去绝对值、约分、取对数是否可逆；不可逆时是否已单独讨论。
4. **边界与特殊值**：区间端点、参数临界值、等号成立条件、极端几何位置。
5. **独立推导**：用另一种方法或另一条代数路径得到同一结果。
6. **工具计算**：符号计算或数值计算，仅在工具真实可用且实际执行时使用。

数值例子只能作为诊断性检查。一个例子通过，不证明一般命题；一个例子失败，足以否定一个全称命题。

## 方程与不等式

- 检查分母为零的排除值。
- 检查平方、两边同乘未知符号表达式、去绝对值等操作引入的增根。
- 检查乘以或除以负数时不等号方向是否翻转。
- 把解代回**原题**，而不是只代回变形后的方程。
- 不等式解集要与定义域、参数范围取交集。
- 参数不等式要检查临界参数值，以及参数变化时解集结构是否改变。

## 函数

- 检查题目要求的定义域与值域限制。
- 用适用条件验证单调性与极值；不要只凭图像印象。
- 区分局部极值与全局最值。
- 检查区间端点，以及最值是否真的能取到。
- 反函数结论要核对一一对应条件与定义域、值域互换。
- 复合函数、分段函数的连接点要单独检查连续性与取值。

## 数列

- 验证首项与递推条件。
- 检查索引范围，特别是递推从哪一项开始成立。
- 区分“验证了前几项”与“对任意正整数项成立”。
- 用数学归纳法时，检查初始情形与归纳步是否都完整。
- 求和公式要检查项数与边界项；等比求和的公比为 1 时要单独处理。
- 只有给出收敛性所需推理时，才讨论极限或收敛。

## 几何与向量

- 检查几何假设是否彼此一致，是否满足题设的平行、垂直、相等、共线关系。
- 检查坐标设定、向量运算与符号。
- 区分图形直观与已证明的几何事实；图不能代替题设。
- 检查退化情形：三点共线、线段端点重合、直线斜率不存在、圆半径为零等。
- 联立所得候选点要回到原曲线与原几何关系核对。
- 立体几何中检查线面关系、二面角范围与法向量方向。

## 概率与统计

- 明确样本空间与事件定义。
- 检查概率非负且不超过 1，所有基本事件概率之和为 1。
- 使用加法或乘法公式前，确认事件互斥或独立是否真的成立。
- 条件概率要写清条件事件与分母。
- 计数时检查是否遗漏或重复；排列与组合的选择要与“是否计顺序”一致。
- 分布列、期望与方差要核对归一化和取值范围。

## 证明

- 检查每个蕴含是否有依据，是否使用了题设中没有的条件。
- 检查要证的是单向还是双向；双向命题不能只证一半。
- 识别循环论证、把结论当前提、用例子替代一般证明。
- 分类讨论要检查是否穷尽、各类是否互斥。
- 反证法要写清假设的否定，并推出真实矛盾。
- 存在性命题要给出具体对象或构造；任意性命题要对一般情形成立。

## 常见非等价变形

| 操作 | 风险 | 处理 |
| --- | --- | --- |
| 两边平方 | 可能引入增根 | 代回原式，或补充符号条件 |
| 两边同乘含未知数的式子 | 可能引入或丢失解 | 讨论该式是否为零 |
| 两边同除以含未知数的式子 | 可能丢失零解 | 先单独讨论除式为零 |
| 去绝对值 | 可能漏分支 | 按符号分类，或平方后核对 |
| 取对数 | 真数必须为正 | 先写定义域 |
| 开偶次方 | 正负两支 | 明确取哪一支及理由 |
| 约分 | 可能改变定义域 | 记录排除值 |
| 不等式两边乘负数 | 方向翻转 | 显式改写方向 |

## 记录核验结果

每条检查写入 `verification.checks`：

```json
{
  "name": "代回原方程",
  "status": "passed",
  "details": "x=2 代入左边得 2，右边得 2，成立；x=-1 代入左边得 1，右边得 -1，不成立。"
}
```

状态用法：

- `passed`：实际检查并通过。
- `failed`：实际检查发现错误，且尚未解决。
- `not_applicable`：该题不适用这项检查。
- `not_completed`：需要但无法完成（缺信息、工具不可用等）。

整体状态：

- 全部相关检查通过 → `passed`。
- 有 `failed` 且未解决 → `failed`。
- 依赖歧义、缺失信息或未完成检查 → `needs_review` 或 `not_fully_verified`。
- **不要仅凭推导看起来顺眼就报 `passed`。**
