# 技术贡献与答辩依据

本项目的数学能力来自宿主大模型；项目贡献需要以可运行的教学流程与可验证机制表达。

| 机制 | 原先风险 | 当前实现 | 证据口径 |
| --- | --- | --- | --- |
| 任务路由 | 求解结果可能替代学生原过程 | 按反馈意图与材料分流；有学生过程时优先诊断 | 路由回归与真实 UI 调用；不声称通用语义路由准确率 |
| 四技能编排 | 原 Solution Refiner 曾从主分支移除，独立技能无法串入作业流程 | 恢复原技能及版本交接检查；工作台以 Math Error Diagnosis 的正确判定作为前置，再调用 Solution Refiner 并重放两道原生门 | `refine` 集成回归、handoff 内容版本测试；模型判正确不等于形式化证明 |
| 首错绑定 | 编造或引用错误步骤 | 首错 step 对应非空行编号，quote 必须属于该行 | 自动绑定检查只证明引用存在，不证明数学理由成立 |
| 校验反馈 | 有 schema 却没实际运行 | 重放原始门，真实错误反馈最多修正两次 | 原始尝试、退出码与修正成功数 |
| 修订状态 | 旧结论错误套用到新过程 | 不可变提交、内容 SHA256、当前版本指针 | 包含旧调用晚完成的回归测试和真实修订演示 |
| 提示控制 | 一次给完答案影响学习 | hint 模式跨轮保持；显式切换才能完整反馈 | 字段门加实际语义评测；不能以关键词检查保证不泄露 |
| 数学工具 | 把自查说成外部验证 | 受限 AST 构建符号表达式，执行指定等式代回与多项式恒等检查 | 精确残差、引擎版本、请求摘要和实际时间；不验证整题完备性 |
| 评测溯源 | 夹具高分被当作能力 | 三组真实调用、冻结源、匿名辅助复核、人工包分开 | 所有结论都可追到原始输出；未取得的人工评分不补写 |

可在答辩中回答：

- “为什么不直接问大模型？”：展示相同模型下新增的原文绑定、提交状态、反馈模式与可审计校验；效果差异以对照结果为准。
- “是不是多写了提示词？”：技能文档是其中一层，运行器、版本数据库、门反馈循环、真实日志和评测复现属于可执行机制。
- “数学一定正确吗？”：明确模型复核、结构检查、指定等式的外部符号计算、真人审阅分别提供什么证据，不合并为一个笼统的“已验证”。
- “草稿分析真的有用吗？”：先看观察是否有版面证据，再看下一题动作是否具体；需要真实学生与教师进一步验证教育效果。
