# 验证说明

本项目包含三个技能、根目录调度规则、交接协议与标准库检查脚本。历史试用和审查记录已合并为本说明及 [代表案例](代表案例.md)。

## 复现方法

在仓库根目录使用 Python 3，无需安装第三方运行依赖：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 tests/核验测试数学.py
python3 tests/新例计算核验.py
python3 tests/高中题型计算核验.py
```

- 衔接回归测试：8项，覆盖准入状态、当前内容版本、非法协议、退出码、卡片接口、额外字段及非UTF-8输入。保留数学错误卡片通过两门的反例。
- draft-coach 门测试：`draft-coach/tests/` 下两份共22项（`test_validation.py` 8项：结构门 + hint；`test_audit.py` 14项：审计门 + refuse），覆盖错误清单结构（缺清单、缺 errors、scope 为空、errors 非数组、条目缺字段）、六维结构（缺维度、评分越界、习惯数、重复习惯、多余字段、`positive` 只许出现在涂改模式、"不适用"只许出现在草稿利用率）、四类非法输入、编造错误的反例（`A_LABEL`/`A_PLAN`/`W_ERROR_NOT_IN_DRAFT` 三条命中）、**判对错已被允许**（"这一步算错了""正确答案是"不再越界）、假设性风险与核心词汇的放行、草稿脱节、学段用词错配、整张草稿纸多题提示（含 `f(1)=-2` 不误报）、"完整过程"这类描述不误判为给完整解答，以及 `refuse` 三个出口的退出码与可复现性。

## 审查要点

PR #1 合并前已修复非法编码输入的JSON错误输出、基本不等式非负条件、固定三方向诱导凑数、单题能力标签四项问题。优化方向不足三个真实改进时不生成卡片，说明原因；不虚构短板。

## 验证边界

交接脚本只核验元信息、当前题目与过程版本，不证明数学正确性、身份或授权。卡片validate/audit只检查结构与措辞；宿主需审查建议的数学依据和实际改进。

draft-coach **首要功能是查错，而"这处算错了"恰恰是它两道门唯一验不了的东西**。结构门只查错误条目有没有四个字段；措辞门只能查"你说的那处在草稿里找不找得到"（`W_ERROR_NOT_IN_DRAFT`），查不了"你判得对不对"——引用了草稿却把对的判成错的，它一声不响。它也不核实卡片说某处"跳步"是否属实。**没有人工复核的草稿检查卡不构成数学结论。**

草稿关联度（`W_DETACHED_DRAFT`）与错误证据检查都用数字与 ASCII 标识符的重合判断，草稿很短或全是中文时这项检查会整段跳过；反过来，证据里出现的新数值（比如"应改成 4"）如果写在 `evidence` 而不是 `fix` 里，也可能被误报成查无此据。图片与 OCR 依赖宿主，**本项目不含手写转写技能**：图片草稿的内容只能由学生自己给出文字，本项目只处理文字还原或学生给的文字描述。

较早代表案例由同一助手产生与复核；本次新增评测采用不同作答上下文和匿名独立复核，仍使用同一模型，不是人类或异模型验证。浮点样本不能证明解集完备；一般结论仍须分类、边界与代数推导。未验证自动技能选择、真实跨消息提示保持或图像识别，不能据有限案例声明任意高考题可靠性。

草稿门层报告（`tests/behavior-evaluation/draft_gate_report.py`）只重放已保存卡片的退出码，**不重新调用模型、也不重新作答**；它读出的"全部通过"只说明卡片没越过结构线与措辞线，不说明"这处算错了"判得对不对。草稿评测的12条草稿是合成材料，不是真实学生草稿，也不是随机抽样；该轮两条件在 `math`、`grounded`、`scope`、`mode`、`actionable` 五项上同时满分，存在天花板效应，不能据此声明 Skill 提高了判定准确率。`boundary` 一项的判定存在灰区（"给出参考解答"算脚手架还是算越界），核验者已主动标出，具体见该文档的限制一节。
