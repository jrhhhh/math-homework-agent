# 验证说明

本项目包含三个技能、根目录调度规则、交接协议与标准库检查脚本。历史试用和审查记录已合并为本说明及 [代表案例](代表案例.md)。

## 复现方法

在仓库根目录使用 Python 3，无需安装第三方运行依赖：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 tests/核验测试数学.py
python3 tests/新例计算核验.py
python3 tests/高中题型计算核验.py
```

- 衔接回归测试：8项，覆盖准入状态、当前内容版本、非法协议、退出码、卡片接口、额外字段及非UTF-8输入。保留数学错误卡片通过两门的反例。
- draft-coach 门测试：`tests/test_draft_coach.py`，18项，覆盖六维结构（缺维度、评分越界、习惯数、重复习惯、多余字段、`positive` 只许出现在涂改模式、"不适用"只许出现在草稿利用率）、四类非法输入、越界反例的四条命中码、假设性风险与核心词汇的放行、草稿脱节、学段用词错配，以及 `refuse` 三个出口的退出码与可复现性。
- 固定数学计算：分别10、6、11组，共27组。后两个脚本生成相邻JSON证据，首个输出JSON到终端；结果可重建，不提交生成文件。
- 前两个技能在2026-10-09用 skill-creator 的 `quick_validate.py` 检查过。**新增 draft-coach 时环境里没有该验证器，这一项没跑**；改做的是等价且可复现的结构检查：三份 SKILL.md 的 frontmatter YAML 与两份 `agents/openai.yaml` 均可解析、示例 JSON 全部可解析、全部 Markdown 相对链接可达、`draft-coach` 门的退出码由 unittest 覆盖。

上述检查在2026-10-09通过；draft-coach 的检查在2026-10-10通过。技能结构检查需要宿主提供 skill-creator 验证器及其依赖，不属于项目运行依赖。

## 审查要点

PR #1 合并前已修复非法编码输入的JSON错误输出、基本不等式非负条件、固定三方向诱导凑数、单题能力标签四项问题。优化方向不足三个真实改进时不生成卡片，说明原因；不虚构短板。

## 验证边界

交接脚本只核验元信息、当前题目与过程版本，不证明数学正确性、身份或授权。卡片validate/audit只检查结构与措辞；宿主需审查建议的数学依据和实际改进。

draft-coach 的两道门同样不检查教学质量：结构门只查卡片长得对不对，措辞门只抓固定说法，换个说法就绕得过去。它**不核实**卡片说某处"跳步"是否属实，也不判断该习惯观察成不成立，宿主必须自己读草稿。草稿关联度（`W_DETACHED_DRAFT`）用数字与 ASCII 标识符的重合判断，草稿很短或全是中文时这项检查会整段跳过。图片、笔迹与 OCR 依赖宿主，本项目只处理文字还原或布局描述。

诊断案例由同一助手产生与复核，没有独立模型盲测。浮点样本不能证明解集完备；一般结论仍须分类、边界与代数推导。未验证自动技能选择、真实跨消息提示保持或图像识别，不能据有限案例声明任意高考题可靠性。
