# 高中数学教师 Agent

面向高中数学教学与学习的本地智能体工作台，支持备课、练习布置、学生作答、过程诊断和针对性教学。教师可以从教学目标出发布置任务，学生提交自己的解题过程，教师再依据当前诊断调整教案或安排再练习。

```text
教学目标 → 学习任务 → 学生作答 → 过程诊断 → 补救或巩固教学 → 再练习
```

数学内容覆盖函数与导数、三角函数与解三角形、圆锥曲线、数列、向量与立体几何、概率统计，以及集合、逻辑、复数等基础代数。

## 快速开始

需要 Python 3.10+，以及已安装并登录的 Codex CLI。可用 `codex login status` 检查登录状态。

在仓库根目录运行：

```bash
python3 run.py
```

Windows PowerShell 可用 `py -3 run.py`，或直接指定解释器路径。macOS 与 Windows 共用同一份代码；若 `codex` 不在 `PATH`，用 `MATH_CODEX_BIN` 指向 CLI。

打开 [本地工作台](http://127.0.0.1:8765/)。练习保存、模型调用和课件生成由本地服务处理；直接打开 `app/static/index.html` 只能查看启动提示和界面预览。

教师备课的课件生成功能需要安装依赖：

```bash
python3 -m pip install -r lesson-materials-builder/requirements.txt
```

按需安装 PDF 文本提取和数学等式核验组件：

```bash
python3 -m pip install pypdf
python3 -m pip install -r requirements-verify.txt
```

运行选项：

| 配置 | 用途 |
| --- | --- |
| `python3 run.py --port 8765` | 指定本地服务端口 |
| `python3 run.py --db .local/workbench.sqlite3` | 指定练习与备课数据库 |
| `MATH_CODEX_BIN` | 指定 Codex CLI 路径 |
| `MATH_API_BASE` | 设置后改用 OpenAI 兼容 HTTP 接口，不再需要 Codex CLI |
| `MATH_API_KEY` | HTTP 后端的密钥；本地无鉴权服务可不设 |
| `MATH_API_STYLE` | HTTP 接口风格：`chat`（默认，`/chat/completions`）或 `responses` |
| `MATH_MODEL` | 指定模型；HTTP 后端必填，Codex 后端未设置时沿用用户配置 |

不设置 `MATH_API_BASE` 时，模型通过已登录的 Codex CLI 调用。设置后走直连 HTTP，适合没有安装 Codex 的电脑：

```bash
MATH_API_BASE=https://api.deepseek.com/v1 \
MATH_API_KEY=... \
MATH_MODEL=deepseek-flash \
python3 run.py
```

也可以启动后在页面右上角「模型设置」中保存后端、接口地址、模型和密钥，无需重启。环境变量优先于页面设置；密钥只保存在本机 `.local/model_settings.json`，页面只显示是否已设置，不回传明文。

服务只监听本机回环地址。当前支持师生共用一台设备和数据库的协作演示，尚不提供独立账号、跨设备提交或班级权限管理。

## 工作台怎么用

### 学生练习

填写原题和自己的解题过程，选择过程检查、单步提示、完整纠正或仅核对答案。只有题目且需要完整解答时，可选择求解；想比较更简洁的方法时，可请求优化，系统会先诊断当前过程。

工作台的“附件与补充要求”可按需展开；按 Ctrl / ⌘ + Enter 可以提交练习、备课与师生任务表单。任务中心集中显示后台进度和结果，支持键盘关闭与返回。

每次提交单独保存，修订后会重新检查，旧反馈保留为历史。提示模式持续到学生明确切换；练习记录可以导出为 JSON。左侧练习栏支持归档与删除：归档只隐藏到“归档”分区，删除会移除该练习及其全部提交，并清理不再被其他练习引用的附件文件；已被师生任务引用的练习不能删除，只能归档。可选的等式工具核验会实际执行代回或多项式恒等检查，并展示检查范围。

草稿习惯反馈接收学生提供的文字还原或布局描述，关注分区、分行、划改、标注和留白。所有练习模式都可以附加最多 3 个附件（图片、PDF、DOCX、TXT、MD，每个不超过 5 MB）。附件只保存在本机、供学生自己对照，**不会发给模型，也不做手写识别**；分析仍然只依据学生填写的文字。PDF / DOCX / TXT / MD 可以通过“提取文字”把**数字文本**放进输入框，学生核对后再提交；扫描版 PDF 没有可复制文字时不会尝试 OCR。草稿模式尤其需要文字描述。它不判断数学对错；要求检查草稿中的数学过程时，由过程诊断处理。

### 教师备课

填写课题、年级、教材版本和课时，粘贴教案或上传 `.docx`、可提取文本的 `.pdf`、`.md`、`.txt` 文件。

系统先整理逐页大纲。教师补充缺失信息、编辑并确认大纲后，生成可编辑的课件 Markdown；检查源码后再渲染 PowerPoint，执行结构与几何复核并下载文件。课件围绕题目、推理、图形、检验和练习组织内容，支持函数图像、单位圆等数学配图。文字可编辑，配图为图片；数学内容和实际放映效果仍需教师审阅。

### 师生任务

1. **教师布置任务**：填写原题与每题目标与成功标准，或依据教学目标起草练习。模型草案标注为未做数学核验，教师检查条件与可解性后发布。
2. **学生领取作答**：从任务进入学习路径，先自己尝试，再按需查看提示、数学活动或完整讲解；每次提交保留当时的帮助条件。
3. **教师回看证据**：刷新查看每题当前提交的诊断，区分未提交、处理中、诊断失败、过程正确、有错、论证缺口和仅答案等状态。
4. **调整教学**：依据当前有效诊断起草可编辑教案，交给教师备课，或发布关联的再练习及同目标新题复核。

任务原题与学生提交保持绑定。学生修订后，旧补救计划会标记过期；备课交接和关联再练习也会检查证据版本。重复修订按同一任务项追踪，不作为多个学生或独立样本统计。

同目标新题复核沿用成功标准，不能重复教学链中已发布的原题。帮助后修订正确与提交前未记录帮助的新题表现分开显示；单次通过不证明稳定掌握。固定数学活动支持二次函数、单位圆及割线与切线。

长任务进入右上角任务中心，关页后仍运行。服务重启后，中断任务暂停供手动继续；有效的阶段结果会复用，课件文件通过哈希检查后复用。停止请求在当前步骤结束后生效。

学习流程、恢复边界及 OpenMAIC 设计参考见 [学习路径与任务恢复](docs/learning-path.md)。详细数据约定与接口见 [师生任务交接协议](docs/teaching-loop.md)。

## 技能分工

[高中数学教师 Agent](high-school-math-teacher-agent/SKILL.md) 按用户目标和输入材料调度技能，仓库根目录的 [AGENTS.md](AGENTS.md) 提供项目级调用约定。

| 技能 | 负责的教学任务 |
| --- | --- |
| [Learning Task Designer](learning-task-designer/SKILL.md) | 将教学目标和教材材料整理为可发布的练习任务 |
| [Math Solver](math-solver/SKILL.md) | 从零求解数学题，给出分步推导与复核说明 |
| [Math Error Diagnosis](math-error-diagnosis/SKILL.md) | 检查学生原始解答，定位首错、论证缺口并提供反馈 |
| [Solution Refiner](solution-refiner/SKILL.md) | 在当前学生过程经完整诊断为正确后，提出解法优化方向 |
| [Draft Coach](draft-coach/SKILL.md) | 根据学生提供的草稿描述，反馈版面组织习惯或进行版面分区 |
| [Learning Evidence Bridge](learning-evidence-bridge/SKILL.md) | 汇总任务当前提交的诊断证据，保留可追溯版本 |
| [Remedial Lesson Planner](remedial-lesson-planner/SKILL.md) | 将当前证据转为补救或巩固教案及再练习目标 |
| [Lesson Materials Builder](lesson-materials-builder/SKILL.md) | 将教师确认的教案与大纲制作成可编辑课件 |

技能也可在支持本地 Skill 的宿主中使用。可让 Agent 读取仓库中的 `AGENTS.md`，或按宿主要求安装所需技能目录；组合使用时保留技能之间的引用关系。Codex 常用技能目录为 `~/.codex/skills/`，覆盖同名目录前应先比较版本。

调用示例：

```text
请使用 $high-school-math-teacher-agent，围绕“解三角方程时保留全部分支”设计学习任务，
在我确认题目后用于学生练习，再根据学生实际提交规划针对性教学。
```

```text
请使用 $math-error-diagnosis，只给一个提示，不要直接告诉答案。

题目：在 0≤x<2π 内解 sin(2x)=sin(x)。
我的过程：用二倍角公式后，两边除以 sin(x)，得 cos(x)=1/2，
所以解只有 π/3 和 5π/3。
```

## 验证与评测

在仓库根目录运行全量常规验收：

```bash
BENCH_IDENTIFIERS='姓名,学号' python3 scripts/verify_all.py
```

运行前将示例值替换为分享材料中需要检查的实际标识符。摘要只记录配置数量，不记录标识符内容；专用测试标记仅能验证扫描流程，不能替代实际身份信息检查。

验收覆盖技能输出约束、工作台、交接版本、数学核验组件、课件生成器回归、Schema 和固定数学案例。当前执行记录见 [验收摘要](docs/delivery/evidence/verification.json)。

师生链路可单独验证：

```bash
python3 -m unittest app.tests.test_teaching_loop -v
```

浏览器端到端验证使用明确的测试替身；真实模型接口检查通过 Codex CLI 执行，两者的复现方法和证据范围见 [师生任务交接协议](docs/teaching-loop.md)。

[三组对照评测](evaluation/course-2026-10-22/README.md) 保存模型辅助评测的案例、输出与评审记录，真人复核尚未完成。评测结论只适用于其冻结代码和样本，不能直接作为当前全部功能的准确率或教学效果证明。

## 能力与证据边界

- **学生过程与助手解答分开保存**：求解稿不冒充学生原文；只有答案时不推断未提供的过程。
- **诊断绑定当前版本**：题目、来源、学段或解答变化后，不能继承旧结论。优化解法需先完成当前过程诊断。
- **检查结果分别陈述**：模型复核、JSON 结构检查、措辞审计、等式工具核验、PPT 几何检查和人工审阅各有范围，不能互相替代。
- **数学核验有明确范围**：代回有限候选值不证明解集完备；同一助手换路线复核不等于第三方验证或形式化证明。
- **课件需要教师审阅**：结构与几何检查不证明数学内容正确，也不能代替实际放映软件中的动画与视觉检查。
- **不内置手写识别或教材数据库**：手写内容需由学生提供文字并确认；外部 OCR 只能作为线索。教材事实以教师提供或指定的材料为依据。

本地练习、提交和备课记录由运行时创建的数据库保存。分享课件或实验材料前，应核查原题、引文和自由文本中的个人信息。
