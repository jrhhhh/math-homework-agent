# `课件.md` 语法规范

这份文件是 `课件.md` 的写法说明，也是 `build_pptx.py` 的实现契约。两者必须严格一致 ——
改语法就要同步改脚本，反之亦然。

设计取向：**Markdown 当源，.pptx 当交付物。** 用户改 markdown 重新渲染即可，
不必在 PowerPoint 里手工返工。所以语法要简单到能手写，不能是某种配置文件方言。

---

## 文件结构

```markdown
---
title: 导数的概念及其意义
subtitle: 讲师：示例教师
version: daily
---

# [封面] 导数的概念及其意义
讲师：示例教师
教材：高中数学人教A版选择性必修二

# [标题] 温故知新
- 用二次函数拟合跳水轨迹
!img: figures/diving.png h=4.2
> 研究整体轨迹就足够了吗？我们如何研究一段时间内的变化？

# [重点] 导数的意义
- **几何意义**：瞬时变化率
- **物理意义**：瞬时速度
!!! 数形结合，以直代曲

# [例题] 例题巩固
- 已知圆锥的底面半径为 r，高为 h，求它的体积 V
!ans: 圆柱体积 V = πr²h
!ans: 等底等高的锥体体积为圆柱的 1/3
!ans: 故 V = 1/3 πr²h
!img: figures/cone.png
```

### frontmatter

| 字段 | 必需 | 说明 |
|---|---|---|
| `title` | 是 | 课件标题，写入文件属性 |
| `subtitle` | 否 | 封面副标题（封面自己写了副标题行时以封面为准，避免重复） |
| `theme` | 否 | `scholar-red` 绛红书院、`ink-teal` 墨青研习、`classic` 旧版；项目内置底版默认绛红书院，用户自备底版默认保留 |
| `version` | 否 | `daily`（默认）或 `contest`。`contest` 时校验是否含阐述页 |

**课题与教材出处只在封面出现一次。** 早期版本把它们做成每页页脚，结果是学生每翻一页
都重读一遍早就知道的信息，还占掉一行正文空间。现在页脚已取消：教材行写在封面页里，
内页什么都不留。

**「内页」包括阐述页。** 阐述页是给评委看的，容易被当成「另一个封面」补上课题与教材，
但评委席上更不需要被提醒这是哪节课 —— 他们手上就有教案。实测作者本人的参赛 PPT：
P12「教学设计阐述」直接以「教学目标」开头，P13「教学重难点及解决」直接以「重难点」
开头，两页都没有课题、没有教材出处。阐述页第一行就是要素本身，不铺垫。

## 页面

每页以 `# [版式] 标题` 开始。版式见 `deck-rules.md` 的版式选用表。

```markdown
# [标题] 温故知新
```

- `[版式]` 省略时默认为 `标题`
- 标题必填。超过 12 字时渲染器告警（规则 3）
- 一页的所有内容写在下一个 `# ` 之前

### 可选：页级注释

```markdown
<!-- 允许无图 -->
```

标记本页豁免「建构段必须有图」的检查（规则 5）。只在该页确实无几何对象可画时使用，
并确认理由站得住 —— 滥用这个标记等于关掉了一条质量约束。

## 教师演讲者备注

```markdown
!note: 时间：3分钟；任务：独立写出分类条件。
!note: 预期回答：先判断除式是否为零；追问：原题保证非零吗？
!note: 卡住时先提示代入 x=0；板书保留两个分支；转场到因式分解。
```

多行 `!note:` 按顺序写入当前幻灯片的演讲者备注，PowerPoint 普通放映中不显示。备注不当作要点、题目或点击答案；教师可在备注视图编辑。练习题答案可放备注或后页讲解，不能依赖静态 PDF 隐藏答案。没有 `!note:` 的旧源码仍可生成。

## 页内元素

### 要点行

```markdown
- 一级要点
  - 二级要点
```

一级渲染为 28pt，二级为 24pt。**一级要点单页不超过 6 行**（规则 7），超出告警。

**数学表达准确、任务明确**（规则 9）。概括内容可用短语，题目、追问和推理依据可用完整句子；不为压缩字数删去条件。
一句聚焦一个主要信息。`check_wording` 会扫一遍并在命中时告警（词典命中高置信、
断句启发式低置信），但规则 9 那四条判据的实质要靠**把要点行念出来**自测。
下面的示例刻意都用书面语，别照着反向学。

### 加粗

```markdown
- **几何意义**：瞬时变化率
```

只用于核心术语与结论句（规则 8）。这是自律条款，渲染器无法自动判定，
但如果 `**` 包住的片段超过全页字符数的三分之一，说明强调失效了。

### 强调块

```markdown
!!! 数形结合，以直代曲
```

渲染为 32pt 居中强调块，用于「本页要得出的那句话」。**每页最多一个** ——
两个强调块等于没有强调。

### 驱动问题

```markdown
> 对于不同的点，不同类型的函数呢？能否用一个数学概念解决一般的问题？
```

渲染为页面底部的高亮问题行。作用是让学生带着悬念翻页（规则 4）。
放在**每个认知台阶的最后一页**，不必页页都有。

**驱动问题是 `check_wording` 的豁免项**：它本来就该是一句问话，正当使用「吗 / 呢 /
凭什么」。没有这条豁免，`体积凭什么不变？`、`把「每一本」换成「每一个截面」，还行吗？`
这类合格的驱动问题会被逼着改成不自然的问句 —— 那是本末倒置。豁免只针对驱动问题，
`-` 要点行里出现同样的词照报。

### 插图

```markdown
!img: figures/secant.png
!img: figures/secant.png h=4.2
!img: figures/diving.png w=6.0
```

- 路径相对于 `课件.md` 所在目录
- `h=` 英寸指定高度，`w=` 指定宽度；都不给则按原始尺寸缩放至不超过版心
- 缩放**等比进行**：`h=` 让图比版心还宽时会整体缩小，不会只压扁宽度
- 图片缺失时**不中断渲染**，改为插入一个占位框并告警 —— 缺图时先看到整体结构，
  比渲染失败更有用

**图放在哪儿由图自己决定**，不由你写版式指定。`[标题]` 版式按图的宽高比自动分派：

| 图的宽高比 | 版式 |
|---|---|
| < 1.5（竖幅、方形） | 左文右图并排，文字栏约占版心 46% |
| ≥ 1.5（横幅） | 上图下文，图占满版心宽 |

两种情况下图都在自己所在的栏/版心内**水平居中**，文字块在正文区内**垂直居中**。
竖幅图不必自己裁成横幅来迁就版面。

**一页只渲染第一张图。** 需要并排多张请用 `[流程]` 或 `[两栏]`。

### 解答块

```markdown
!ans: 圆柱体积 V = πr²h
!ans: 等底等高的锥体体积为圆柱的 1/3
!ans: 故 V = 1/3 πr²h
```

**放映时点击一次，整个块一起出现。** 用它来表达教案里「引导学生思考讨论」的地方 ——
先给问题，答案等着点。多行 `!ans:` 合成**一个**块（同一次点击一起出现），
不做逐行揭示：逐行要写 `p:bldLst` 文本构建 XML，风险面大得多，而分步推演本来
更适合在黑板或留白区走。

字号比题干小一号（24pt），文字用正文色 —— 驱动问题是蓝、强调块是橙、答案是正文色，
分量依次递减。答案的"出现"本身就是醒目事件，不必再靠颜色强调一次。

**归宿分两种**：

| 版式 | 解答块画在哪 |
|---|---|
| `[例题]` | 题干下方的**左下留白**里，是这块留白的主要用途 |
| 其余版式 | 页面底部的堆叠区，排在强调块与驱动问题**之下**（结论 → 问题 → 答案） |

`[封面]` / `[阐述]` 不渲染底部块，写在这两个版式上的 `!ans:` 会**整段消失**并告警。
这类消失特别隐蔽：答案本来就是"点一下才出现"，少一块不像出错。

**交付前必须复核动画真的挂上了** —— 见 SKILL.md「先问题后答案」一节里的 COM 读回命令。
那段时序是手写的底层 XML，写坏了演示软件可能安静地忽略掉，构建阶段看不出来。

### 两栏

仅 `[两栏]` 版式使用：

```markdown
# [两栏] 定量看

- 割线斜率：Δy/Δx
- 让 Δx 趋近于 0

## 右
!img: figures/secant.png
```

### 流程页

用于把「先 A，再 B，最后 C」的推导过程**排在同一页上**，用箭头串起来。
这是课本讲「三棱柱分成三个等体积三棱锥」这类分割过程的常见呈现方式 ——
拆成三页翻过去，学生记不住上一步长什么样。

```markdown
# [流程] 分割锥体
1. !img: figures/prism_1.png | 三棱柱体积 Sh
2. !img: figures/prism_2.png | 切出第一个三棱锥
3. !img: figures/prism_3.png | 三个锥体体积相等
> 每个三棱锥的体积是多少？
!ans: 每个三棱锥体积为 **V = 1/3 Sh**
```

注意第 3 步的说明**不能写成「各为 1/3 Sh」** —— 那句话正是本页要留到点击才出现的
答案（`!ans:`）。说明一旦把它说破，`!ans:` 就只是把已经看到的东西又显示一遍。

`|` 之后是该步的说明文字（可省略）。渲染规则：

- N 张图横向并排，图之间用箭头连接，箭头画在间隔的**垂直中线**上
- **各图统一到同一尺度**：先取一个共用的"着墨高度"，再按各自的形状分宽。这一页的
  价值就是让上一步和这一步同时在场被对照，尺度不统一的话，学生看到的是三张大小不一
  的插画，而不是"同一个东西变过来的三步"
- 着墨区之外的**白边会被自动裁掉**（`a:srcRect`），所以出图时补白与否都不影响结果；
  但**形状差得太多**（比如两个竖高的图配一个横宽的图）统一尺度后图形会小到看不清，
  这时渲染器告警，**正确反应是重出图让各步形状接近，或拆页，不是去补白**
- 说明文字固定在底部同一基线，左右居中，读成一张表。说明可以借用两侧的间隔，
  所以比图宽略宽一点
- **说明的长短受"本格图宽"约束，不是受整行宽度约束。** 窄图的说明列也窄，会先折行，
  而折出来的行要占高度、把图区压矮。20pt 下一格能放的字数约为 `列宽(in) × 3.6`：
  两栏宽的窄格（约 2.4in）只放得下 8 个字符。所以说明要写成**短标签**（`切出第一个三棱锥`），
  不写成句子（`一个三棱柱，体积已知为 Sh` 会折成两行）
- **建议 ≤ 4 步**。再多人就得凑近看，该拆页或改回多页
- 流程页一般**不要**再放 `!!!`。图和说明已经占满，再加强调块会把图区压扁。
  带 `!ans:` 时更要留意 —— 说明行、驱动问题、解答块三层叠上去，图区就只剩不到一半

`[分步]` 是旧版式名（同一过程拆成 N 张幻灯片），仍可用但会提示改名。

### 例题页

模板的职责是**别把解答写死**。`[例题]` 版式留出一块固定区域给解答或手写：

```
y=1.42 ┌──────────────────────────────────────┐
       │ 题干：占满版心宽，28pt，左对齐，贴顶     │
       ├───────────────────┬──────────────────┤
       │  留白 60%          │   配图 40%        │
       │  （!ans: 落在这里，  │  （在本区居中）    │
       │    点击后显现）      │                  │
y=6.85 └───────────────────┴──────────────────┘
```

```markdown
# [例题] 例题巩固
- 已知圆锥的底面半径为 r，高为 h，求它的体积 V
!ans: 圆柱体积 V = πr²h
!ans: 等底等高的锥体体积为圆柱的 1/3
!ans: 故 V = 1/3 πr²h
!img: figures/cone.png
```

- **题干必填**，写成要点行、贴顶、占满版心宽。没有题干会告警 —— 这个版式靠题干
  压顶，配图和留白都排在它下面，没有题干时整页只剩一张图加一个悬空的解答
- **固定 28pt，不参与自适应填充**。填充的职责是把文字撑满可用高度，与"故意留白"
  正好相反。题干过长时告警，该改的是题干本身
- **配图可选**（"如果有配图"）。挂在题干下方、版心右侧 40% 区内并水平垂直居中；
  没有配图时下半区整片留白，解答块放宽到满版心
- **左下 60% 是故意空着的**：要么放点击后显现的解答，要么就是留给老师在投影上写、
  或学生上台写的。别拿它当"排版没排满"去补内容
- 答案块**贴顶**排在留白区里（紧接着题干往下读），不在留白区里垂直居中 ——
  居中会在题干与解答之间空出一截，读着像两件不相干的东西
- 这个版式里也可以写 `!!!` 与 `>`，与其它版式一样走底部堆叠区
- **不进"建构段必须有图"的检查**：配图是可选的

### 阐述页

仅比赛版（`version: contest`）追加：

```markdown
# [阐述] 教学设计阐述
- **教学目标**：（1）……
- **理论依据**：逆向设计 + APOS 理论

# [阐述] 教学重难点及解决
- **重点**：……
- **难点**：……
- **解决路径**：……
```

细则用 16pt。阐述页**第一行就是上面的要素本身**（`教学目标` / `重难点`），不写课题、
不写教材出处 —— 理由见前面 frontmatter 一节。

#### 写不出来的条目，留占位符

**教学目标、重难点、解决路径**这三类可以从教案里提炼，直接写实。真正写不出来的是
**理论依据 / 教学理念**那段论述 —— SKILL.md 已说明那部分需用户自己写，代笔在比赛中
反而减分（评委一眼能看出套话）。

写不出来时，**必须留一个显眼的占位符**，而不是：

- ❌ 留空 —— 版面看着像渲染漏了，用户不一定会回头补
- ❌ 硬编一段通用套话（「本课以学生为主体，注重核心素养的培养」）—— 比留空更糟：
  它读起来像成品，用户很可能就让它这么交上去了
- ❌ **把本技能自己的说明文字抄进幻灯片**（比如「这里的教学理念原创表述需用户自己写」
  「代笔在比赛中反而减分」）—— 那是写给写课件的人看的，出现在投给评委的页面上
  是事故级的尴尬

✅ 正确做法：

```markdown
# [阐述] 教学设计阐述
- **教学目标**：（1）理解祖暅原理……
- **理论依据**：（待填写 —— 需教师本人撰写本课的教学理念，此处不代笔）
```

占位符要**读得懂、看得见、改得掉**：写清"待填写"三个字，简短说明要补什么，
放在投屏上一眼就知道这页还没完。用户补完再渲染一次即可。

## 版式几何

页面 16:9，13.3333 × 7.5 英寸（12192000 × 6858000 EMU，精确 16:9）。
左右边距 0.76in，版心 11.813in。
底版不是 16:9 时渲染器直接报错退出 —— 所有几何量都是按这个尺寸定的。

| 元素 | 位置 |
|---|---|
| 页面标题 | y 0.39in，高 0.79in（粗体，与底边 1.18in 对齐） |
| 正文区 | y 1.42in 至 6.85in |
| 强调块 / 驱动问题 / 解答块 | 自 6.85in **向上**堆叠（视觉顺序：强调块 → 驱动问题 → 解答块），高度按行数算 |
| `[例题]` 题干 | y 1.42in 起，占满版心宽，**不参与填充** |
| `[例题]` 配图 | 题干下方、版心**右侧 40%** 区内居中 |
| `[例题]` 解答块 | 题干下方、版心**左侧 60%** 留白区内，贴顶 |

强调块、驱动问题与解答块的高度都是**算出来的**（按各自字号和折行数），正文区的底边
因此严格等于堆叠区的顶边，三者不会重叠。同时出现时正文区会明显变矮，渲染器在低于
1.6in 时告警建议拆页。

`[例题]` 版式是唯一不走这条堆叠规则的：它的解答块归题干下方的留白区管
（见「例题页」一节）。判据是**版式**而不是"有没有写 `!ans:`"—— 留白区正是这个版式
存在的理由，所以这一页的下半区永远由它接管。

### 字号表

| 元素 | 字号 |
|---|---|
| 封面主标题 | 70pt（10 字以上 54pt，14 字以上 44pt） |
| 页面标题 | 32pt 粗体 |
| 一级要点 | 28pt，内容稀疏时自动升到 30pt |
| 二级要点 | 一级的 0.857 倍（28pt → 24pt） |
| 强调块 | 32pt |
| 驱动问题 | 24pt |
| 解答块 | 24pt（= 二级要点；钉死，不参与字号自适应） |
| 阐述页细则 | 16pt（固定） |
| 流程页说明 | 20pt |

**字号不许往小调。** 渲染器只会把正文放大到 30pt，永远不会低于 28pt —— 装不下时的
正确反应是拆页（规则 2），不是调小字号（规则 7）。

字体：**标题「微软雅黑」，正文「华文中宋」**。两者都与配套样本 PPT 一致 ——
样本里标题继承主题的 `+mj-ea`，正文则在 run 上把 `a:latin` 与 `a:ea` 都硬编码成
华文中宋，西文与数学变量因此也跟着走衬线体。渲染器显式写死字族而不是靠继承：
换底版时主题中文字体会跟着变，而字体是契约。要换字体用 `--font-title` /
`--font-body`。

> 配图**内**的文字刻意用无衬线（微软雅黑）：图内标签字号小，衬线笔画在投影距离下
> 糊成一团。这是有意的不一致，见 `math-figures.md`。

### 自适应填充

页面留白不是靠"把字居中"消化的，而是两级调节：

| 手段 | 幅度 | 什么时候起作用 |
|---|---|---|
| 字号 28 → 30pt | +7% | 内容稀疏时的第一反应 |
| 段后距 10 → 26pt | ×2.6 | 主力。只加**段间**空隙，读起来是"分组更清楚" |
| 行距 1.30 → 1.60 | ×1.23 | 要点很少（1–3 段）时段后距几乎无效，只能靠它 |
| 垂直居中 | — | 三档到顶后的残余空白交给它 |

目标是文字块占正文区 82%。三档都到顶还差得远就停手 —— **宁可留白，也不把版面撑变形**。
此时若占用率仍低于 35% 会告警建议补充内容（带驱动问题或强调块的页除外：那类页面的
留白是"给学生想的地方"）。

数学符号用 Unicode（`Δ` `→` `≈` `∞`），不用 OMML 公式对象，
保证在各版本 PowerPoint 里渲染一致。

## 渲染器行为

`build_pptx.py` 渲染时会做的事：

1. 解析 frontmatter 与页面
2. 按版式几何表摆放元素
3. 插入图片；缺图则插占位框并告警
4. 执行校验并打印告警清单（不中断渲染）
5. 给每个解答块注入单击显现的 `<p:timing>`（`CLICK_REVEAL=False` 时跳过并告警）

校验项与对应规则：

| 校验 | 规则 |
|---|---|
| 文字块装不下（附生效的字号/段距/行距） | 2 |
| 一级要点 ≤ 6 行 | 7 |
| 标题 ≤ 12 字 | 3 |
| 建构段每页有图（除豁免） | 5 |
| 每页强调块 ≤ 1 个 | — |
| 一页只渲染第一张图 | — |
| 不渲染插图的版式上写了 `!img:`（图会整张丢失） | 5 |
| 字体缺字形（会画成方框，PowerPoint 不报错） | — |
| 流程页步数 ≤ 4、图区不过矮、统一尺度后图形不过小 | — |
| 流程页说明行越过底部堆叠区（文字压文字） | 6 |
| 底部堆叠区挤占后正文区 ≥ 1.6in | — |
| 正文占正文区 ≥ 35%（带问题/强调块的页除外） | 7 |
| 要点块的间距已显式写入 | — |
| `version: contest` 时含阐述页 | — |
| `frontmatter` 里没有已废弃的字段 | — |
| **要点行有口语痕迹（词典命中，高置信）** | **9** |
| **要点行疑似散文断句（启发式，低置信）** | **9** |
| **`[例题]` 页没有题干** | — |
| **`!ans:` 写在 `[封面]` / `[阐述]` 上（解答会整段丢失）** | — |
| **`!ans:` 后面是空的（不会有任何内容出现）** | — |
| **`[例题]` 的解答自然高度超过留白区（会被压缩行距）** | — |

最后四条里有两条值得说明，因为它们挡的都是**不报错的丢失**：写在 `[封面]`/`[阐述]`
上的解答会整段消失，而答案本来就是"点一下才出现"，少一块不像出错；空的 `!ans:`
同样无声。这两条都不是格式洁癖，是"渲染成功但内容少了"这种最难发现的失败模式。

**另有两项脚本查不了、只能靠人和演示软件**：

1. **动画是否真的挂上了。** 注入的 `<p:timing>` 是手写的底层 XML，写坏了演示软件
   可能**安静地忽略**它 —— 产出正常打开，只是解答不再点击显现、直接摊在屏幕上。
   XML 本身是良构的，所以结构校验无能为力。必须调 `scripts/verify_anim.ps1` 让
   演示软件自己读回来（见 SKILL.md「先问题后答案」）。脚本会打印是**哪个**软件
   读的 —— 装了 WPS 的机器上「PowerPoint」可能其实是 WPS（详见 SKILL.md）。
2. **点击前那块内容到底藏住没有。** 注意 `Slide.Export` 导出的图是**点击后**的样子
   —— 实测（作者样本里被动画藏起来的那张表格，导出图里是显示的；PowerPoint 与 WPS
   都是这样），所以导出图不能用来判断"藏没藏住"，只能用来查排版。要验藏没藏住，
   得真放映一遍点一下看。

   这条不是没试过别的办法：全屏放映后抓屏也失败过两次，一次是被别的窗口盖住，
   一次是抓到了编辑器窗口 —— 这台 150% 缩放的屏上 `SlideShowWindow.HWND` 拿不到、
   `CopyFromScreen` 的坐标被虚拟化，抓出来的前后两张图一模一样，看着像"点了没反应"，
   其实是根本没抓到放映。**所以别信抓屏得到的"藏住了"**，那多半是没抓到。

最后一条「间距已显式写入」值得说明：渲染器写的是**绝对**行高（`spcPts`），不是
"字体自然行高的 130%"（`spcPct`）。因为自适应填充是按绝对高度做决定的，一旦混用
百分比行距，估算就与真实渲染脱钩，而且换个底版换个字体后结果还会再变。这条校验
专门抓这种静默脱钩。

告警是**提示**不是错误：渲染照常完成，由用户判断是否接受。有些页面确实需要破例，
把判断权留给人比强行拦截更有用。

**渲染完请自己打开通看一遍 —— 而且要用讲课时真正用的那个软件。** 脚本能保证结构、
几何、字体、长宽比都对，但看不出「70pt 的封面标题在真实字体度量下是否折行」这类
只有眼睛能判断的事。两个软件都要是**用户手里的那个**：WPS 与 PowerPoint 的排版与
动画读回实测一致，但一致是结论不是前提，别替用户假设他用哪个。
