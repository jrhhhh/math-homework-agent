# 教案草稿 → 课堂课件

把中学教案设计草稿转换成可放映的 `.pptx` 课件。

## 这个技能要解决的问题

教案和课件不是同一份东西。教案写的是「教师怎么想」（教学目标、设计意图、理论依据），
课件要的是「学生看到什么」。把教案的章节标题直接搬成幻灯片标题，做出来的是教案的
复读机 —— 页数不少，但每页都在重复同一件事，学生看不出这页要他干什么。

本技能做的是**重新切页**：按学生的**认知台阶**切分，让每页对应一个思维动作
（感受、比较、抽象、应用），而不是对应教案里的一个标题。

自检标准：学生扫一眼某页，能不能说出「这页要我干什么」。说不出就是切错了。

## 什么时候不用这个技能

- 用户只要教案本身，不要课件 → 直接写，不走本技能
- 用户要试卷、习题集、单元复习提纲 → 那是练习材料，不是课堂课件
- 用户要学案、讲义 → 本技能目前不产出（后续可能增补）

## 流程

### 第 1 步：读教案，列出「已有 / 缺失」

读用户给的 `.docx` / `.pdf`，逐项核对：

| 要素 | 用途 |
|---|---|
| 课题、年级、教材版本 | 术语与符号要和课本一致，否则学生要在两套说法之间翻译 |
| 课时长度 | 决定页数与内容切分 |
| 教学目标 | 只在「阐述页」出现，不进教学页 |
| 教学重难点 | 决定哪些页需要强调版式 |
| **教学过程**（师生活动、设计意图） | **课件的主要原料** |
| 板书设计 | 小结页可直接复用 |
| 作业 | 作业页 |

缺什么就问用户。不要替用户编学情 —— 学情判断错了，整份课件的深度都会偏。

读文件的方式：

```bash
# .docx —— 直接读 XML，无需额外依赖
python -c "import zipfile,re,html,sys; sys.stdout.reconfigure(encoding='utf-8',errors='replace'); x=zipfile.ZipFile(sys.argv[1]).read('word/document.xml').decode('utf-8'); x=x.replace('</w:p>','\n'); print(html.unescape(re.sub(r'<[^>]+>','',x)))" 教案.docx

# .pdf
python -c "from pypdf import PdfReader; import sys; sys.stdout.reconfigure(encoding='utf-8',errors='replace'); print('\n'.join(p.extract_text() or '' for p in PdfReader(sys.argv[1]).pages))" 教案.pdf
```

开头那句 `sys.stdout.reconfigure(...)` 不是装饰。Windows 上 Python 输出流默认走 GBK，
教案正文全是中文，于是这条命令的**输出编码取决于运行环境的 `PYTHONIOENCODING`**。
实测（同一份 docx，把 stdout 设成 GBK）：不写这句时输出 5166 字节且按 UTF-8 解码
在第 7 字节就失败 —— 也就是说拿到手的是一堆乱码，而进程**退出码为 0、stderr 为空**。
教案读成乱码，后面每一步都建立在乱码上，没有任何迹象提示"这里出过错"。
编码写死在命令里，这条命令的输出就与谁在什么终端里跑它无关了。

### 第 2 步：确认参数

缺哪个问哪个，不要猜。这些参数会实质改变产出：

| 参数 | 影响 |
|---|---|
| 年级（初一~高三） | 例子选型与抽象程度 |
| 课时长度 | 页数与内容切分粒度 |
| 教材版本 | 术语、符号、习题编号的引用方式 |
| **比赛版 / 日常版** | 是否在末尾追加「阐述页」 |

### 第 3 步：按认知台阶切分，输出大纲，**请用户确认**

这是整套流程最该让人把关的地方。先写大纲让用户点头，再动手生成 ——
一口气吐 20 页再返工，比先花两分钟确认大纲贵得多。

大纲要写清每页四件事，而且**要点行要写成最终要上屏的那句原话**，不是转述：

```
P1  封面      导数的概念及其意义
P2  温故知新  用二次函数拟合跳水轨迹                            [图]
              > 研究整体轨迹就足够了吗？我们如何研究一段时间内的变化？
P3  两种速度  平均速度：Δy/Δx
              瞬时速度：Δy/Δx 在 Δx→0 时的极限              [无图]
P4  定性看    割线斜率 → 无限逼近 → 切线斜率                    [图+GIF]
...
```

**为什么大纲里就得是原话**：语体是在「落成句子的那一刻」定下来的。大纲若只写
「温故知新：叠书引入」，原话要到第 5 步写 `课件.md` 时才成形 —— 口水话就是那时候
钻进去的，而那时你已经点过头了。提前到大纲，语体问题就在你点头**之前**露出来。

这不是纸上谈兵：`references/deck-rules.md` 规则 9 的改写对照表，全部取自本技能的
实际产出 —— 那些句子零告警地通过了构建，因为旧版只查行数、字号、加粗，没有一条
规则看语体。第 6 步会按同一套判据再扫一遍（`check_wording`），但那时改的成本是
重写 md 再渲染一次。

**切分依据是认知台阶，不是教案标题。** 参考 `references/deck-rules.md` 里的规则 2。

### 第 4 步：出图

先写一份 `figures.json` 声明要出哪些图（含 `output_dir`），再跑：

```bash
python scripts/make_figures.py figures.json          # 输出到清单里的 output_dir
python scripts/make_figures.py figures.json -o tmp/  # 或临时指定目录
```

已实现的 recipe（函数图像、割线切线、3D 柱锥、叠书、棱柱分割、GIF 逼近动画）
与参数表见 `references/math-figures.md`。**那条 recipe 表盖不到的范围也写在同一节，
出图前先读** —— 公式推导条、教材原图、真实照片都不在里面，那类图的正解是自己截图
放进 `figures/` 再 `!img:` 引用（手工插的图和脚本出的图待遇完全相同）。

三件出图后必须做的事：

1. **用眼睛看图** —— 中文字体缺失时图能正常生成、但字全是方框，不报错，只能靠看。
   `--check-fonts` 可先验证字体。
2. **量一下实际长宽比**（`python -c "from PIL import Image; im=Image.open('figures/x.png'); print(im.size[0]/im.size[1])"`）。
   渲染器按长宽比决定这页是「左文右图并排」还是「上图下文」，而裁白之后画布形状
   完全由内容决定、`figsize` 说了不算 —— 照着 `figsize` 猜会猜错。
3. **流程页的一组图，比一比图形本身的高度**（不是比文件画布）—— 这一步就是要用眼睛
   看。流程页各图按着墨区等比排，图形形状差得多时渲染器会告警，那时该重出图或拆页，
   不是补白：补白只让文件看着一致，藏住差异。

概念建构段（排除封面、重点页、阐述页）的每一页都该有图 —— 中学数学的抽象概念
如果没有图形支撑，课件就退化成提词器。确实不需要图的页，在源码里写
`<!-- 允许无图 -->` 标豁免，渲染器就不会告警。

### 第 5 步：渲染课件

先写 `课件.md`（语法见 `references/slides-spec.md`），再：

```bash
python scripts/build_pptx.py 课件.md -o 课件.pptx
```

用自备底版时加 `--template assets/base.pptx`（见「底版」一节）。

比赛版在末尾追加两页「教学设计阐述」「教学重难点及解决」；日常版不追加。

这两页**第一行就是要素本身**（教学目标 / 重难点），不重复课题与教材 —— 它们是内页。
教学理念那类写不出来的条目留 `（待填写 …）` 占位符，别拿套话糊过去，
更别把本技能的说明文字抄上去。细则见 `references/slides-spec.md` 的「阐述页」一节。

### 第 6 步：自检

`build_pptx.py` 会在渲染时自动告警（结构问题它自己会报）。逐条确认：

- 单页要点 ≤ 6 行
- 标题 ≤ 12 字，且同份课件内句式对仗
- 建构段每页有图（或用 `<!-- 允许无图 -->` 豁免）
- 加粗只出现在核心术语与结论句上
- 课题与教材出处只出现在封面 —— **阐述页也算内页**，第一行直接写「教学目标」
  「重难点」，不铺垫课题
- 排版告警（正文区被压到 1.6in 以下、正文占用率低于 35%、流程页步数过多）——
  这些的正确反应是**拆页或补内容**，不是调小字号
- **字形告警**（`「微软雅黑」没有 '⇒' 的字形`）—— 字体里没这个字形时 PowerPoint
  不报错，直接画成方框，只有逐字看才发现，所以脚本自己去查字体表。见到就把该字符
  换成同类可显示的（`⇒`→`→`、`₁`→`1`）
- **插图告警**（`[重点] 版式不渲染插图`）—— 写在这个版式上的 `!img:` 会被整张丢弃，
  要么换 `[标题]` / `[两栏]` / `[纯图]`，要么把图去掉
- **语体告警**（`要点行有口语痕迹 '一下'` / `N 个逗号串了多个小句`）——
  前者是词典命中，高置信，按规则 9 的对照表改写；后者是启发式，低置信，
  确实该是一整句就忽略。两种都只提示不拦截。
- **解答告警**（`[阐述] 版式不渲染底部块，N 行解答会被整段丢弃`）——
  `!ans:` 写在 `[封面]` / `[阐述]` 上时整段消失，且因为解答本来就是「点一下才
  出现」，少一块不像出错。换 `[例题]` / `[标题]` / `[重点]`，或删掉解答。

上一段的告警是**渲染器自己**报的。几何与字体的那一半由另一个脚本独立复核：

```bash
python scripts/verify_pptx.py 课件.pptx --figures figures/
```

它**刻意不 import `build_pptx`** —— 复核必须独立于被检代码，否则是自证。只读
`.pptx` 成品，几何量自己从 EMU 算、判据自己定。退出码 1 = 有 ERROR。

查得到（客观、与字体度量无关）：画布尺寸、形状越界、图片拉伸、图文重叠、
一排流程图的间距均匀性、字体契约、行距单位、内页页脚、要点条数、同页重复长文本。

**查不到，别把「没查」当成「没问题」**：70pt 封面标题在真实字体下会不会折行
（需真实字体度量，脚本没有，也不冒充）；「点击前那块内容到底藏住没有」（导出图
是点击**后**的样子，抓屏在本机也失败过两次）。这两件只能人眼看 —— 渲染完请自己用
**上课真正要用的那个**演示软件打开通看一遍。

### 第 6 步之外：改了这个技能之后，跑回归测试

上面第 6 步查的是**刚生成的这一份课件**。它回答不了另一个问题：**你刚改的那几行，
是让技能变好了还是变坏了？** 那个要拿固定输入跑一遍比出来：

```bash
python scripts/bench.py regress                    # 秒级，零模型成本，36 条断言
BENCH_IDENTIFIERS=真名,学号 python scripts/bench.py regress   # 再多跑一条隐私扫描
```

**为什么要有它**：这个技能里每个校验器都是「被动」的 —— 它们只在有人调用时才说话。
一条检查哪天被某次重构悄悄关掉了，从外面完全看不出来：产出照样生成，告警照样是空的，
而**空告警和「检查还在、只是没问题」长得一模一样**。所以每组检查都配了一个
**规定必须触发它**的夹具（`evals/fixtures/`），哪天检查哑了，红的是它自己的对照。

- 四态：`PASS` / `FAIL` / `NOT-RUN` / `ERROR`。**只要出现 FAIL、ERROR、NOT-RUN 任一，退出码就是 1。**
  「没跑」被算成不通过，是故意的 —— 一个不打招呼就绿的测试台比没有还危险。
- `reg.privacy` 扫的是**技能目录本身**，防的是「真名/学号漏进分享包」。标识符从
  环境变量来，绝不写进技能包里的任何文件。没给清单时它记 NOT-RUN 并让整轮变红，
  而不是安静地跳过。
- 已知漏检写成 **xfail**（当前预期不报）。哪天补上了，它会转成 `XPASS` 并提示可以摘掉。
- 夹具里有**故意做坏的对照组**（`evals/fixtures/mutate_pptx.py`，14 个变异）。
  别把它们当垃圾删掉 —— 那是这套东西唯一的自证手段。

**改了 `build_pptx.py` / `verify_pptx.py` 的任何判据，跑一遍 `regress` 再交。**
它只覆盖回归层；产出层（端到端生成一份课件）见 `evals/README.md`。

## 版式与规则

`references/deck-rules.md` 是从用户自己的配套样本（同一节课的教案 + 参赛 PPT）
逐一比对得出的 9 条转换规则，含版式选用表。**写大纲前先读它** —— 它决定了
页怎么切、字号怎么定、图放在哪。

`references/slides-spec.md` 是 `课件.md` 的完整语法，也是 `build_pptx.py` 的契约。

## 动态演示的能力边界

中学数学课件常需要「动态演示」（如割线逼近切线）。必须先说清能做到什么：

| 做法 | 状态 | 说明 |
|---|---|---|
| 静态图 | ✅ | matplotlib，函数图像 / 几何截面 / 3D 柱锥 |
| **流程页** | ✅ | 同一过程的 N 个瞬间排在一页上，箭头串起顺序。最稳，无播放器兼容风险 |
| **GIF 动画** | ✅ | 插入 pptx 后放映时自动播放，能表达连续变化过程 |
| **单击显现**（解答点击才出现） | ✅ | 每页一个 Appear 效果，见下节 |
| 其它原生 PPT 动画（飞入、擦除、自动播放等） | ⛔ | 只实现了上面这一种，其余不写 |
| GeoGebra 交互演示 | ⛔ | 无法生成可双击运行的 `.ggb` |
| 视频（MP4） | ⛔ | manim 未安装且依赖 LaTeX，不引入 |

**优先用流程页**：它对播放环境没有任何要求，用户事后也最好改。流程页还有个副产品 ——
N 个瞬间同时在场，学生能把「上一步」和「这一步」对照着看，这正是分步讲解的价值所在。
只有在过程必须**连续**（如「无限逼近」的渐近感）时才用 GIF；两者也能叠加，
流程页里放一张 GIF 是合法的。

不要把同一过程拆成多张幻灯片（旧版的「分步页」）：翻页会丢掉上一步，而支撑推理的
恰恰是那个上一步。`[分步]` 仍能渲染，但会被改名成 `[流程]` 并提示。

### 先问题后答案：`!ans:`

教案里写着「引导学生思考讨论」的地方，**不要一上屏就把答案摊开** —— 那样讨论就没了。
把答案写成 `!ans:`，它平时不显示，讲台上**点一下才整块出现**：

```markdown
# [例题] 例题巩固
- 已知圆锥的底面半径为 r，高为 h，求它的体积 V
!ans: 圆柱体积 V = πr²h
!ans: 等底等高的锥体体积为圆柱的 1/3
!ans: 故 V = 1/3 πr²h
!img: figures/cone.png
```

多行 `!ans:` 合成**一个**块，一次点击整体显现（不做逐行）—— 逐行要写
`p:bldLst` 文本构建 XML，风险面大得多，而分步推演本来更适合在黑板或留白区走。
`!ans:` 在任何版式上都可用；`[例题]` 版式会把它放进题干下方的左下留白里。

作者本人的参赛 PPT 也是这个思路（问题分次出现，答案另起一页或上黑板）——
本技能把「答案上黑板」换成了「答案点一下出现在留白区」。

**交付前必须过一遍 COM 读回。** 这段动画是手写的底层 XML，写错了演示软件有两条
反应，**两条都不会让构建报错**：弹「需要修复」，或者安静地忽略掉 —— 后者最危险，
产出看着完全正常，只是解答不再藏着、直接摊在屏幕上，讲课的人要到讲台上才发现。
`build_pptx.py` 的结构校验对这两种都无能为力（XML 本身是良构的）：

```bash
python scripts/build_pptx.py 课件.md -o 课件.pptx   # 记下「单击显现 N 页」
powershell -NoProfile -File scripts/verify_anim.ps1 -Pptx 课件.pptx -Expect N
```

脚本退出码非零就说明动画没挂上，**那时不要交付**：把 `build_pptx.py` 的
`CLICK_REVEAL` 改成 `False` 重新渲染 —— 解答会改为直接显示，版面分毫不差，
只是少了一次点击（这是设计好的安全退化，不是补救）。同时把上面那段讲清限制。

**看清脚本报的是哪个软件。** 装了 WPS 的机器上，「PowerPoint」很可能不是
PowerPoint：WPS 会把 `PowerPoint.Application` 这个 ProgID 改写成自己的
`wpp.exe /Automation`，而它对外还自称 `Microsoft PowerPoint 14.0` —— 按名字
判断会被骗过去。所以脚本按**可执行文件路径**报关，逐个打印

```
   真身路线：Microsoft PowerPoint
== Microsoft PowerPoint  （自称 Microsoft PowerPoint 16.0）
   path: C:\Program Files\Microsoft Office\root\Office16
```

如果路径里是 WPS，结论就只代表 WPS，脚本会明说，**不要把它读成「PowerPoint
里验过了」**。本机（PowerPoint 16 + WPS 共存）实测两个引擎读回来完全一致，
但一致性是结论、不是前提 —— 要用哪个软件放映，就在哪个软件里过一遍。

## 底版

默认使用脚本内置版式（16:9，标题「微软雅黑」/ 正文「华文中宋」—— 与配套样本 PPT
一致）。如果用户有自己惯用的 PPT 风格，可以用它剥出空白底版，让生成的课件继承
同一套视觉语言：

```bash
python scripts/make_base.py 你的PPT.pptx -o assets/base.pptx
```

该脚本删除全部幻灯片，保留母版、版式、主题与字体。

两点注意：

- **字族是脚本显式写死的，不靠主题继承** —— 换底版时主题中文字体会跟着变，而字体是
  契约。要换字体用 `--font-title` / `--font-body`，别指望底版。
- **底版必须是 16:9**，否则脚本直接报错退出。所有几何量（边距 0.76in、标题带、
  正文区 1.42–6.85in、填充算法的估值）都是按 13.3333 × 7.5 英寸算的，
  换个比例整套版面就散了。python-pptx 内置的默认底版是 10 × 7.5，
  所以 `--template` 拿到非 16:9 的文件时报错是**保护**不是 bug。

## 已知限制

- 「教学设计阐述」「教学重难点及解决」两页里的**教学理念原创表述**（如
  「逆向设计 + APOS 理论」这类论述）只能按模板填要素，实质内容需用户自己写。
  这部分代笔在比赛中反而减分。教学目标 / 重难点 / 解决路径能从教案提炼，照写即可；
  写不出来的条目留一个显眼的 `（待填写 …）` 占位符 —— **不要把本技能的说明文字抄进
  幻灯片**（那是写给写课件的人看的，投给评委就是事故），也不要拿通用套话充数
  （读起来像成品，用户可能就这么交上去了）。细则见 `references/slides-spec.md`。
- 数学公式以**纯文本 + Unicode 符号**呈现（如 `Δy/Δx`、`lim`），不使用
  OMML 公式对象。可编辑性优先，也避免公式渲染在不同 PowerPoint 版本间走样。
- 渲染产物的版式可继续在 PowerPoint 里手工微调 —— 脚本只负责把结构立对。
