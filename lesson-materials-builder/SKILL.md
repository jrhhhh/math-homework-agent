# 数学课堂课件

交付目标是教师能够按课件组织一节课：学生知道当前要解决什么、为什么进入下一步，教师有可用的问题、追问、提示、解答和时间安排。以完整教学环节为内容单位，再按投影可读性切页。单页简洁不等于整课删掉必要推理。

## 输入与范围

先检查教师已有材料及会话中已确认的信息：课题、年级、课时、教材版本、课型、已有基础、目标和例题。不要重复询问已知参数。

- 课型不明时，根据材料选择新授课、习题课或讲评课，明确所采用的选择；缺少学情时写设计假设，不虚构学生诊断结果。
- 只有简略草稿时，可主动设计教学顺序、问题、板书与原创配套练习，并标明材料来源和数学核验状态。不得编造教材页码、官方例题编号或课堂实测。
- 需要教师决定的目标、范围或缺失原题，先指出；不影响工作的细节用明确假设继续。用户要求试讲样例或修改 Skill 时，可用合成课例验证，不把其当作实际班级证据。
- 学生正式作业诊断、草稿评估和纯习题求解按项目路由处理；本 Skill 的数学检查不替代那些技能。

读取文件时保留中文编码。Word 可用：

```bash
python -c "import zipfile,re,html,sys; sys.stdout.reconfigure(encoding='utf-8',errors='replace'); x=zipfile.ZipFile(sys.argv[1]).read('word/document.xml').decode('utf-8'); x=x.replace('</w:p>','\n'); print(html.unescape(re.sub(r'<[^>]+>','',x)))" 教案.docx
```

PDF 可使用 `pypdf` 提取可复制正文；扫描件不得假装已准确读取数学公式。

## 先确定视觉模板

先读取 `references/visual-design.md`，查看 `assets/themes/` 中真实渲染的主题预览。默认使用“绛红书院”，可选“墨青研习”；同时提供原生 PPTX 版式、JSON 视觉规范和模板样册。大纲写出所选主题及每页构图，源码 frontmatter 写 `theme`。不能只换颜色或把空白列表页称为已套模板。

## 第 1 步：选模板，写教学蓝图

开始前读取 `references/classroom-design.md` 和 `references/classroom-templates.md`。

选择课型后，先写出：

1. 本课结束时学生应独立完成的具体任务，以及判断完成的证据。
2. 旧知识如何支持新任务；本课关键障碍是什么。
3. 驱动问题及后续问题链，每个问题如何把学生带到下一步。
4. 例题和练习分别承担什么功能，避免只换数字的重复。
5. 各环节时间与机动安排；累计时间与课时一致。留出真实作答、交流和检查时间。

模板的课时和页数是规划参考，不是硬凑数量。短课收缩任务，整课补齐学习环节；不能把 8 页概要直接宣称为 45 分钟成品。

## 第 2 步：逐页大纲与教师确认

每页大纲使用以下字段，写出真正要用的内容：

| 字段 | 应写内容 |
|---|---|
| 环节、页码、时间 | 本页属于哪个任务，预计用时；同一任务多页合计计时 |
| 学生先看到什么 | 完整题目、条件、图或关键表达，不能只写“思考/讨论” |
| 主问 | 一次能作答的具体问题，明确需要写式子、画图、说明还是判断 |
| 预期回答 | 关键推理或可观察结果；不是虚构实际学生回答 |
| 追问与支架 | 可能卡在哪里；先追问什么，再给哪个最小提示 |
| 收束与转场 | 什么结论成立、依据是什么、为什么进入下一环节 |
| 模板与呈现 | 页型、配图、板书、答案在何时出现 |

预期错误标成“可能出现”，不得写成已发生事实。让教师确认大纲；用户已确认的目标和课型继续沿用。若只要求修改 Skill，完成 Skill 和验证材料即可，不为验证课例额外索要确认。

## 第 3 步：填充完整课堂内容

按确认的大纲填充题目、概念、推理、图形、练习和答案。每个核心知识点至少提供一次从学生已有知识走到结论的过程，不能只给定义或结论。

- **问题链**：先提出可进入的问题，再给学生处理信息的任务，随后追问依据、条件或反例，最后形成结论并应用。根据课题选择步骤，不机械套用口号。
- **例题**：题目与条件 → 审题和策略选择 → 关键步骤及依据 → 检验与方法归纳。关键推导跨页时保留题目/当前式和前一步结果，允许分阶段翻页。
- **练习**：基础检查 → 同目标变式 → 适度迁移；整课安排独立作答和退出检测。每题准备答案、关键依据、常见风险与判断标准，不能用“教师另行布置”代替已承诺的练习。
- **错例**：给出具体错误步骤，先判断其成立条件，再用反例或分支说明风险，最后形成可执行的修正；不只标“注意漏解”。
- **概念或定理**：含义、条件、表示、例与非例、使用边界按课题需要展开；不把不适用的模块硬塞进课内。

允许创设与已确认目标一致的题目，但须完整求解并检查；工具不可用或未核验的内容明确留待教师核对。优先使用已提供、可追溯材料；不要把助手创编题包装成教材原题。

## 第 4 步：使用页面模板与教师备注

`assets/templates/` 提供可直接改写的 Markdown 模板；`references/classroom-templates.md` 说明选择方法。原有 `assets/base.pptx` 只是母版底版，不能替代教学内容模板。

完整填充示例见 `assets/examples/trigonometric/lesson.md` 与同目录 `lesson.pptx`：21 页合成三角方程习题课，包含 43 分钟活动、2 分钟机动、问题推进和教师备注。只用作设计与渲染参考，不是实际课堂验证；替换课题时重新设计并核验，不照搬题目或学情。

每个核心教学页用 `!note:` 填入教师备注：时间、预期回答、追问、卡住时的提示、板书和转场；这些内容写入 PPT 演讲者备注，不堆到学生屏幕上。练习答案与评分依据也在备注中保留。不要交付未替换的方括号占位符。

先问后答可以选两种方式：

- 问题页 → 讨论后的讲解页：可靠且便于分步引导；讲解页保留必要题目和条件。
- `!ans:` 一次点击整块显现：只适合简短解答，不能将整题十行解答挤进底部。它不支持逐行显现。

完整推导、教师支架和学生屏幕分别组织；不能通过“每页少写几行”把教学内容删除。

## 第 5 步：配图与渲染

读取 `references/math-lesson-quality.md`、`references/deck-rules.md`、`references/slides-spec.md`。教学设计以本 Skill 及 `classroom-design.md` 为准；样本风格规则不能取消问题链、完整推导或有效反馈。

标题、两栏、例题、重点、纯图、流程承担不同内容功能。图形应帮助比较、理解关系、验证或探究，不要求每页凑图。图内标注需要投影可读，图文拥挤时拆页。

配图参数见 `references/math-figures.md`，支持函数、单位圆、割线切线、柱锥与棱柱等。无对应 recipe 时用可编辑文字推导或教师提供且可使用的图片，不编造支持的图形功能。

在技能目录运行：

```bash
python scripts/make_figures.py figures.json -o figures/
python scripts/build_pptx.py 课件.md -o 课件.pptx --template assets/base.pptx
python scripts/verify_pptx.py 课件.pptx --figures figures/
```

用户底版为 16:9；`scripts/make_base.py` 可剥出母版。字体由渲染器显式设置，可用 `--font-title` / `--font-body` 调整。公式为可编辑文本，不是 OMML；配图是图片。不得把继承空母版说成已套用了完整课堂模板。

## 第 6 步：按课堂流程验收

先演练教学，再逐页渲染。检查：

- 学生能否只根据屏幕和问题进入任务；每个关键追问是否有具体数学对象。
- 难点是否被分解并有支架；结论是否来自前面的推理；下一题是否检验该目标。
- 学生作答后，教师是否有明确的答案、判断依据、纠错与继续路径。
- 每道例题与练习的条件、分支、端点、推理和答案是否检查；核验状态有无如实记录。
- 课时是否容得下思考、书写与反馈；是否存在占位符、空泛活动、重复页或无依据的教材引用。
- 所有页面渲染后文字、图形、条件是否完整；字号、留白、图文比重是否适合教室投影；备注是否写入。

缺少核心教学环节时回到内容设计，不能仅凭结构检查通过就宣称“可直接上课”。交付 PPTX、Markdown 源、配图清单及核验说明；教师备注在 PPT 内，源码也保留。

播放验证与结构检查分别记录：单击显现 XML 不等于实际播放通过。Windows 可运行 `scripts/verify_anim.ps1` 并核对实际播放软件路径；不能验证时优先使用前后两页呈现答案，并说明未测动画。GIF、静态流程可用；GeoGebra、其它原生动画和视频不是本技能已实现能力。

## 修改技能后的检查

运行 `python scripts/bench.py regress`；包含隐私扫描时以 `BENCH_IDENTIFIERS` 提供真实待查标识符。缺少清单记 NOT-RUN；仅做功能检查可用 `--no-privacy` 并明确其范围。不要将跳过检查描述为全部通过。

脚本或语法变化后重跑实际课件，检查成品与备注。结构、数学、视觉、课堂效果分别报告。数学核验不证明教学效果，合成课例不等于实际授课。
