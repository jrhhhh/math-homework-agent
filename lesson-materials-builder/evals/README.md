# 这个技能的基准测试

三层。**只有第一层是默认该跑的。**

| 层 | 量什么 | 成本 | 状态 |
|---|---|---|---|
| ① 回归 | 改技能有没有把已有行为改坏 | 秒级，零模型 | 已可用 |
| ② 产出 | 端到端生成一份课件，质量如何 | 一次子代理（10–20 分钟） | 见下文 |
| ③ 触发 | 什么时候会/不会调用这个技能 | 每条 query 一次 `claude -p` | **未做** |

## ① 回归层 —— 日常就靠它

```bash
python scripts/bench.py regress
python scripts/bench.py list          # 看有哪些探针
```

34 条断言，跑几十秒。探针分五类：

- **语体**（`reg.wording`）—— 词典命中必须报；干净句子必须一条都不报
- **结构告警**（`reg.layout_alias` / `reg.answer` / `reg.flow_caption` / `reg.glyph` /
  `reg.emph_spacing`）
- **变异矩阵**（`reg.mutate`）—— 14 个变异，每个砸坏成品 `.pptx` 的一个属性，
  断言**特定的错误子串**必须出现。这是唯一能证明「复核脚本不是哑的」的手段
- **对照**（`reg.control`）—— 干净输入必须 0 告警。见下方「为什么也要防误报」
- **静态**（`reg.independence` / `reg.skill_md` / `reg.privacy` / `reg.ink`）

### 四态，以及为什么「没跑」要算不通过

`PASS` / `FAIL` / `NOT-RUN` / `ERROR`。退出码：**出现 FAIL、ERROR、NOT-RUN 任一 → 1。**

一条检查没跑成，和它跑通了，在摘要里都是「没有 FAIL」。若不区分，一次因为缺 Pillow
而跳过的复核，读起来就成了「这份课件没问题」。所以：

- 前置条件在探针执行**前**求值，不满足就记 `NOT-RUN`，并写清是哪个条件、怎么补
- `passed` 是**算出来的**（`status == "pass"`），写断言的人填不了这个字段
- 每个用例声明它**应当**出现哪些断言 id，跑完双向对账：声明了没报 → 补 `NOT-RUN`；
  报了没声明 → 记 `ERROR`。**这条专治「检查被悄悄关掉」**

想验证这套机制本身没坏：把 `evals/fixtures/` 里任一夹具改坏，`regress` 必须变红。
一道永远绿的测试等于没有测试。

### 夹具先红，再修：`reg.emph_spacing` 的来历

这条探针单独说，因为它是这套东西**第一次真的抓到缺陷**（产出层第一次真跑时浮上来的）。

`with_skill` 组的子代理报上来：折成两行的 `!!!` 强调块必报「行距未显式指定」，
而作者从 `课件.md` 里**改不掉** —— 只能把句子压成一行。那是绕过，不是修好。

查下去，根因比「多一条告警」深：`add_emph()` / `add_question()` 各自手搓形状、不走
`layout_block`，于是**谁也不给它们写 `spcPts`**；可它们的高度是按 `EMPH_LINE = 0.62` /
`QUESTION_LINE = 0.47` 算出来的，渲染行高却由字体的自然行高决定 ——
**模型假定 0.62in 一行，实际渲染是另一个数**。这正是 `check_spacing_written` 的
docstring 自己警告的那种「静默脱钩」，而两套行距校验当时又都只查 `body-block` /
`answer-block`，这类块便整片漏掉。

按这套东西自己的规矩办：**先写夹具（`fixtures/emph-wrap.md`），看着它红，再修。**

```
修前  reg.emph_spacing  FAIL —— 报了 1 条：行距未显式指定：Rectangle 3
修后  reg.emph_spacing  PASS —— 那份夹具 verify 报 ERROR 0 / WARN 0
```

夹具里特意留了一句一行的 `!!!`（短结论）作对照 —— 修完不能让**所有**强调块都多出告警。

**改渲染就必须回答「有没有把已有卡组改坏」**，而且只能量、不能推。拿三份真卡组重渲染：
好那份 0 ERROR 0 WARN、那次的 `with_skill` 产物 0 ERROR 0 WARN、盲跑那份仍只报它自己
那条 P12 页脚（**它的 P7 着墨错误消失了**，因为那份 `.pptx` 是更早一版渲染器产出的、
把图拉伸成了方块；同一份 `课件.md` 用现在的渲染器重渲染，图按长宽比缩放、白边被
`a:srcRect` 裁掉，着墨自然就齐了 —— 详见 `warning-categories.json` 里
`verify.flow.ink_mismatch` 的 note）。

### 隐私扫描

```bash
BENCH_IDENTIFIERS=真名,学号 python scripts/bench.py regress
# 或单独跑：
python scripts/lint_privacy.py --identifier 真名 --identifier 学号
```

扫技能目录，防的是真名/学号漏进要发出去的分享包。退出码 0 干净 / 1 命中 /
**2 = 没跑**（没给标识符清单）。

**标识符一律从外部传入，技能包里任何文件都不许写。** 理由见脚本 docstring：
为了防泄露而泄露，是最讽刺的一种。

`--no-privacy` 可以不跑这一项。它会在结论**之后**打一屏醒目的横幅，并把
`skipped` 写进 `grading.json` —— 因为「检查不在场」和「检查通过」在摘要里长得一样，
只在 stdout 留个提示，等于留给后来翻文件的人一个看起来一切正常的报告。

### 为什么也要防**误报**

一个见谁都报的检查等于没有检查 —— 会被忽略。所以每条「必须报」的断言都配了
「必须不报」的对照：`wording-clean.md`、`mutation-base.md`、`two-col-img-left.md`、
`reg.ink.real_clean`。加新判据时请照这个模式配对照。

### 拿一份**人写的**课件当尺子

想用告警数回答「这份课件好不好」，先得回答一个更早的问题：**这个类别量的到底是
质量，还是本技能的文风？**

判据是实测出来的：**拿一份人写的、拿得出手的课件去撞它。** 基准是
`示例/教学技能大赛ppt - 复赛.pptx`（人写的 13 页比赛稿；**文件名里的讲师姓名已抹掉
—— 这个包要发给别人，任何人名都不许留在里面**）。它触发的类别
（`spacing.missing` 17、`spacing.pct` 17、`outside_content` 9、`pic.offcenter` 5、
`overlap.pic_text` 6、`row.off_center` 3、`row.gap_uneven` 1、`footer.leak` 1、
`bullets.too_many` 2）**一律不能当质量判据** —— 人不会去写 `a:spcPts`，也不按版心
居中。拿这些计分，等于宣布人做的课件不合格。

结果记在 `warning-categories.json` 的 `human_control` 字段与 `exclude_from_scoring`
标记里；`bench.py` 的 `excluded_cats()` **读表**而不是在代码里写死一份，两边不会
各自漂走。

**但「人写稿没触发」不自动等于校准通过。** 它可能是：那份课件压根没有该类检查
适用的版面 —— 计数恒为 0，那是**空集不是校准**。`gap.large` 就栽在这上面：人写稿
有 5 个并排页测量值，但全部 `has_mate=False`（配不上文字块），检查在那份上**没生效**。
所以它的 `human_control` 记的是 `null`，不是 `0`。**报一条信号，必须连它的校准
到什么程度一起报。**

### 两次「狼来了」——量出来的判据也会骗人

接上 `verify_pptx.py --json`（按类别统计）之后，浮出两处**判据自己撒谎**：

**① 正文块上沿高于正文区顶 —— 差点被当成唯一的区分点。** 初测是「基线 10 页报
9 页，技能产出 0、人写稿 0」。看着像最硬的那种信号：纯几何、可重复、只有一方触发。
逐页拆开，那 9 个被点名的形状**全是标题**（30pt 的节标题，top=0.45），而正文块
规规矩矩从 1.90in 起排 —— 那份课件一个毛病都没有。判据用「字号 > 40pt」认标题，
30pt 溜了过去；技能自己躲过纯属侥幸（它的标题框 0.79in，卡在另一道高度守卫外）。
修法是跳过每页最高的文字块，**并配 `mutate_pptx.py → body-rides-up`** ——
「跳过最高的块」离「这条检查整个不跑了」只差一步。

**② 画布差 305 EMU 被判成 ERROR。** 0.0003 英寸、0.0025% 的差，投影上看不出来，
却让「基线 1 ERROR」被当成技能的优势。画布容差改成 0.02in：4:3 那种真变形差 3.33in
远超它，`canvas-43` 变异照样命中。

**教训是一样的：从「计数有差别」推到「一方更好」，中间必须拆开看几条。**
两次都是拆开之后结论反转。

### 盲评：判官跑通了，但**参照塌了**

`SKILL.md` 的核心主张（按**认知台阶**切页，而不是按教案标题）代码零实现，
也不该由代码判。所以建了盲评层：

```bash
BENCH_IDENTIFIERS=真名,学号 python scripts/bench.py blind-prep \
    --run <run 目录> --pair 名字=A.pptx:B.pptx --expect 名字=A
#   ← 脱敏副本 + 每页导 PNG + plan.json；调用方再起判官子代理
python scripts/bench.py blind-grade --run <run 目录>
```

脱敏是硬前置：任一副本复扫标识符 **必须 0 命中**，否则不导图、不起判官
（`blind.py` 直接返回 1）。实测四份副本全部 0 命中。

第一次真跑的判据是「好·祖暅 vs 坏·盲跑」——**12 个独立判官（6 维度 × 2 种位置
顺序）全票投给了标着「坏」的那一份，位置一致 6/6，零「无法判断」。**

判官给的是**可证伪的具体理由**，不是感觉。逐条机械核实：

| | 标着「好」的那份 | 标着「坏」的那份 |
|---|---|---|
| 页标题 | 温故知新／祖暅原理／理解原理／柱体体积／分割锥体／锥体体积公式 | 叠书之问／**越切越薄**／祖暅原理／**两个条件**／柱体公式／**三锥等分** |
| 性质 | 教案**小节名**，一节搬一页 | 前六个是**认知动作**名 |
| 末两页 | 占位符已填成真实内容 | 原样留着「（请自行填写 —— 建构主义、具身认知、HPM 的原创论述，此处的代笔在比赛中反而减分）」 |

第一行是**纯文本、可脚本化**的事实。判官没分错 —— **是这两个标签的来历有问题。**

**「好」的来历是循环的。** 翻遍工作区，没有任何一处对人做过质量裁定；能找到的
只有两条：`corpus.json` 的 slot-1 明写「**没有人写的版**，所以它只测『和上次比
退步没有』，**不测『够不够好』**」；而 README 里「已知良好」是贴给**告警数为 0**
的那一份的。也就是说 **「好」=「过得了我自己的检查」** —— 拿它去校准判官，等于
用被测物定义正确答案。这正是这个基准从第一天起想摆脱的那个循环，只是这次它
藏在参照里。

所以闸门记 **NOT-RUN**，而且**不是**因为判官分不开（它分得很干脆），是因为
**闸门的前提不成立**。按预登记「闸门不过就停手」，正式的 A/B（`with_skill` vs
基线）**没跑** —— 在一个没有标定过的判官身上花钱，买回来的数字读不出意思。

两条旁证，顺带说清各自的边界：

- **盲站得住。** 判官另答一题「哪份更像同一套工具批量做的」：4 票指认 A、4 票
  指认 B、4 票「两份都是」，完全分散 —— 认不出。所以上面的票不是靠认出了出处投的。
- **长度偏置拆不开。** 12 票的赢家每次都是字多的那份（925 vs 828）。但**只有 1 对
  课件**，字数与胜负在这对上完全共线，「判官偏爱字多」和「字多的那份确实更好」
  是一回事，分不开。要拆开得多给几对、且每对里两份字数互有高低。
- **D1 按预登记作废。** 对照题「哪份更好看」也选了同一份 → 按事先写好的规则
  D1 记 `NOT-RUN`。**但这条规则在 n=1 时有约 50% 的误杀率** —— 一对课件上两个
  问题碰巧同选的概率就是一半。所以这个作废是**弱证据**，不是发现；别把它读成
  「D1 其实在量好看」。

**测量代码自己也犯了同一类错，两次。** 长度偏置和「认出来了吗」两处，我都拿
`winner == "A"` 直接去对拷贝 `pair1-A` —— 可判官回的是**「先给的那份」**，
BA 顺序下同一个 `"A"` 指的是另一份课件。长度偏置因此先报出「12 条里 6 条，
没有偏置」这个**假结论**（真实是 12/12）。和上面两次「狼来了」同一类：
**从计数推到结论，中间必须把映射关系核一遍。**

**一个被误杀的候选判据。** 正文里「页标题 ↔ 教案环节名重合率」早先被否掉，因为
两份都是 22% / 20%，且换分词口径会反号 —— 但那是**把两份共有的尾页**（例题巩固、
课堂小结、作业布置）一起算进去的结果。真正分开两份的是**非尾页的标题是什么**：
认知动作 vs 大纲名。这条判据尚未实现，先记在这里，**别当成已有的能力**。

**三、基线组被作业文件抄了技能的核心主张**

`selfcheck` 按配置拆开，**漏了这一句**。证据不是推测：

- 基线自己写的 `大纲.md` 开头：「切页按**认知台阶**排，不按教案的小标题（一、二、三、四）
  直接搬」，并据此把教案的 4 个环节拆成 **6 级台阶**
- 时间戳：job 文件 18:39:49 → 子代理 18:39–18:44 → `bench.py` 的修复 **19:43**，在跑完之后

## ② 产出层 —— 里程碑才跑，不是每次都跑

端到端跑一份教案、生成一份课件，再对产物做断言。**每跑一条 = 一次完整的执行子代理
（10–20 分钟、15–40 万 token）**，所以默认只跑一份。

**`bench.py` 不调模型** —— 生成课件必须由 agent 完成，脚本起不了子代理。所以是三段式，
人在中间：

```bash
python scripts/bench.py plan  --corpus <外面>/corpus.json --run <run 目录>   # 出 job 文件
#   ← 由调用方起执行子代理跑 jobs/*.md，产物写进 out/<slot>__<config>/
python scripts/bench.py grade --corpus <外面>/corpus.json --run <run 目录>   # 对产物跑脚本断言
python scripts/bench.py report --run <run 目录>                              # 汇总
```

成本闸门：

- **默认只跑 `mini-1`**（一份、干净、docx）。`--only mini-2,mini-3` 按需展开，
  `--all` 才跑满 5 条。**大部分迭代根本不该跑产出层** —— 日常改动在回归层就够了。
- `--config without_skill` 是**基线**（完全不用技能）。跑一次就存档复用，别每次重跑：
  基线只在「技能实质变过」时才需要重测。
- `--config both` 一次出两份 job，用来比 `with_skill` 与基线。

### 脚本断言（`grade` 做的）

每条 slot 六条，全部免费、确定、可重复：

| 断言 | 抓什么 |
|---|---|
| `produced` | 产物在不在。不在 → `NOT-RUN`，**不是** FAIL |
| `verify` | `verify_pptx` 有无 ERROR |
| `defects` | **校准后**的缺陷数 = 0 —— 只数「连人写课件也从不触发」的类别 |
| `pages` | 页数 ≥ 下界 |
| `density` | 每页正文 ≥ 下界（防空页） |
| `figures` | 图片数 ≥ 下界 |
| `warns` | 渲染告警 ≤ 上界（**基线组不适用**，走的是另一条管线） |

**`defects` 是防误报回归，不是「技能更好」的证据。** 目前它唯一的区分力来自
`verify.gap.large`（技能产出 0 / 基线 5），而那条**校准未完成** —— 人写那份课件
的并排页配不上文字块，检查在那份上没生效，所以拿不到「老师会不会认为 0.93in 的
留白是缺陷」这个答案。能说的是：技能的图文间隙是一个系统常量（0.35，五页一致），
基线是手敲坐标、页页不同（0.627 / 0.827 / 0.927 / 0.727 / 0.627）。那是个真实、
可重复的差别；**不能说它是质量差别。**

**下界都是从实测来的，别拍脑袋改。** `min_chars_per_page` 一开始定 40，结果在
**已知良好**的参考卡组上就误报「第 1 页过空」（封面 34 字）。量了两份真卡组：

```
好·祖暅原理 [34,54,71,74,47,54,50,63,64,61,143,114]
坏·盲跑     [34,55,52,56,73,52,34,43,49,52,49,201,176]
```

最低 34，两处 —— 封面（本来就字少）与流程页（三张图为主）。改成 20。换语料要重测。

### `report` 给的两张对照表

**① 技能加了多少值（同轮两配置）。** 跑了 `--config both` 就自动出：同一个 slot，
`with_skill` 和 `without_skill` 逐条并列。**这是回答「技能有什么用」的地方** ——
它比的不是技能的两个版本，是**有技能和没有技能**。

若两边全过，报告会明说「这组断言对这条 slot 没有区分度」—— 一张整齐的表很容易被读成
「技能和不用一样好」，那是误读。也可能是断言太松。

**② 与基线的差异（跨轮）。** 加 `--baseline <某个 run 目录>` 才出，四类：
退步了 / 修好了 / **检查消失了** / 新增断言。

两张表问的不是一件事，别混：基线组是**同一个技能的历史**，对照组是**没有技能**。

### 为什么 `pass_rate` 可能是 `null`

有 `NOT-RUN` 或 `ERROR` 时**不给分数**。拿一个没跑完的分数去比较两次迭代，比出来的
多半是「哪次跳过的少」。`RUN-NOTES.md` 顶部会明说这一轮没跑完。

### 模型评分（未实现）

只判脚本看不见的：切页有没有踩认知台阶、要点行是否是书面语、每页「要学生干什么」
是否清楚。写成 **rubric 而非断言**，并允许判「无法判断」（→ `NOT-RUN`），
不逼评分者二选一。**若 `with_skill` 与基线都接近满分，说明断言不具区分度** ——
报告要明说，不能给一个好看的绿。

### 语料 `evals/corpus/`

三份自写教案，随技能包发 —— 无隐私、无版权问题：

| # | 口径 | 特征 | 格式 |
|---|---|---|---|
| `mini-1` | 10 分钟片段 · 初中 | 完整稿，要素齐全 | `.docx` |
| `mini-2` | 10 分钟片段 · 高中 | **残缺 + 三栏表格排版** | `.docx` |
| `mini-3` | 一课时 · 初中 | 详案，带设计意图与板书 | `.pdf` |

`src/*.md` 是手写源，`make_corpus.py` 由它生成 `.docx` / `.pdf`。**改语料改 `src/`，
别改生成物。** 三份盖住两种口径、两种读路径、干净与脏、初中与高中 ——
不追求统计意义（三个样本算不出分布），测的是「走得通吗、在哪类输入上退化」。

**这份语料的弱点要说清楚**：写教案的和被评的是同一个模型，基准可能**自洽而证明力弱**。
两条缓解：数学内容取自人教版真实目录与课本；结构上留了接外部真实文档的位置。

## 量不到的，别把「没查」当成「没问题」

写报告时必须标 `NOT-RUN`，不许含糊过去：

- **70pt 封面标题在真实字体度量下会不会折行** —— 需要真字体度量，`verify_pptx.py`
  的 docstring 自己承认没有。只能人眼。
- **「点击前那块内容到底藏住了没有」** —— `Slide.Export` 导出的是**点击后**的样子
  （PowerPoint 与 WPS 皆如此，已实测），抓屏在本机 150% 缩放下失败过两次。
  真正不可脚本化。
- **语义完整性**（有没有漏掉教案里的一个环节）—— 模型判断
- **视觉美观** —— 人眼
- **`verify_anim.ps1` 只读到 WPS 时**，「在 PowerPoint 里读回通过」这条是
  `NOT-RUN`，不是 `PASS`。按引擎分条：`path:` 行报的是谁，结论就归谁。
