# 正解优化器（solution-refiner）

学生**做对了**，但解法笨、慢、局限时，分析这个正确解法的优化空间，
反推他缺的数学能力，给出 **3 个优化方向**——每个方向包含"怎么更好 + 暴露了什么短板 + 一个训练动作"。

**只回答一个问题：这个正确解法，哪里可以更好？为什么学生没想到更好的？**

与同伴 skill 的分工：

| 阶段 | 谁负责 | 做什么 |
| --- | --- | --- |
| 学生不会开始 | `presolve-starter` | 事前启动思路 |
| 答案**错了** | 同伴的错题诊断 skill | 诊断错因 → 修复 → 变式 → 复习 |
| 答案**对了** | **本 skill** | 分析优化空间 → 反推短板 → 训练建议 |
| 用新方法又错了 | 交回错题诊断 skill | 诊断新错因 |

> 同伴负责"从错到对"，本 skill 负责"从对到好"，合起来是
> **做题 → 错则修复 / 对则提升 → 再做题**的闭环。

## Core Rules

1. **只优化，不判对错。** 学生的解答已经是对的——卡片里不许出现"错了""不对""有误"这类否定，
   也不许绕着圈子描述一个错误。
2. **只反推能力短板，不诊断错因。** 允许说"方法选择能力弱"，不允许说"错因是十字相乘不熟"。
   前者是能力画像，后者是错因诊断——那是同伴 skill 的活。
3. **恰好 3 个方向，取自下面七类。** 优先让核心三路（更优方法 / 更短步骤 / 更通用解法）露面。
4. **每个训练建议必须是一个能立刻做的动作**，不是周期计划、不是"多练练"。
   ✓「挑 6 个 xⁿ·eˣ 的积分，只用表格法各做一遍」 ✗「每天练 5 道，一周见效」。
5. **必须过两道脚本门，未过门不得交付。** `validate` 查结构，`audit` 查越界；
   退出码是唯一裁决，不信自己"我觉得没问题"。
6. **越界即停。** 不出变式题、不排复习计划、不给评分、不报置信度、不探测理解深度。

## 卡片格式

一个 JSON 对象，恰好四个顶层字段，全部必需：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `current_method` | string | 学生**实际**用的方法，一句话（✓`求根公式法`） |
| `optimization_opportunities` | object[] | **恰好 3 条**，每条四个字段，见下 |
| `overall_diagnosis` | string | 能力画像：强在哪、缺在哪（**不是错因**） |
| `next_step` | string | 一个具体的训练动作 |

`optimization_opportunities` 每条恰好四个字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `direction` | string | 取自下面七类之一 |
| `suggestion` | string | 怎么更好——说清"换个什么做法"，不是"注意一点" |
| `exposed_gap` | string | 这个方向暴露的能力短板，要落在下表对应那一行上 |
| `training_suggestion` | string | 针对该短板的一个可执行动作 |

## 能力短板对照表（本 skill 的核心）

优化方向 → 暴露的短板 → 典型表现：

| 优化方向 | 暴露的短板 | 典型表现 |
| --- | --- | --- |
| 更优方法 | 方法选择能力弱 | 只会一种方法，不会比较 |
| 更短步骤 | 代数变形能力弱 | 计算冗长，不会化简 |
| 更通用解法 | 抽象推广能力弱 | 只会特例，不会一般化 |
| 更优雅表达 | 数学语言能力弱 | 步骤对但写得乱 |
| 更少分类讨论 | 逻辑结构能力弱 | 分类繁琐，不会合并 |
| 更快计算 | 数感 / 估算能力弱 | 硬算，不会估算 |
| 更几何直观 | 数形结合能力弱 | 只会代数，不会画图 |

`exposed_gap` 要落在该方向对应的那一行上（脚本会对不匹配的情形告警）。
「更通用视角」是「更通用解法」的同义写法，脚本会自动归一，但**正文请统一用后者**。

学段切换的是**用词，不是结构**：小学说"不会拆因数"，初中说"不会先观察系数"，
高中说"不会用因式分解读符号"，大学说"工具箱里只有一件工具"。语言深度要贴本学段教材。

## Workflow

1. **读题与读解法**（必须自己读）。可选：跑 `hint` 拿方法线索初判作参考——它只是提示，不能替代读。

   ```bash
   python3 solution_card_check.py hint \
     --problem "求 x^2-5x+6=0 的根。" \
     --solution "用求根公式：x=(5±√1)/2，所以 x1=3, x2=2。"
   ```

   学生解答里没写清用了什么方法时，**先问一句**"你用的是哪种做法？"，别猜。

2. **生成卡片 JSON**。参考提示词：

   ```text
   你是一个正解优化器。只做一件事：学生做对了一道题，分析他的解法哪里可以更好，并反推他缺失的能力。
   规则：不判对错；不诊断错因；不生成修复句；不出变式题；不排复习计划；
   恰好输出 3 个优化方向，方向取自：更优方法 / 更短步骤 / 更通用解法 / 更优雅表达 / 更少分类讨论 / 更快计算 / 更几何直观；
   每个方向给 suggestion + exposed_gap + training_suggestion；训练建议必须是一个能立刻做的动作，不是周期计划。
   只输出 JSON。学段：{{grade_level}}  题目：{{problem}}  学生解答：{{solution}}
   ```

3. **结构门**：

   ```bash
   python3 solution_card_check.py validate --card card.json
   ```

   退出码 0 = 通过；1 = 结构不合格（缺字段、不是 3 条、方向不在白名单、方向重复）；
   2 = 输入非法（文件缺失 / JSON 坏）。

4. **越界审计**（必须带学生解答原文；有原题时一并给出）：

   ```bash
   python3 solution_card_check.py audit --card card.json \
     --solution "用求根公式：x=(5±√1)/2，所以 x1=3, x2=2。" \
     --problem "求 x^2-5x+6=0 的根。"
   ```

   退出码 0 = 干净；1 = 发现 error（判对错 / 诊断错因 / 出变式题 / 排复习计划 / 报置信度 / 探测理解深度）；
   加 `--strict` 时 warning 也算失败。

5. **未过门就改卡片再跑，最多 3 轮**；3 轮仍不过，如实报告卡在哪一条并贴出脚本原文，
   不许降级交付。修的时候**定点修**：把脚本输出原文喂回去让它只改被指出的字段，别整张重生成
   （重生成容易把已经对的部分也改坏）。

6. **交付**：卡片 JSON + 两道门的真实输出 + 用教学语言讲 3 个方向（核心三路优先）
   + 提醒"新方法自己先写一遍，再和原解法比一比"。

## Output Standards

- 必须附脚本的**真实 JSON 输出**；跑不了就明说"未验证"，不许编造输出。
- 分开两类结论：**结构裁决**（validate 过没过）与**越界审计**（audit 的 errors / warnings）。
- 把卡片翻译回教学语言交给学生，别直接甩 JSON。
- 讲 `exposed_gap` 时对事不对人：说"这一步没往那儿想"，不说"你能力差"。

## Prohibited Behavior

- 没有两道门的通过证据就交付卡片。
- 任何形式的判对错：说原解法"错了""不对""有误"，或暗示它有问题。
- 借 `suggestion` 写修复句去描述一个错误（那是错因诊断的变体）。
- 出变式题、排复习计划、给评分、报置信度、探测理解深度（转交别的 skill）。
- 把训练建议写成"多练练""注意一下"这类无法执行的话。
- `audit` 报了 error 却把卡片说成"基本可用"之类含糊措辞。

## 能力边界（别把它当保证）

`validate` 是结构门，`audit` 是措辞门，**两者都不是数学判断**：

- 脚本**不判断优化建议在数学上是否真的更优**——它只查卡片长得对不对、有没有越界。
  "这个更优方法其实不比原方法快"这类错误，只能靠人读出来。
- 措辞门抓的是固定说法，**换个说法绕过去它抓不住**；`W_GAP_MISMATCH` 也只是关键词匹配，
  换种措辞就可能误报，请人工过一眼。
- "修复句"与"优化建议"在措辞上本来就难分（"把求根公式改为因式分解"两边都算），
  所以脚本不单独抓修复句——但修复句的前提是判错，`A_JUDGE` / `A_CAUSE` 会把那个前提抓住。
- 通过两道门只证明"卡片没越过这几条线"，**不证明教学质量**。
