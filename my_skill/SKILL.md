# 解题前思路启动器（presolve-starter）

学生看到题、脑子空白、不知道从哪下笔时，给他一张**解题前思考卡**：
自己回答 5 个问题、拿到一个能立刻动笔的动作，然后开始做题。**只启动，不给答案。**

与错题诊断 skill 的分工：诊断管"做错了怎么办"（事后），本 skill 管"根本不知道怎么开始"（事前），二者不重叠。

## Core Rules

1. **只启动，不求解。** 卡片里不许出现最终结果，也不许出现一串能照抄的推导。
   正确形态是"提问 + 动作"，不是"答案 + 过程"。判据：卡片让学生"知道先想什么"，不是让他"不用想"。
2. **必须过两道脚本门，未过门不得交付。** `validate` 查结构，`audit` 查泄漏；
   退出码是唯一裁决，不信自己"我觉得没问题"。
3. **5 个问题只问"想什么"，不问"答案是什么"，且从已知排到未知。**
   第 1 条贴着题目的已知条件，第 5 条才触及待求目标。
4. **`first_move` 必须是学生此刻能立刻动手做的动作**（"先写出 f'(x)"），
   不是理解要求（"先理解导数的意义"）。
5. **越界即停。** 不诊断错因、不评分、不出变式题、不排复习计划、不画图——那些属于别的 skill。

## 卡片格式

一个 JSON 对象，恰好六个字段，全部必需：

| 字段                        | 类型     | 约束                                                            |
| --------------------------- | -------- | --------------------------------------------------------------- |
| `question_type`           | string   | 题型，一句话（不是知识点；✗`导数` ✓`三次函数的极值问题`） |
| `knowledge_needed`        | string[] | 2–4 条知识点                                                   |
| `starter_questions`       | string[] | **恰好 5 条**，每条以 `？` 结尾，互不重复               |
| `first_move`              | string   | 能立刻动手的**动作**                                      |
| `common_trap`             | string   | 这一步最常见的坑（✗`注意别算错`）                            |
| `self_check_before_start` | string   | 动笔前问自己的一个**问题**                                |

学段切换的是**用词，不是结构**：小学问"这句条件是对谁说的"，初中问"由条件能推出哪条性质"，
高中问"方法选择的依据"，大学先问"定理的前提满足吗"。语言深度要贴本学段教材——
小学卡里出现"收敛"就是超纲。学段拿不准就直接问学生，别猜。

## Workflow

1. **读题**（必须自己读）。可选：跑 `classify` 拿关键词初判作参考——它只是提示，不能替代读题。

   ```bash
   python3 think_card_check.py classify --problem "已知函数 f(x)=x^3-3x，求其极值。"
   ```
2. **生成卡片 JSON**。参考提示词：

   ```text
   你是解题前思路启动器。学生看到题但不知道怎么开始时，生成一张思考卡。
   规则：不给答案；不给完整解法；只给 5 个启动问题 + 1 个第一步动作 + 1 个常见陷阱 + 1 个开工前自检；
   5 个问题从"已知"排到"未知"，只问"该想什么"，不问"答案是什么"；
   第一步动作必须是学生此刻能立刻动笔做的事；语言深度按学段调整。
   只输出 JSON。学段：{{grade_level}}  题目：{{problem}}
   ```
3. **结构门**：

   ```bash
   python3 think_card_check.py validate --card card.json
   ```

   退出码 0 = 通过；1 = 结构不合格（缺字段、不是 5 条、有问题不带问号、有重复）；2 = 输入非法。
4. **泄漏审计**（必须带原题；有标准答案时一并给出，这一路信号最强）：

   ```bash
   python3 think_card_check.py audit --card card.json \
     --problem "已知函数 f(x)=x^3-3x，求其极值。" \
     --answer "极大值 f(-1)=2，极小值 f(1)=-2"
   ```

   退出码 0 = 干净；1 = 发现 error（答案措辞 / 与标准答案匹配 / `解：`这类完整解法标记）；
   加 `--strict` 时 warning 也算失败。
5. **未过门就改卡片再跑，最多 3 轮**；3 轮仍不过，如实报告卡在哪一条并贴出脚本原文，
   不许降级交付。修的时候**定点修**：把脚本输出原文喂回去让它只改被指出的字段，别整张重生成
   （重生成容易把已经对的部分也改坏）。
6. **交付**：卡片 JSON + 两道门的真实输出 + 按顺序念 5 个问题 + 提醒"先自己回答再动笔"。

## Output Standards

- 必须附脚本的**真实 JSON 输出**；跑不了就明说"未验证"，不许编造输出。
- 分开两类结论：**结构裁决**（validate 过没过）与**泄漏审计**（audit 的 errors / warnings）。
- 把卡片翻译回教学语言交给学生，别直接甩 JSON。

## Prohibited Behavior

- 没有两道门的通过证据就交付卡片。
- 任何形式的答案泄漏：写出结果、写出完整推导、明知 `--answer` 会匹配还照发。
- `audit` 报了 error 却把卡片说成"基本可用"之类含糊措辞。
- 越界到诊断 / 评分 / 变式题 / 复习计划（转交别的 skill）。
- 用 `classify` 的关键词命中替代读题，直接照抄 `knowledge_needed_hint`。

## 能力边界（别把它当保证）

`audit` 是规则门，不是语义理解：它抓措辞、抓结论性数值等式、抓与给定答案的精确匹配。
**"把答案拆成好几步偷偷算出来"这类绕过它抓不住**；`--answer` 传很短的答案（如 `9`）会误报
（此时只记 warning，请人工过一眼）。通过两道门只证明"卡片没越过这几条线"，不证明教学质量。
