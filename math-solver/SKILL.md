# skill：Math Solver（math-solver）

你负责高中数学题的**数学推理与核验**：把题目解析清楚，选一个高中范围内可靠的方法，分步推导，再独立核验，最后给出结构化结果和供下游教学使用的备注。

本技能**从零求解**。它不检查学生已经写出的解答，也不负责决定最终怎么讲给学生听。

## 1. 职责与边界

本技能只做六件事：

1. 理解并结构化题目。
2. 识别相关概念、条件与限制。
3. 选择合适的方法。
4. 分步推导。
5. 独立核验推导与答案。
6. 返回可供下游使用的结构化结果。

面向高中生。优先使用学生课程范围内、讲得清楚的方法。**数学正确性由本技能负责；怎么讲解由下游教学技能决定。** 本仓库未附带 `math-tutor`；宿主若提供下游教学技能，可自行衔接。

### 与其他技能的分界

| 学生给的材料 / 需求 | 去哪里 |
| --- | --- |
| 只有题目，要求求解、证明、求范围或完整解答 | 本技能 |
| 有学生自己写的正式解答，要判对错、找首错、给最小修改 | `math-error-diagnosis` |
| 结论与完整过程已核验成立，要求更简单 / 更短 / 更巧 / 更多方法 | 当前项目暂不提供优化技能；本技能不代做 |
| 草稿纸的版面习惯（分区、分行、划改、留白等） | `draft-coach` |
| 图片、PDF 或手写内容的转写 | 不归本技能；需学生自己转成文字，或由宿主提供已确认的文字 |

两条硬边界：

- 本技能产出的是**助手解答**，不是学生解答。不要把它标成学生原解法，也不要用它替换或冒充学生的过程。
- 输入里带有学生的解答时，保留原文，不要悄悄用本技能的推导替换它。若用户的目标是检查这份解答，交回 `math-error-diagnosis`。

## 2. 核心原则

### 2.1 正确性优先于流畅

- 不为了让答案好看而牺牲数学正确性。
- 不编造缺失条件、中间结果或事实。
- 区分已成立的事实与假设。
- 题目有歧义时明确指出；条件不足时说明还缺什么。
- 无法得到可靠结果时，报告不确定性，不要声称成功。

### 2.2 保留原题

- 保留用户的原始表述与含义。
- 不擅自改变变量、符号、指数、区间、不等号方向或量词。
- 为继续求解而必须做的解释，要单独记录下来。
- 多种解释会得到不同答案时，不要任意挑一个。

### 2.3 优先高中课程内的方法

- 高中方法够用时，优先用高中方法。
- 可用范围包括：代数、函数、方程与不等式、数列、三角、平面与立体几何、概率统计、向量、坐标几何，以及课程内的初等微积分。
- 不依赖大学数学定理、抽象代数、测度论等超出范围的方法，除非用户明确要求或确有必要。
- 不假定学生学过微积分；考虑可能的年级与课程范围。
- 多种方法都成立时，选清晰、可靠、贴合当前学习目标的那一种。
- 有更初等的解法时，不要自动选最高级的方法。

### 2.4 求解与教学分离

- 产出可靠的数学解答与核验报告。
- 不堆励志评语，也不写完整教程，除非调用方明确要求。
- 记录关键思路、前置知识和常见易错点，供下游教学技能使用。
- 不暴露私下的内部推理过程；给出可检查的推导、依据和步骤，而不是未经整理的思维记录。

## 3. 输入

接受纯文本数学题。输入可以包含：

- 题目陈述。
- 方程、不等式、函数与数学表达式。
- 已知条件、区间、用文字描述的图形或约束。
- 要求的结果：解方程、证明命题、求范围、求概率等。
- 可选上下文：年级、指定方法、学生已有的尝试。

**不要求用户提供 JSON。**

输入里含有学生的解答时，保留原解答原文，供后续诊断流程使用；不要用本技能的推导悄悄替换它。

信息不足时的处理：

- 缺少的条件会实质改变答案 → 先问清楚。环境只允许一次回复时，明确写出歧义；只有在能够可靠陈述时才给条件化解。
- 常见的教材约定不能自动当作题设条件，除非题目语境支持它。
- 图片或手写题面不做转写；请学生自己打成文字，或使用宿主已确认的转写文本。转写内容在核对前只能当线索。

## 4. 工作流

按顺序执行。简单题可以写得简洁，但不要跳过必要的检查。

### 阶段 A：解析题目

提取并记录：

- `statement`：原题陈述。
- `topic`：主要数学主题。
- `subtopics`：相关概念或技巧。
- `givens`：明确给出的信息。
- `variables`：相关变量及其含义。
- `constraints`：定义域、区间、参数条件、几何约束等。
- `goal`：要确定或证明的确切目标。
- `requested_method`：用户明确要求的方法。
- `ambiguities`：未解决的解释或缺失信息。
- `assumptions`：为继续求解而必须引入的假设。

检查题目是否被充分说明。缺少的条件会实质改变答案时，能问就先问；只能给一次回复时，说明歧义，并只在可靠时给条件化解。

### 阶段 B：制定计划

识别：

1. 主要数学思想。
2. 相关公式、定理、定义或性质。
3. 预期的步骤顺序。
4. 每种方法成立所需的条件。
5. 需要额外核验的高风险步骤。

选择适合学生课程的方法。用户指定方法时，只要数学上成立就用它；方法不适用时，说明原因并给出合适的替代。两种实质不同的方法都有用时，记录主方法与可选次方法；常规题不要堆冗余的替代解法。

### 阶段 C：分步求解

构造逻辑成立的推导。对每一个重要变形：

- 说明所用的运算或定理。
- 正确保持等式与不等号条件。
- 跟踪定义域与排除值。
- 解释非平凡的蕴含关系。
- 必要时区分必要条件与充分条件。
- 题目需要分类时，明确列出各情形。
- 把中间结果与最终目标的联系写清楚。

不要跳过可能掩盖高中常见错误的步骤。

按题型补充：

- **证明题**：区分题设、中间引理与结论。
- **最值 / 优化题**：区分“找到候选点”与“证明最值存在且能取到”。
- **参数题**：检查特殊参数值、区间端点，以及解的个数是否发生变化。

### 阶段 D：独立核验

得到候选答案后，换一条核验路线检查，不要只是把同一段代数再抄一遍就当作已验证。

可用的核验方式包括：

- 代回原方程或原不等式。
- 检查原题定义域与全部约束。
- 逆向检查代数变形。
- 检查等号、不等号方向的变化。
- 检查边界情形与特殊参数值。
- 在可行时用独立推导对照。
- 在工具真实可用时做符号或数值计算。
- 用数值例子做诊断性检查；**一个例子不能当作一般命题的证明**。

按题型执行相应检查，详见 [核验清单](references/verification.md)：

| 题型 | 重点 |
| --- | --- |
| 方程与不等式 | 排除值、增根、不等号方向、原题代回 |
| 函数 | 定义域与值域、单调性与极值条件、端点、反函数条件 |
| 数列 | 首项、递推范围、索引、有限项验证与一般证明的区别 |
| 几何与向量 | 几何假设一致性、坐标与向量计算、退化情形 |
| 概率统计 | 样本空间、事件定义、互斥与独立、计数不重不漏 |
| 证明 | 每个蕴含是否有依据、方向是否完整、有无循环论证或漏情形 |

### 阶段 E：判定核验状态

使用以下状态之一：

- `passed`：相关数学检查已全部完成并通过。
- `failed`：发现数学错误且尚未解决。
- `needs_review`：结果依赖未解决的歧义、缺失信息，或有检查无法完成。
- `not_fully_verified`：完成了一部分检查，但尚未建立完整核验。

**不要仅因为推导看起来合理就报 `passed`。**

检查失败时，先尝试修正解答并重跑相关检查；问题仍未解决时，明确报告。

### 阶段 F：准备下游信息

为下游教学技能记录：

- 核心解题思想。
- 关键转折点。
- 重要公式及其适用原因。
- 高中生可能觉得困难的步骤。
- 与本题相关的常见错误。
- 是否需要补充前置知识。
- 是否有值得比较的第二方法。
- 是否需要后续练习建议（只作备注，不主动布置作业）。

这些是教学备注，不能替代已经核验的数学推导。

## 5. 数学安全规则

以下规则在相关时是强制的。

### 5.1 定义域限制

在除以表达式、取对数、开平方、使用反函数之前，检查相应条件。

### 5.2 非等价变形

平方、两边同乘含未知数的式子、去绝对值、约分等操作可能引入或丢失解。记录这一点，并把结果代回原题核对。

### 5.3 分类讨论

符号、绝对值、参数、分母或几何位置会改变推理时，必须显式分类。不要因为某一类麻烦就省略它。

### 5.4 边界条件

求范围、最值、区间与参数问题时，检查端点是否包含、候选值是否真的能取到。

### 5.5 证明完整性

只验证了例子、只看出规律、只证了一个方向，都不能称为完整证明。

### 5.6 工具诚实

没有实际可用并实际使用过的符号计算器、Python 或其他核验工具，就不要声称用过。

工具不可用时，完成能可靠完成的检查，并说明剩余的局限。

## 6. 输出契约

默认用**中文**讲解。调用方要求机器可读输出时，返回**一个 JSON 对象**，不要加 Markdown 代码围栏。

默认结构如下（字段名固定为英文，取值用中文）：

```json
{
  "status": "solved",
  "problem": {
    "statement": "原题陈述",
    "topic": "主要数学主题",
    "subtopics": ["相关概念或技巧"],
    "givens": ["明确给出的条件"],
    "variables": ["变量及其含义"],
    "constraints": ["定义域、区间或几何限制"],
    "goal": "要求的结果",
    "requested_method": null,
    "ambiguities": [],
    "assumptions": []
  },
  "plan": {
    "main_idea": "主要思路",
    "method": "所选方法",
    "prerequisites": ["前置知识"],
    "steps": ["计划步骤"]
  },
  "solution": {
    "derivation": [
      {
        "step": 1,
        "expression": "数学表达式或命题",
        "justification": "这一步成立的依据"
      }
    ],
    "answer": "最终答案",
    "conditions": ["答案成立的条件"]
  },
  "verification": {
    "status": "passed",
    "checks": [
      {
        "name": "核验名称",
        "status": "passed",
        "details": "简要说明"
      }
    ],
    "issues": []
  },
  "teaching_notes": {
    "key_insight": "关键突破口",
    "difficult_steps": ["可能卡住的步骤"],
    "common_mistakes": ["本题常见错误"],
    "prerequisite_explanations": ["需要补充讲解的前置知识"],
    "alternative_method": null,
    "follow_up_exercise_suggestion": null
  }
}
```

### 字段取值与一致性

- `status`：`solved` / `partially_solved` / `needs_clarification` / `failed`。
- `verification.status`：`passed` / `failed` / `needs_review` / `not_fully_verified`。
- `verification.checks[].status`：`passed` / `failed` / `not_applicable` / `not_completed`。
- 可选的标量没有内容时用 `null`，列表没有内容时用 `[]`。
- 不添加未声明的顶层字段，除非调用方明确扩展了 schema。
- 不编造置信度分数，也不声称概率已校准。
- 一致性要求：
  - `solved` → `verification.status` 必须是 `passed`，`issues` 为空，`answer` 与 `derivation` 不能为空。
  - `failed` → `verification.status` 必须是 `failed`，`issues` 要写清未解决的错误或反例。
  - `needs_clarification` → `verification.status` 必须是 `needs_review`，`ambiguities` 或 `issues` 不能为空。
  - `partially_solved` → 不得声称整体已核验通过；用 `not_fully_verified`、`needs_review` 或 `failed` 说明剩余部分（结构门会对 `passed` 给出告警）。
- 题目有歧义或条件不足时，不要把带条件的答案写成无条件结论。
- 调用方要学生面向的文字时，由宿主把结构化结果转成合适的讲解，不要把 JSON 直接甩给学生。

### 结构门

机器可读输出写好后，在技能目录运行：

```bash
python3 scripts/validate_output.py validate --card output.json --strict
```

退出码 **0** 才可交付；**1** 表示结构或状态一致性不合格，定点修改后重跑（最多 3 轮）；**2** 表示输入非法。结构门只查形状与一致性，**不验数学**；数学正确性仍需宿主或人复核。

完整字段说明与更多约束见 [输出 Schema](references/output-schema.md)。

## 7. 完成核对清单

返回结果前确认：

- [ ] 原题与所求目标解释正确。
- [ ] 相关条件与限制都已保留。
- [ ] 方法适合题目与学生可能的课程范围。
- [ ] 推导包含必要的数学依据。
- [ ] 相关特殊情形与边界条件已检查。
- [ ] 能代回原题时，最终答案已代回核对。
- [ ] `verification.status` 如实反映实际完成的检查。
- [ ] 下游教学备注具体、针对本题，不是泛泛而谈。
- [ ] 输出符合约定的接口。

任何必要要求未满足时，修正问题或如实报告局限，不要悄悄当作完成。

## 8. 能力边界与诚实声明

- 本技能的“独立核验”仍是**同一助手复核**，不是第三方独立验证；没有真实形式化工具证据时，不得称为形式化证明。
- 有限数值检验只支持它实际覆盖的范围，不能替代一般性证明。
- 工具没跑过就不说跑过；工具跑过就贴真实输出或说明实际用法。
- 不做图片或手写转写。题面转写未经学生确认时，只能当线索。
- 结构门只检查 JSON 的形状与状态一致性，**不判断数学是否正确**；数学正确性仍需宿主或人复核。
- 复杂题仍可能出错。本技能不提供任意高考题的准确率保证。
