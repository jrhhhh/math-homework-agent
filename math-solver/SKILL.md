# 数学试卷参考答案编制

输入一份试卷，交付一份与题号、小问、分值对应的完整参考答案。默认交付经实际编译的 PDF、可编辑的 `.tex` 源码和所需本地资源。用户只要在线文字时可省去 PDF。机器调用普通求解时保留旧接口。

## 先选择执行路径

- 整卷、参考答案、评分细则、采分点请求：读取 [参考答案编写规范](references/exam-answer.md) 和 [LaTeX 排版与验收](references/latex-production.md)，使用 `assets/reference-answer.sty`。这两份规范共同定义交付要求。
- 单题普通求解：用课程范围内的方法推导并换路线复核；机读结果遵循 [原有输出契约](references/output-schema.md)，使用原有 `scripts/validate_output.py`。该结构门不验证数学。
- 用户要求检查学生已有过程：保留学生原文并交回 `math-error-diagnosis`。助手参考答案不能当作学生原稿。
- 用户要优化学生的正确解法：先完成诊断，再由 `solution-refiner` 处理。

## 整卷工作流

1. **确认原卷。** 记录来源、年份、卷型、页数；从数字 PDF/可编辑文档提取文本后，核对公式、选项、题号、小问、分值和配图。不可用残缺网页代替完整原卷。图片或扫描件的字符转写需要宿主提供的已确认文本；本技能不做 OCR。新来源不可靠时继续寻找可核对的原卷，无法确认的部分明确列出。
2. **建立覆盖清单。** 为每题及每小问登记题型、分值、依赖、解答状态。对照原卷逐项完成，不能用一题试样冒充整卷。中途示范应明确叫“版式示例”。
3. **先解题，再编评分。** 独立整理完整推导并执行适用的核验（见 [核验清单](references/verification.md)）。参考资料只作对照；不能把旧夹具、现成解析的 `passed` 状态当作本次实际核验。
4. **编制教学信息。** 围绕本题的关键数学成果设计采分点，给出简短点拨及有具体理由的难度判断。按编写规范检查等价方法、漏分和重复计分。
5. **制作 LaTeX。** 直接编写数学 LaTeX，用模板环境组织，不将 Unicode 公式或程序表达式逃逸后塞进正文。先编译一题基础题和一题长解答检查风格，再完成整卷；这是内部检查，不代替最终整卷交付。
6. **编译与复核。** 用 `scripts/build_reference_pdf.py` 执行 XeLaTeX 两遍、记录日志并拦截编译错误、缺字和溢出版心。渲染 PDF 检查公式、表格、分页和评分标记；修改后重编译再看图。
7. **交付。** 提供 PDF 和自包含的源码包；列出试卷来源、覆盖情况、实际核验与尚待核定事项。整卷未完成或数学有未解决错误时，交付物标题必须标“草稿/部分完成”，不能标“完整参考答案”。

## 全过程约束

- 题设条件、区间、量词、图形关系不变；缺失条件不擅自补入。
- 数学表达式写完整，证明中的引理必须给出适用条件及证明或可核查出处；不以“可得”“经枚举”掩盖关键步骤。
- 分值来源和教学建议分别标识；不声称建议是官方标准。不用平均分配算法把总分均摊给推导行。
- “同一助手换路线复核”“实际工具检查”“教师审阅”分别记述。数值例子不代替证明，代回不证明解集完备。
- 难度为针对目标学段的教学评价；没有学生样本就不编造难度系数、区分度或正确率。

## 工作台衔接

工作台的 `exam_answer` 模式通过 `app/core.py` 装载参考答案编写规范，生成的正文在 `reply` 中展示，原有六字段 `result` 契约不变。在线正文用 KaTeX 支持的 `\(...\)`、`\[...\]`，JSON 中反斜杠须正确转义；不要放入完整导言区、私有宏或 Markdown 表格来冒充已渲染 PDF。

目前工作台尚无自动整卷拆题、覆盖清单核验和 LaTeX/PDF 导出服务。宿主拥有文件与执行工具时，须按本技能另行编译并交付真实文件；仅返回在线正文不得声称 PDF 已生成。后续接入导出时，编译应由宿主在隔离目录执行，不能让无工具的模型声称运行过编译器。
