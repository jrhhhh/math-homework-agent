# skill：Draft Coach（草稿检查教练）

**首要：检查草稿里的计算错误。其次：看草稿的过程习惯——哪里跳步、哪里没写清楚。**

输入是学生的草稿（手写照片、文字还原，或笔迹数据）。输出一张卡片：错误清单在最前，六维过程观察和 3 条习惯在后。

不诊断知识漏洞，不贴标签，不出变式题，不排复习计划，不给整题重写。

## 与 math-error-diagnosis / solution-refiner 的分界

本技能**首要是查错**，所以和 `math-error-diagnosis` 有重叠。分界线只有一条，但它很干净：

| | 输入 | 干什么 |
| --- | --- | --- |
| `math-error-diagnosis` | **正式解答** + 原题 | 首错定位、最小修改、分层提示；有六份题型清单 |
| `draft-coach`（本技能） | **草稿** | 计算错误清单 + 过程习惯；六维过程观察是它独有的 |
| `solution-refiner` | **已核验成立的**解答 | 三个优化方向 |

**判别靠输入，不靠问题**：学生给的是**作业本 / 答卷上的正式解答**，走 `math-error-diagnosis`；给的是**草稿纸**，走本技能。两者的错误检查**不可互相替代**：本技能没有题型清单，只覆盖草稿上看得见的计算；`math-error-diagnosis` 不做过程习惯分析。

交接包（`scripts/handoff_check.py`）只服务于 `math-error-diagnosis → solution-refiner` 那条链，**与本技能无关**，不要为它生成或校验交接包。

## Core Rules

1. **先查错，后讲习惯。** 卡片里 `error_check` 排在最前；交付时先报错误，再谈习惯。草稿没错就明说没错，不要为了凑内容编一条出来。
2. **每条错误都必须有草稿依据。** `evidence` 要点名草稿里的具体位置和记号。**报一处草稿里根本没有的错误，是本技能最严重的失误**——审计的 `W_ERROR_NOT_IN_DRAFT` 就是冲这个来的。
3. **不诊断知识漏洞，不贴标签。** 可以说"这里移项没变号"，不能说"你不懂移项"；可以说"草稿没有分区"，不能说"你思维混乱"。
4. **不越界。** 不给整题重写或完整解答（`A_SOLUTION`）、不出变式题（`A_VARIANT`）、不排复习计划（`A_PLAN`）、不评分扣分（`A_SCORE`）。
5. **每条建议都是下一道题就能做的动作。** ✓「下一道题移项时把变号后那一行单独写出来」 ✗「认真检查」「多练几道」「每天练 5 道」。
6. **积极信号必须指出。** 涂改后能自我纠正、有多路径尝试、画图时机对，都要肯定；否则学生只感到被批评。
7. **学段只改用词，不改结构。** 六个维度和错误清单在任何学段都一样。默认高中学段。
8. **必须过两道脚本门，未过门不得交付。** `validate` 查结构，`audit` 查越界与证据；退出码是唯一裁决。
9. **没有草稿就不分析。** 用 `refuse` 给标准回复，不要从最终解答倒推草稿。

## 卡片格式

一个 JSON 对象，恰好六个顶层字段，全部必需：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `error_check` | object | **首要产出**，见下 |
| `dimensions` | object | **恰好 6 个维度**，键名固定，不新增不细分 |
| `top_3_habits` | object[] | **恰好 3 条**，每条恰好 `habit` / `impact` / `training` 三个字段 |
| `next_step` | string | 一句话：下一道题只做一件事 |
| `grade_level` | string | 小学 / 初中 / 高中 / 大学，默认高中 |
| `draft_source` | string | `text_reconstruction` / `stroke_data` / `image_description` |

### error_check

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `scope` | string | **必填**：这次实际检查了什么、什么没查（缺原题时尤其要写清） |
| `errors` | object[] | 允许为空数组；**没发现错误就写 `[]`，不能省略** |

`errors` 每条恰好四个字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `location` | string | 草稿里的位置 |
| `evidence` | string | 草稿里的原话或原式，**必须能对上草稿** |
| `explanation` | string | 错在哪、为什么错 |
| `fix` | string | 改成什么（最小修改，不是整题重写） |

### dimensions

六个维度键名固定：`organization`（组织度）、`skipping`（跳步模式）、`correction_pattern`（涂改模式）、`trial_and_error`（试错痕迹）、`graphic_use`（图形使用）、`draft_to_solution`（草稿利用率）。

每个维度四个字段，外加一个受限的可选字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `score` | string | 高 / 中 / 低；**只有 `draft_to_solution` 在缺少最终解答时可用「不适用」** |
| `observation` | string | 一句话观察 |
| `evidence` | string | 草稿里的具体证据，点名位置或记号 |
| `risk` | string | 这个习惯**可能导致**的问题（假设句） |
| `positive` | string | **可选，且只有 `correction_pattern` 可以写**；其他维度的积极信号写进 `observation` |

## 六维评分尺度

### 1. organization 组织度——草稿是否分区、有序、可追溯

- **高**：有明确分区，计算 / 推理 / 验证各有区域，回头能找到每一步。
- **中**：有基本顺序，但没有分区，不同运算混在一起。
- **低**：东写一块西写一块，无法追溯思考路径。

观察点：草稿纸有没有被划成不同区域？已知条件、推导过程、计算结果有没有分开写？回头检查时能不能快速定位某一步？

### 2. skipping 跳步模式——哪些步骤在草稿里消失了

- **高**：关键步骤全部落笔，可以逐步复核。
- **中**：偶尔跳步，跳的是简单步骤。
- **低**：跳步严重，心算过多，关键步骤不落笔。

观察点：从 A 到 B 之间省略了哪些必要步骤？哪些是心算完成的？跳步有没有伴随涂改？跳步常见风险：解方程跳步 → 漏根；代数变形跳步 → 符号错；代入计算跳步 → 算术错；分类讨论跳步 → 漏情况。

> 跳步和错误清单是两件事：**跳步本身不是错误**，它只是"没落笔"。同一处既可能被记进 `errors`（结果确实错了），也可能只记进 `skipping`（结果对，但过程没法复核）。两处都写时要分清。

### 3. correction_pattern 涂改模式——涂改的频率、位置、类型

- **高**：极少涂改，或涂改有明确标记和理由。
- **中**：有涂改，但能看出修改意图。
- **低**：涂改频繁，或涂改后没有留下修改理由。

观察点：是"想清楚了再改"还是"写着写着发现不对"？改的地方有没有标注为什么改？涂改集中在哪一类步骤？改完有没有保留原思路的痕迹？
**积极信号**（写进 `positive`）：涂改后能自我纠正 → 有检查意识；改处有标注 → 有反思习惯。
**风险信号**：反复涂改同一处 → 犹豫；大面积划掉 → 方法选择反复；涂改无痕迹 → 无法复盘。

### 4. trial_and_error 试错痕迹——有没有多路径尝试

- **高**：主动尝试多种方法，标注哪条走通。
- **中**：偶尔尝试备选路径。
- **低**：一条路走到黑，没有备选方案。

观察点：草稿里有没有"另一条路"的痕迹？换了方法吗？第一条路走不通时有没有换？多路径尝试有没有标号区分？风险：只用一个方法，出错就没有退路；尝试了多路径却没标注，无法判断哪条走通。

### 5. graphic_use 图形使用——有没有画图、画了什么图、什么时候画的

- **高**：主动画图辅助理解，图形清晰、标注完整。
- **中**：偶尔画图，但不够完整或不够及时。
- **低**：完全不画图，纯代数硬推。

观察点：草稿里有没有图形？图形有没有帮上理解（标了关键点、区间）？画图时机对不对（是否在动笔计算前就画了）？
适用题型：函数题 → 函数图像；几何题 → 辅助线；应用题 → 关系图；概率题 → 树状图或韦恩图；数列题 → 项的变化趋势。

### 6. draft_to_solution 草稿利用率——草稿到正解的转化率

- **高**：草稿中的计算结果全部用上了，草稿即检查。
- **中**：草稿部分被利用，部分白打。
- **低**：草稿和正解脱节，草稿白打。
- **不适用**：没有提供最终解答，无法判断转化率。宁可标不适用，也不猜一个分数。

观察点：草稿算出的结果有多少进入了最终解答？草稿里的检查步骤有没有帮助发现前后不一致？草稿是"思考工具"还是"废纸"？

## 学段适配指南

学段切换的是**用词，不是结构**——六个维度、错误清单、三段输出在任何学段都一样。

| 学段 | 语言风格 | 训练动作 | 重点维度 |
| --- | --- | --- | --- |
| 小学 | 简单、具体、像口令 | 折纸分区、每步落笔、画图 | 组织度、跳步 |
| 初中 | 清晰、鼓励、可操作 | 先观察再选方法、草稿标号 | 跳步、试错 |
| 高中 | 简洁、策略导向 | 先画图再算、多路径标号 | 图形使用、试错 |
| 大学 | 平等、元认知导向 | 探索路径标注、草稿即检查 | 草稿利用率、组织度 |

小学说"把草稿纸折成四格"，初中说"先看系数再选方法"，高中说"先画图再算"，大学才谈"多路径探索时标号"。这张表的机器可读版本在 `draft_coach_check.py` 的 `GRADE_TABLE`，**两处不一致时以脚本常量为准**。

## 输入形态与手写草稿

草稿可能是文字、照片或笔迹数据，三类输入的处理不同：

| 输入形态 | `draft_source` | 怎么处理 |
| --- | --- | --- |
| 学生自己口述或打字的草稿 | `text_reconstruction` | 直接用。布局词（左上、中间、划掉、旁边补写）**是证据本身**，转述时别丢 |
| 手写草稿的照片 / 扫描件 | `image_description` | 先转写、再核对、后分析，见下 |
| 平板导出的笔迹数据 | `stroke_data` | 按坐标还原分区、笔序和涂改，再当成上一种处理 |

**手写照片必须先转写、再核对、后分析，顺序不能颠倒：**

1. **转写**——把图像还原成"内容 + 位置 + 涂改"三层描述。逐块写清楚：左上角写了什么、哪一处被划掉、划掉之后旁边补了什么、有没有图形、图形上标了什么。**涂改和分区是观察点，不是背景**，不能用"写了几步计算"一笔带过。
2. **核对**——把转写念给学生确认，尤其是涂改和分区这两块。**看不清的记号直接点名问，不猜。**
3. **分析**——用核对过的描述走下面的流程，`draft_source` 按上表填。

核对不是客套：**它没做完就不许往下走。** 现在这一点比过去更要紧——**查错要靠转写**。把草稿里读错的一个数字写进错误清单，等于指控学生犯了一个他没犯的错。后面两门脚本都拦不住：结构门不查数学，`W_ERROR_NOT_IN_DRAFT` 只能发现"这处在草稿里找不到"，发现不了"你读错了那个数字"。照片本身不够用时（模糊、反光、笔迹实在认不出）不要硬猜，用 `refuse --reason unreadable`，让学生重拍或口述。

## 只给草稿、不给原题——可以，但查错会降级

**必需输入仍然只有草稿。** 原题、最终解答都是可选的，别因为缺原题就拒绝分析。

但**没有原题时，'查计算错误'只能降级为'查草稿内部自洽'**，这是必须对学生讲清楚的：

| 有原题 | 只有草稿 |
| --- | --- |
| 逐步核对每一步是否成立 | 只能查：同一量前后是否矛盾、等式两边是否对得上、代回是否成立、推导链是否断掉 |
| `scope` 写"逐步核对了全部可见步骤" | `scope` 必须写"只有草稿、没有原题，只核对了草稿内部的自洽性，未核对题意是否抄对、未核对解题方向是否正确" |

**不要把"草稿内部自洽"说成"我检查过了"。** 这也意味着：缺原题时，**方向性错误（列错了式子、用错了定理）基本查不出来**，只能查算术和变形。

另外，草稿本身通常自带题意：学生抄下来的条件、最后一行要求的东西，足够重建"他在算什么"。据此分析即可。

**唯一会变虚的维度是「图形使用」。** 判断"该不该画图"要知道题型——纯代数化简不画图完全正常，函数题不画图才是问题。所以：

- 绝大多数情况题型能从草稿内容认出来（出现 sin/cos 就是三角，出现三角形或辅助线就是几何，出现求和号就是数列），照常评分。
- **认不出来时，把观察限定在草稿内部**：说"有图但三个顶点都没标注"，不说"该画图却没画"。前者是草稿里的事实，后者需要原题才能成立，凭草稿猜就是编造。
- 反过来，**有了原题也不要拿它补草稿里没有的东西**——证据仍然只能来自草稿。

草稿太简略、连"在算什么"都看不出来时（只有几个孤立的数字、没有目标），**先问一句，或者退 `refuse`**，不要为了凑满六个维度硬给评分。评分是观察的结论，不是配齐的配额。

## 一整张草稿纸：先分块，再逐题分析

现实里的草稿纸又乱又多题。**整张发过来可以，但分块必须是显式的一步，而且分完要让学生确认。**

**分析单位是一道题，不是一张纸。** 把两道题的计算当成一份草稿去打分，会把"两队人马挤在一起"误判成**组织度低**，把"步骤写到别题区域去了"误判成**跳步**。**更要紧的是查错**：把甲题的条件和乙题的结果对在一起，会报出一堆根本不存在的错误。

流程：

1. **分块**——按空间位置把整张纸切成若干块，逐块写出内容，并说明这块在算什么。
2. **归属**——给每块标上属于哪道题。**没有题号、没有明显边界的，不要硬认**。
3. **核对**——把"这块是第几题"念给学生确认。**这一步没做完不许往下走。**
4. **逐题出卡**——一块一道题一张卡。过门时 `--draft` 传**那一块**的内容，不是整张纸。归属分不清的块如实说明"这块归属不明，没有纳入"，**不要凑进任何一道题里**。

给学生的现实建议：能分开拍就分开拍；非要一张纸，就在纸边写个题号——**这本身就是"组织度"的一部分**。

**脚本会把关**：草稿里出现两个以上题号标记时，`audit` 报 `W_MULTI_PROBLEM_DRAFT`。它只认题号（`第一题`、`（2）`、`①`、段落起首的 `1、`），不认普通数字，所以 `f(1)=-2` 这类记号不会误报。

### 分块确认不了时怎么办（常见）

学生常常自己也说不清那张纸上到底有几道题。**不要逼他猜，也不要自己硬认。** 六个维度对"边界"的依赖并不一样：

| 维度 | 作用域 | 分块定不下来时 |
| --- | --- | --- |
| 组织度 | **整张纸** | **不受影响**——整张纸层面本来就是它的主战场 |
| 涂改模式 | 局部 | **不受影响**：涂改痕迹落在哪一格都算数 |
| 图形使用 | 局部 | **不受影响**（"该不该画图"仍需题型才能判） |
| 跳步模式 | 单题内 | **收缩到连续区域内部**："这一段里从 A 直接到 B"成立；"这一步跑到别的题去了"不成立 |
| 试错痕迹 | 单题内 | **受影响最大**——分不清"同一题的另一条路"和"另一道题"，这一条最不可靠 |
| 草稿利用率 | 单题 | 缺最终解答时标不适用 |

**但 `error_check` 比这六条都更依赖边界**：归属错了，报出来的"错误"就是假的。所以分块确认不了时，**错误清单要么留空并写明原因，要么只报那些完全落在单一连续区域内部的错误**，并在 `scope` 里说清。**宁可少报，不可误报。**

允许出一张"整张纸"层面的卡，三条要求：交付时明说"本卡题目边界未确认"；跳步只写连续区域内部的观察；**试错那一条主动声明不可靠**。这时 `--draft` 传整张纸的转写。

## Workflow

1. **读草稿**（必须自己读）。草稿是手写照片或笔迹数据时，先按 [输入形态与手写草稿](#输入形态与手写草稿) 转写并核对；一张纸上有不止一道题时，先按 [一整张草稿纸](#一整张草稿纸先分块再逐题分析) 分块并确认归属。

2. **查错**（首要）。逐步核对草稿上的计算；有原题就对着原题核对题意，没有就在 `scope` 里写明降级范围。

3. **可选：跑 `hint` 拿六维要点与学段表作参考**——它只是提示，不能替代读。

   ```bash
   python3 draft_coach_check.py hint --draft "左上角写 x^3-3x 求极值；下面写 3x^2=3 → x^2=1 → x=1（划掉）x=±1" --grade-level 高中
   ```

4. **生成卡片 JSON**。参考提示词：

   ```text
   你是一个草稿检查教练。首要任务：检查草稿里的计算错误；其次：分析草稿的过程习惯。
   规则：不诊断知识漏洞；不贴标签；不给整题重写；不出变式题；不排复习计划；不评分；
   每条错误必须引用草稿里的原式作为证据，报不出证据的错误不要报；
   六个维度都要给评分（高/中/低）：组织度、跳步模式、涂改模式、试错痕迹、图形使用、草稿利用率，
   每个维度给 observation + evidence + risk，risk 只能是"若…可能…"的假设句，
   涂改模式的积极信号写进 positive；
   恰好 3 条习惯，每条 habit + impact + training，training 必须是下一道题就能做的动作。
   只输出 JSON。学段：{{grade_level}}  草稿：{{draft_content}}
   ```

5. **结构门**：

   ```bash
   python3 draft_coach_check.py validate --card card.json
   ```

   退出码 0 = 通过；1 = 结构不合格（缺错误清单、错误条目缺字段、缺维度、评分越界、习惯不是 3 条、多余字段）；2 = 输入非法。

6. **越界审计**（必须带草稿原文；有最终解答时一并给出）：

   ```bash
   python3 draft_coach_check.py audit --card card.json \
     --draft "左上角写 x^3-3x 求极值；…；x=1（划掉）x=±1" \
     --final-solution "极大值 2，极小值 -2。" --strict
   ```

   退出码 0 = 干净；1 = 发现 error（诊断知识漏洞 / 贴标签 / 排题量计划 / 出变式题 / 给完整解答 / 评分扣分）；
   加 `--strict` 时 warning 也算失败。**`W_ERROR_NOT_IN_DRAFT` 一定要人工看**——它是这张卡最要紧的一道闸。

7. **未过门就改卡片再跑，最多 3 轮**；3 轮仍不过，如实报告卡在哪一条并贴出脚本原文，不许降级交付。
   修的时候**定点修**：把脚本输出原文喂回去让它只改被指出的字段，别整张重生成。

8. **交付**：先报错误清单和 `scope`，再讲六维观察和 3 条习惯，最后重申 `next_step`。
   按学段调整措辞，先肯定积极信号，再指出问题。

9. **没有草稿 / 认不出来 / 请求不归本技能**：不要硬答，用 `refuse` 给标准回复。

   ```bash
   python3 draft_coach_check.py refuse --reason empty        # 无草稿，退出码 2
   python3 draft_coach_check.py refuse --reason unreadable   # 草稿无法识别，退出码 2
   python3 draft_coach_check.py refuse --reason out_of_scope # 请求不归本技能，退出码 1
   ```

   退出码的读法：**2 = 草稿本身不能当证据**（没给 / 给了但用不了）；**1 = 草稿没问题，但这个问题不归本技能管**。
   `refuse` 只负责输出标准话术，**判断理由是模型给的**——脚本认不出请求是否越界。

## Output Standards

- 必须附脚本的**真实 JSON 输出**；跑不了就明说"未验证"，不许编造输出。
- 分开三类结论：**错误清单**（含 `scope`）、**结构裁决**（validate 过没过）、**越界与证据审计**（audit 的 errors / warnings）。
- **`scope` 必须原样交给学生**：让他知道这次到底查了什么、什么没查。不写范围的"我检查过了"是误导。
- 卡片是机器接口，**交付给学生时翻译成教学语言**，别直接甩 JSON。
- 对事不对人：说"这一行移项没变号"，不说"你不认真"。
- 先讲积极信号，再讲要改的地方。

## Prohibited Behavior

- 报一条草稿里找不到证据的错误（这是本技能最严重的失误）。
- 没有两道门的通过证据就交付卡片；`W_ERROR_NOT_IN_DRAFT` 报警却当作没看见。
- 诊断知识漏洞、给学生贴标签（粗心、马虎、思维混乱、基础差）。
- 给整题重写或完整解答；出变式题；排复习计划；评分扣分；报置信度。
- 把 `training` 或 `next_step` 写成"要认真检查""多练练""每天练 5 道"这类无法在下一道题执行的话。
- 缺原题时把"草稿内部自洽"说成"检查过了"，或在 `scope` 里含糊其辞。
- 只有最终解答（没有草稿）时硬做草稿分析——那属于 `math-error-diagnosis` 的地盘。

## 能力边界（别把它当保证）

`validate` 是结构门，`audit` 是措辞门，**两者都不验数学**：

- **本技能最核心声称的是"这处算错了"，而它恰恰是两道门唯一验不了的东西。** `validate` 只看错误条目有没有四个字段；`audit` 只看证据在不在草稿里、有没有越过措辞边界。**没有人工复核的草稿检查卡不构成数学结论。**
- 审计唯一守得住的是"**错误指控必须有草稿证据**"（`W_ERROR_NOT_IN_DRAFT`）：引用了草稿却把对的判成错的，它一声不响。反过来，它也可能误报——证据里的新数值（比如"应改成 4"）如果写在 `evidence` 而不是 `fix` 里，就会被当成查无此据。
- 措辞门抓的是固定说法，**换个说法绕过去它抓不住**。
- 手写照片的转写对不对、整张纸上哪块属于哪道题，**都没有任何脚本能核**——唯一的防线是让学生确认那两步。转写读错一个数字，就会变成一条凭空指控学生的"错误"。
- 图片、笔迹、OCR 依赖宿主；本脚本只处理**文字还原或布局描述**。
- 通过两道门只证明"卡片没越过这几条线"，**不证明这份检查真的说中了这个学生**。
