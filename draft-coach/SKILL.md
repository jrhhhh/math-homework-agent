# Purpose

**skill：Draft Coach（草稿检查教练）**

学生把**草稿纸**交过来，想知道三件事：我算得对不对、哪里算错了、这张草稿本身写得怎么样。本 Skill 做两件事，**有先后**：

1. **首要——检查草稿里的计算错误。** 逐处核对，报出具体哪一行、错在哪、改成什么。
2. **其次——看过程习惯。** 分区组织、跳步、涂改、试错、画图、草稿利用率六个维度，各给判定与草稿依据。

预期结果：一张结构固定的 JSON 卡片（**错误清单在最前**，六维过程观察与习惯在后），交付学生时翻译成教学语言。卡片有两种形态，由 `analysis_basis` 区分：**完整卡**（`full`，有确认过的内容，习惯恰好 3 条）与**版面卡**（`layout_only`，只有助手亲眼看的版面，错误清单为空、只评版面能支撑的维、习惯 1–3 条）。

不诊断知识漏洞，不贴标签，不出变式题，不排复习计划，不给整题重写。

本文件是入口：`Rules`、`Workflow`、`Output Format`、`Tool Usage`、`Error Handling` 是行为契约。逐字段的约束、六维判定尺度、示例按需读取，见 [Tool Usage](#tool-usage) 的参考资源表。

# Scope

## In scope

- 检查**草稿**里的计算错误：算术、移项、符号、去括号、代数变形、求导 / 因式分解 / 极限 / 矩阵等规则性错误，以及一处错误带偏后续的传播链。
- 分析草稿的**过程习惯**：六维观察 + 3 条下一道题就能执行的训练动作。
- 指出**积极信号**：涂改后能自我纠正、有多路径尝试、画图时机对，都要肯定。
- 可处理的输入：草稿的文字还原；学生自己看手写照片写下的文字描述；**机器候选转写经学生全文核对后的确认稿**；或只有一张手写照片——此时出只依据版面的卡（本技能不内置识别引擎；未确认的机器读数不算内容）。
- 分析单位是**一道题**，不是一张纸。

## Out of scope

- **不做**：诊断知识漏洞、给学生贴标签、评分扣分、排题量或复习计划、出变式题、给整题重写或完整解答。
- 学生交的是**正式解答**（作业本 / 答卷）而不是草稿 → 走 `math-error-diagnosis` 做首错定位与分层提示。
- 要优化**已经核验成立**的解法 → 走 `solution-refiner`。
- **只有最终解答、没有草稿** → 硬做草稿分析属于越界，那同样是 `math-error-diagnosis` 的地盘。
- 跨题错因归纳、置信度、能力定级 → 都不做。
- 交接包（`scripts/handoff_check.py`）只服务 `math-error-diagnosis → solution-refiner` 那条链，**与本技能无关**，不要为它生成或校验交接包。

### 判别靠输入，不靠问题

| | 输入 | 干什么 |
| --- | --- | --- |
| `math-error-diagnosis` | **正式解答** + 原题 | 首错定位、最小修改、分层提示；有六份题型清单 |
| `draft-coach`（本技能） | **草稿** | 计算错误清单 + 过程习惯；六维过程观察是它独有的 |
| `solution-refiner` | **已核验成立的**解答 | 三个优化方向 |

两者的错误检查**不可互相替代**：本技能没有题型清单，只覆盖草稿上看得见的计算；`math-error-diagnosis` 不做过程习惯分析。

**超出能力范围时的处理方式**：不要硬答，用 `refuse` 给标准回复，见 [Error Handling](#error-handling)。

## 能力边界（别把它当保证）

`validate` 是结构门，`audit` 是措辞门，**两者都不验数学**：

- **本技能最核心声称的是"这处算错了"，而它恰恰是两道门唯一验不了的东西。** `validate` 只看错误条目有没有四个字段；`audit` 只看证据在不在草稿里、有没有越过措辞边界。**没有人工复核的草稿检查卡不构成数学结论。**
- 审计唯一守得住的是"**错误指控必须有草稿证据**"（`W_ERROR_NOT_IN_DRAFT`）：引用了草稿却把对的判成错的，它一声不响。反过来，它也可能误报——证据里的新数值（比如"应改成 4"）如果写在 `evidence` 而不是 `fix` 里，就会被当成查无此据。
- 措辞门抓的是固定说法，**换个说法绕过去它抓不住**。
- 学生给的文字对不对、整张纸上哪块属于哪道题，**都没有任何脚本能核**——唯一的防线是让学生确认那两步。内容里读错一个数字，就会变成一条凭空指控学生的"错误"。
- 图片识别依赖宿主，**本技能不内置识别引擎**：脚本处理文字还原、学生给的文字描述，或**学生逐行核对过的机器候选**。机器转写的确认是否真的发生、识别是否准确，脚本都验不了。
- 通过两道门只证明"卡片没越过这几条线"，**不证明这份检查真的说中了这个学生**。

# Inputs

## 必需输入

- **草稿**：文字还原，或学生自己看手写照片写下的文字描述。学生只给照片、没给文字时，版面看得清就可以直接出**版面卡**（见下）。

## 可选输入

- **原题**：有它才能逐步核对每一步是否成立；没有就只能查草稿内部自洽（见下）。
- **最终解答**：有它才能评「草稿利用率」；没有就标「不适用」，不要猜一个分数。
- **学段**：默认高中。

**原题与最终解答都是可选的**，不能因为缺原题就拒绝分析。

## 输入格式

草稿可能是文字，也可能是别人看了一张手写照片后写下的描述，两类输入的处理不同，`draft_source` 按实际填：

| 输入形态 | `draft_source` | `analysis_basis` | 怎么处理 |
| --- | --- | --- | --- |
| 学生自己口述或打字的草稿 | `text_reconstruction` | `full` | 直接用。布局词（左上、中间、划掉、旁边补写）**是证据本身**，转述时别丢 |
| 手写草稿的照片 + 学生的文字描述 | `image_description` | `full` | 走[两条流](references/image-intake.md)：**内容**只能来自学生的文字描述，**版面**自己看图，并把内容全文念给学生核对；见下 |
| 手写草稿的照片，**没有**文字描述 | `image_description` | `layout_only` | 不做内容分析，直接出**版面卡**（[image-intake.md 第六条](references/image-intake.md)）：错误清单为空、内容三维不适用、习惯 1–3 条；`audit --draft` 传你自己的版面描述 |
| 手写草稿的照片 → 机器候选 → 学生**逐行**核对 | `machine_transcription` | `full` | 机器出整份候选（`transcribe` 校验），学生确认/更正后的**确认稿**作 `--draft`；`scope` 写明"学生已逐行核对，更正 N 处"。未确认不得当证据（[transcription.md](references/transcription.md)） |

**本项目不含任何转写（OCR）技能**：把照片变成文字这一步不归本技能，也不许由你代劳——见 [image-intake.md](references/image-intake.md) 第一条与它引的那次实验。

## 信息缺失或存在歧义时

### 手写照片：内容靠学生的描述，版面自己看

**两件事拆开做，而且不许互相越界**（细则见 [`references/image-intake.md`](references/image-intake.md)）：

1. **内容流——写了什么**：**只能来自学生自己写下来 / 口述的文字**（`image_description`），**或经学生逐行核对确认的机器候选**（`machine_transcription`）。**未确认的机器读数不是内容**。确认稿存下来，`audit --draft` 传的就是它。
2. **版面流——长什么样**：**自己看图**，只判几何与痕迹——分了几块、哪一处被划掉、旁边补写了没有、有没有图形、行序与密度。**不许据版面观察断言某个字符是什么。**
3. **核对**——把**内容全文**念给学生确认（不是只念你不确定的那些），`draft_source` 按上表填。
4. **分析**——用核对过的内容 + 版面观察走 Workflow。

两条流**分开陈述**。合并成一句话（"左上角那行算错了"）就丢掉了"这句是看出来的还是认出来的"，而那正是这份卡最容易被冤枉学生的地方。

**为什么这么严**：查错要靠内容。把读错的一个数字写进错误清单，等于指控学生犯了一个他没犯的错。两门脚本都拦不住——结构门不查数学，`W_ERROR_NOT_IN_DRAFT` 只能发现"这处在草稿里找不到"，发现不了"你读错了那个数字"。**而且最危险的错不是"我看不清"，是"我以为我看清了"**：所以易混记号（`≤`/`<`、`±`/`+`、`6`/`8`、`1`/`7`、小数点位置）**不许单独支撑一条错误**。这时有两个出口：学生在线就走 `clarify` 只问这一处（见 [key-marks.md](references/key-marks.md)），不在线就写进 `scope` 的未核对项并出保守卡。

**本技能不内置识别引擎，也不许把未确认的读数当内容。** 学生没给文字描述时有三条路：

- 版面看得清 → 直接出[版面卡](references/image-intake.md)（`analysis_basis: "layout_only"`），明说本卡不含计算错误判断；
- 学生愿意核对 → 机器出整份**候选**（`transcribe`），学生**逐行**核对/更正，确认稿作 `--draft`，来源写 `machine_transcription`（见 [transcription.md](references/transcription.md)）；
- 请他补文字描述（口述即 `text_reconstruction`），补齐后出完整卡。

照片本身不够用时（模糊、反光、笔迹实在认不出）用 `refuse --reason unreadable`。

### 只给草稿、不给原题——可以，但查错会降级

**没有原题时，"查计算错误"只能降级为"查草稿内部自洽"**，这是必须对学生讲清楚的：

| 有原题 | 只有草稿 |
| --- | --- |
| 逐步核对每一步是否成立 | 只能查：同一量前后是否矛盾、等式两边是否对得上、代回是否成立、推导链是否断掉 |
| `scope` 写"逐步核对了全部可见步骤" | `scope` 必须写"只有草稿、没有原题，只核对了草稿内部的自洽性，未核对题意是否抄对、未核对解题方向是否正确" |

**不要把"草稿内部自洽"说成"我检查过了"。** 缺原题时，**方向性错误（列错了式子、用错了定理）基本查不出来**，只能查算术和变形。

另外，草稿本身通常自带题意：学生抄下来的条件、最后一行要求的东西，足够重建"他在算什么"。据此分析即可。

**唯一会变虚的维度是「图形使用」。** 判断"该不该画图"要知道题型——纯代数化简不画图完全正常，函数题不画图才是问题。所以：

- 绝大多数情况题型能从草稿内容认出来（出现 sin/cos 就是三角，出现三角形或辅助线就是几何，出现求和号就是数列），照常评分。
- **认不出来时，把观察限定在草稿内部**：说"有图但三个顶点都没标注"，不说"该画图却没画"。前者是草稿里的事实，后者需要原题才能成立，凭草稿猜就是编造。
- 反过来，**有了原题也不要拿它补草稿里没有的东西**——证据仍然只能来自草稿。

### 草稿太简略、看不出在算什么

只有几个孤立的数字、没有目标时，**先问一句，或者退 `refuse`**，不要为了凑满六个维度硬给评分。**评分是观察的结论，不是配齐的配额。**

### 一整张草稿纸：先分块，再逐题分析

现实里的草稿纸又乱又多题。**整张发过来可以，但分块必须是显式的一步，而且分完要让学生确认。**

**分析单位是一道题，不是一张纸。** 把两道题的计算当成一份草稿去打分，会把"两队人马挤在一起"误判成**组织度低**，把"步骤写到别题区域去了"误判成**跳步**。**更要紧的是查错**：把甲题的条件和乙题的结果对在一起，会报出一堆根本不存在的错误。

流程：

1. **分块**——按空间位置把整张纸切成若干块，逐块写出内容，并说明这块在算什么。
2. **归属**——给每块标上属于哪道题。**没有题号、没有明显边界的，不要硬认**。
3. **核对**——把"这块是第几题"念给学生确认。**这一步没做完不许往下走。**
4. **逐题出卡**——一块一道题一张卡。过门时 `--draft` 传**那一块**的内容，不是整张纸。归属分不清的块如实说明"这块归属不明，没有纳入"，**不要凑进任何一道题里**。

给学生的现实建议：能分开拍就分开拍；非要一张纸，就在纸边写个题号——**这本身就是"组织度"的一部分**。

**脚本会把关**：草稿里出现两个以上题号标记时，`audit` 报 `W_MULTI_PROBLEM_DRAFT`。它只认题号（`第一题`、`（2）`、`①`、段落起首的 `1、`），不认普通数字，所以 `f(1)=-2` 这类记号不会误报。

#### 分块确认不了时怎么办（常见）

学生常常自己也说不清那张纸上到底有几道题。**不要逼他猜，也不要自己硬认。** 六个维度对"边界"的依赖并不一样：

| 维度 | 作用域 | 分块定不下来时 |
| --- | --- | --- |
| 组织度 | **整张纸** | **不受影响**——整张纸层面本来就是它的主战场 |
| 涂改模式 | 局部 | **不受影响**：涂改痕迹落在哪一格都算数 |
| 图形使用 | 局部 | **不受影响**（"该不该画图"仍需题型才能判） |
| 跳步模式 | 单题内 | **收缩到连续区域内部**："这一段里从 A 直接到 B"成立；"这一步跑到别的题去了"不成立 |
| 试错痕迹 | 单题内 | **受影响最大**——分不清"同一题的另一条路"和"另一道题"，这一条最不可靠 |
| 草稿利用率 | 单题 | 缺最终解答时标不适用 |

**但 `error_check` 比这六条都更依赖边界**：归属错了，报出来的"错误"就是假的。所以分块确认不了时，**错误清单要么留空并写明原因，要么只报那些完全落在单一连续区域内部的错误**，并在 `scope` 里说清。**宁可少报，不可误报。**

允许出一张"整张纸"层面的卡，三条要求：交付时明说"本卡题目边界未确认"；跳步只写连续区域内部的观察；**试错那一条主动声明不可靠**。这时 `--draft` 传整张纸的转写。

# Workflow

1. **读草稿**（必须自己读）。"自己读"的含义按输入形态分：文字还原直接读；**手写照片走[两条流](references/image-intake.md)——内容用学生给的文字或经学生全文确认的机器候选，版面自己看图**。学生只给照片时：要么走 `transcribe`（机器出候选 → 学生逐行核对 → 确认稿），要么转第 2 步的版面卡分支。一张纸上有不止一道题时，先按 [一整张草稿纸：先分块，再逐题分析](#一整张草稿纸先分块再逐题分析) 分块并确认归属。

2. **查错**（首要）。逐步核对草稿上的计算；有原题就对着原题核对题意，没有就在 `scope` 里写明降级范围。**版面卡没有确认过的内容，跳过查错**：`errors` 写 `[]`，`analysis_basis` 填 `layout_only`，只评版面看得见的三维。

3. **拿不准的记号：先问，不要猜。** 如果一个记号的不同读法会改变一条要交付的结论，学生又在线，就跑 `clarify` 只问那几处（≤5 项，见 [key-marks.md](references/key-marks.md)）。**这一轮不产出分析卡。** 学生回答后，把原话追加进草稿文字（`【学生补充·原话】…`），从第 2 步重跑。学生不在线就跳过这一步，把未核对项写进 `scope` 并出保守卡。

4. **可选：跑 `hint` 拿六维要点与学段表作参考**——它只是提示，不能替代读。命令见 [Tool Usage](#tool-usage)。

5. **生成卡片 JSON**（空白骨架见 [`assets/output_template.json`](assets/output_template.json)）。参考提示词：

   ```text
   你是一个草稿检查教练。首要任务：检查草稿里的计算错误；其次：分析草稿的过程习惯。
   规则：不诊断知识漏洞；不贴标签；不给整题重写；不出变式题；不排复习计划；不评分；
   每条错误必须引用草稿里的原式作为证据，报不出证据的错误不要报；
   六个维度都要给评分（高/中/低）：组织度、跳步模式、涂改模式、试错痕迹、图形使用、草稿利用率，
   每个维度给 observation + evidence + risk，risk 只能是"若…可能…"的假设句，
   涂改模式的积极信号写进 positive；
   恰好 3 条习惯，每条 habit + impact + training，training 必须是下一道题就能做的动作。
   只输出 JSON。学段：{{grade_level}}  草稿：{{draft_content}}
   ```

   **版面卡变体**：把"检查计算错误"换成"不做任何计算错误判断，errors 写空数组"，把"六个维度都要给评分"换成"组织度、涂改模式、图形使用给评分，跳步、试错、草稿利用率标不适用"，把"恰好 3 条习惯"换成"只写版面能支撑的 1–3 条"。

6. **过结构门**（`validate`）。未过门不得交付。

7. **过越界审计**（`audit`，必须带草稿原文；版面卡带你自己的版面描述；有最终解答时一并给出）。

8. **未过门就改卡片再跑，最多 3 轮**；3 轮仍不过，如实报告卡在哪一条并贴出脚本原文，**不许降级交付**。修的时候**定点修**：把脚本输出原文喂回去，让它只改被指出的字段，别整张重生成。

9. **交付**：完整卡先报错误清单和 `scope`，再讲六维观察和 3 条习惯，最后重申 `next_step`；版面卡先明说"本卡不含任何计算错误的判断"，再讲版面观察与 1–3 条习惯。按学段调整措辞，先肯定积极信号，再指出问题。

10. **没有草稿 / 认不出来 / 请求不归本技能**：不要硬答，用 `refuse` 给标准回复，见 [Error Handling](#error-handling)。

# Rules

## Must

1. **先查错，后讲习惯。** 卡片里 `error_check` 排在最前；交付时先报错误，再谈习惯。草稿没错就明说没错，不要为了凑内容编一条出来。（版面卡没有内容可查，`errors` 必须为空，交付时先说清这一点。）
2. **每条错误都必须有草稿依据。** `evidence` 要点名草稿里的具体位置和记号。判定对错、指出"这一步算错了"、给出该写成什么，**都是本职**。
3. **每条建议都是下一道题就能做的动作。** ✓「下一道题移项时把变号后那一行单独写出来」 ✗「认真检查」「多练几道」「每天练 5 道」。
4. **积极信号必须指出。** 涂改后能自我纠正、有多路径尝试、画图时机对，都要肯定；否则学生只感到被批评。
5. **学段只改用词，不改结构。** 六个维度和错误清单在任何学段都一样。默认高中学段。
6. **必须过两道脚本门，未过门不得交付。** `validate` 查结构，`audit` 查越界与证据；**退出码是唯一裁决**。
7. **跳步不是错误。** 跳步只是"没落笔"。同一处既可能进 `errors`（结果确实错了），也可能只进 `skipping`（结果对但没法复核）。两处都写时要分清。
8. **交付时附脚本的真实输出。** 跑不了就明说"未验证"，不许编造输出。分开陈述三类结论：**错误清单**（含 `scope`）、**结构裁决**、**越界与证据审计**。
9. **`scope` 必须原样交给学生**，让他知道这次到底查了什么、什么没查。**不写范围的"我检查过了"是误导。** 卡片是机器接口，**交付时要翻译成教学语言**，别直接甩 JSON。
10. **对事不对人**：说"这一行移项没变号"，不说"你不认真"。
11. **划改状态决定一条算不算错。** 只看草稿的**可见状态**，三态分清：

    | 草稿状态 | 怎么处理 |
    | --- | --- |
    | 划线 **+** 旁边补写了正确式子 | 已自我纠正 → 进 `correction_pattern.positive`，**不是**现存错误 |
    | 划线 **+** 没有补写（放弃的备选路径） | 也**不是**现存错误 → 只在 `trial_and_error` / `correction_pattern` 里观察 |
    | 有划线，但后续**仍沿用旧值** | 旧值**仍是**错误，照报 |

    拿不准时按"宁可少报，不可误报"处理：**进错误清单的必须是学生当前仍在使用的式子**。
    被划掉的那条路径即使本身写得不完整（少一个根、少一步），也不算错——
    学生已经放弃它了；那属于 `trial_and_error` 的观察，不是 `errors`。
12. **图片输入：内容必须出自学生的文字，或经学生全文确认的机器候选；版面必须自己看，两条流分开陈述。** 未确认的机器读数**不是内容**，不许拿它报错，也不许把版面观察当成内容。`audit --draft` 传学生给的文字或确认稿，不传未经确认的版本。
13. **易混记号不许单独支撑一条错误。** `≤`/`<`、`≥`/`>`、`±`/`+`、`6`/`8`、`1`/`7`、`0`/`6`、小数点与上标位置——从图片读来的这类记号，如果一条错误没它就立不住，就**不报进 `errors`**：学生在线走 `clarify` 只问这一处，不在线写进 `scope` 的未核对项并附判据。**候选只能来自学生文字点过名的角色，不许从字形推断**（见 [key-marks.md](references/key-marks.md)）。
14. **没有文字描述时出的是版面卡，不是"检查过了"。** `analysis_basis` 必须填 `layout_only`，`errors` 必须为空，`scope` 里必须出现「内容未经学生确认」或「不含计算错误判断」，`audit --draft` 传只含版式事实的版面描述。把版面卡说成"我检查了你的计算"是误导，也是最容易冤枉学生的地方。

## Must not

- **报一条草稿里找不到证据的错误**——这是本技能最严重的失误，`W_ERROR_NOT_IN_DRAFT` 就是冲这个来的。
- **把已划掉、旁边没有补写的放弃路径当成现存错误报出**（那是假错，判据见 Must 11）。
- 没有两道门的通过证据就交付卡片；`W_ERROR_NOT_IN_DRAFT` 报警却当作没看见。
- 诊断知识漏洞、给学生贴标签（粗心、马虎、思维混乱、基础差）。**可以说"这里移项没变号"，不能说"你不懂移项"；可以说"草稿没有分区"，不能说"你思维混乱"。**
- 给整题重写或完整解答（`A_SOLUTION`）；出变式题（`A_VARIANT`）；排复习计划（`A_PLAN`）；评分扣分（`A_SCORE`）；报置信度。
- 把 `training` 或 `next_step` 写成"要认真检查""多练练""每天练 5 道"这类无法在下一道题执行的话。
- 缺原题时把"草稿内部自洽"说成"检查过了"，或在 `scope` 里含糊其辞。
- 把版面卡（`layout_only`）说成查过计算错误，或在版面卡里报任何一条 `errors`。
- 只有最终解答（没有草稿）时硬做草稿分析。
- **没有草稿就不分析**：用 `refuse` 给标准回复，不要从最终解答倒推草稿。

# Output Format

分析卡是一个 JSON 对象，**恰好七个顶层字段，全部必需**（`clarify` 那一轮不产出这张卡，只输出问题单）：

`error_check`（首要产出）· `dimensions`（恰好 6 维，键名固定）· `top_3_habits`（完整卡恰好 3 条，版面卡 1–3 条；每条 `habit`/`impact`/`training`）· `next_step` · `grade_level`（小学/初中/高中/大学）· `draft_source`（`text_reconstruction`/`image_description`/`machine_transcription`）· `analysis_basis`（`full`/`layout_only`）

四个容易记错的硬约束：

- `error_check` 恰好两字段：`scope`（**必填**，写明这次检查了什么、什么没查）与 `errors`（**允许空数组，但不能省略这个字段**）。每条错误恰好四字段 `location`/`evidence`/`explanation`/`fix`。
- 每个维度四字段 `score`/`observation`/`evidence`/`risk`；`positive` **只有 `correction_pattern` 可以写**，其他维度的积极信号写进 `observation`。
- `score` 取 高/中/低。**`不适用` 的适用范围由 `analysis_basis` 决定**：完整卡里只许 `draft_to_solution` 在缺最终解答时用；版面卡里 `skipping`/`trial_and_error`/`draft_to_solution` 必须为 `不适用`，`organization`/`correction_pattern` 必须真实评分，`graphic_use` 只在无图且题型判不了时可用 `不适用`。`risk` 必须是「若…可能…」的假设句。
- **版面卡不是"不完整的完整卡"**：`analysis_basis: "layout_only"` 时 `errors` 必须为空、`draft_source` 必须是 `image_description`；违反任一条，结构门直接判不合格（`E_BASIS_ERRORS` / `E_BASIS_SOURCE`）。

六维键名固定、顺序固定：`organization`（组织度）· `skipping`（跳步模式）· `correction_pattern`（涂改模式）· `trial_and_error`（试错痕迹）· `graphic_use`（图形使用）· `draft_to_solution`（草稿利用率）。

- 逐字段类型与约束、`E_*` / `W_*` 代码表 → [`references/output-schema.md`](references/output-schema.md)
- 高/中/低怎么判、观察点、风险与积极信号、学段适配 → [`references/analysis-rules.md`](references/analysis-rules.md)
- 空白骨架 → [`assets/output_template.json`](assets/output_template.json)（**未填的骨架**，直接跑 `validate` 会因占位值报 `E_BAD_SCORE` / `E_BAD_GRADE` / `E_BAD_SOURCE` / `E_BAD_ANALYSIS_BASIS`，填完再跑）

# Tool Usage

## 可用工具

| 工具 | 用在哪 | 命令 | 退出码 |
| --- | --- | --- | --- |
| 结构门 | 出卡后，审计前 | `python3 scripts/validate_output.py validate --card card.json` | **0** 通过 · **1** 结构不合格（缺错误清单、错误条目缺字段、缺维度、评分越界、习惯条数不合法、分析依据与评分/来源不符、多余字段） · **2** 输入非法 |
| 越界审计 | 结构门过之后，交付之前 | `python3 scripts/audit_output.py audit --card card.json --draft "…" [--final-solution "…"] [--strict]` | **0** 干净 · **1** 发现 error（诊断知识漏洞 / 贴标签 / 排题量计划 / 出变式题 / 给完整解答 / 评分扣分） · **2** 输入非法 |
| 拒绝出口 | 没有草稿 / 认不出来 / 请求不归本技能 | `python3 scripts/audit_output.py refuse --reason empty\|unreadable\|out_of_scope` | **empty → 2** · **unreadable → 2** · **out_of_scope → 1** |
| 澄清出口 | 关键记号拿不准、且会改变结论 | `python3 scripts/audit_output.py clarify --input questions.json` | **0** 问题单有效并输出 · **1** 问题单不合格 · **2** 输入非法 |
| 转写出口 | 只有照片、学生愿意逐行核对 | `python3 scripts/audit_output.py transcribe --input candidate.json` | **0** 候选稿有效并输出 · **1** 候选稿不合格 · **2** 输入非法 |
| 六维提示 | 可选，读草稿之前或之后 | `python3 scripts/validate_output.py hint --draft "…" [--grade-level 高中]` | 输入合法时总是 **0** |

## 参数与调用顺序

`validate` → `audit` → （通过才）交付。顺序不能颠倒：结构不合法时审计的措辞判定没有意义。

- `audit` **必须带 `--draft` 的草稿原文**；整张草稿纸要传**分块后的那一块**，不是整张纸。**图片输入要传学生给的那份文字**（见 [`references/image-intake.md`](references/image-intake.md)），不传自己复述的版本——这样"证据在不在草稿里"才是机器能查的事。
- **版面卡的 `--draft` 是例外**：传你自己的**版面描述**（分块、涂改、图形、行序，不含任何字符内容）。审计会据此识别 `layout_only` 并跳过"证据是否出自草稿""卡片与草稿关联度""多个题号"这几项——那几项在版面卡上只会自我循环，不是漏检。
- 有最终解答时一并给 `--final-solution`：它同时用于「草稿利用率」的核查（给了最终解答却把利用率标成「不适用」会报 `W_UTILIZATION_UNAVAILABLE`）。
- **加 `--strict` 时 warning 也算失败**。`W_ERROR_NOT_IN_DRAFT` 一定要人工看——它是这张卡最要紧的一道闸。
- `refuse` 只负责输出标准话术，**判断理由是模型给的**——脚本认不出请求是否越界。
- `clarify` 是**另一条出口，不是卡片**：跑它的那一轮不产出分析卡，调用方看 `action`（`clarify`）判断，别把退出码 0 当成"卡片已就绪"。问题单 ≤5 项，候选可选，措辞与卡片同标准。学生回答后把原话追加进草稿文字，再回到第 2 步重跑。
- `transcribe` 同样是出口：机器出**整份候选**，学生**逐行**核对/更正，确认稿才作 `--draft`（来源写 `machine_transcription`）。**候选不是证据**；学生没核对就退回版面卡。`candidate` 不按助手的越界措辞扫描（那是学生内容），`message` 与 `uncertain` 扫。
- `hint` 只是提示：`authority` 字段为 `heuristic-hint-only`，不能替代读草稿。

## 工具执行失败后的处理

- **未过门**：定点修改被指出的字段，重跑，**最多 3 轮**。3 轮仍不过，如实报告卡在哪一条并贴出脚本原文，**不许降级交付**。
- **退出码 2（输入非法）**：是调用方式错了（卡片文件不存在、JSON 坏、`--draft` 为空、学段非法），不是卡片内容的问题——先修调用，别改卡片。
- **脚本跑不起来**：明说"未验证"，不许凭印象写"应该会通过"，也不许编造输出。

## 结果验证方式

- 必须附脚本的**真实 JSON 输出**（`errors` / `warnings` / `passed`）。
- 交付前自查：`W_ERROR_NOT_IN_DRAFT` 是否出现；出现的每一条都人工复核过。
- **两道门都不验数学。** 通过只说明"卡片没越过结构线与措辞线"，不说明"这处算错了"判得对。**没有人工复核的草稿检查卡不构成数学结论。**

# Error Handling

| 情形 | 处理 |
| --- | --- |
| **完全没有草稿**（只给题目、只给最终解答、只有答卷） | `refuse --reason empty`，**不要从最终解答倒推草稿** |
| **草稿认不出来**（照片模糊、反光、笔迹实在认不出） | `refuse --reason unreadable`，让学生重拍或口述；**不要硬猜记号** |
| **请求不归本技能**（要变式题、复习计划、评分、找知识漏洞、跨题错因归纳） | `refuse --reason out_of_scope`；草稿本身可查的话，也可以照查草稿 + 婉拒越界部分 |
| **缺原题** | 仍要分析，但查错降级为"查草稿内部自洽"，并在 `scope` 里写明降级范围（见 [Inputs](#inputs)） |
| **只有照片、没有文字描述** | 版面看得清就直接出**版面卡**（`layout_only`）并明说不含计算错误判断；学生愿意核对就让机器出候选（`transcribe`），逐行确认后出完整卡；也可以请学生补文字描述 |
| **机器候选学生没核对** | 候选存档，但**只能出版面卡**；`scope` 写明"机器转写未经确认"。**不许把"没反对"当确认** |
| **草稿太简略、看不出在算什么** | 先问一句，或 `refuse`；**不要为了凑满六个维度硬给评分** |
| **信息冲突**（学生口述与草稿对不上、同一量前后矛盾） | 点名学生确认，**不要自己选一个**；在线走 `clarify` 只问冲突处，不在线写进 `scope` 的未核对项 |
| **局部记号拿不准**（不等号、±、小数点、上下标…） | 在线走 `clarify` 只问那几处（≤5 项），学生答后把原话补进文字再重跑；不在线写进 `scope` 并出保守卡。**不许读字形猜** |
| **题目边界确认不了** | 错误清单留空并写明原因，或只报完全落在单一连续区域内的错误；**宁可少报，不可误报** |
| **未过门** | 定点修改 ≤3 轮；仍不过如实报告并贴脚本原文，不许降级交付 |
| **脚本执行失败** | 明说"未验证"，不许编造输出，不许把"应该能过"写成"已通过" |
| **两道门都过了** | 也只证明卡片没越线。数学对不对**仍需人工复核**，不能对学生下"全对"的断言 |

# Examples

## Example 1: Normal case（正常分析）

Input:

```text
请使用 $draft-coach 检查我的草稿，先看有没有算错，再说过程习惯。

草稿：左上角写 x^3-3x 求极值；中间写 f'(x)=3x^2-3；下面写 3x^2=3 → x^2=1 → x=1（划掉）x=±1；
右边写 f(1)=1-3=-2；右下角写 f(-1)=-1+3=2；底部写 极大值2 极小值-2
```

Expected behavior:

- 判断：**草稿没有算错**，`errors` 写 `[]`，`scope` 说明核对了求导、解方程、代入求值三步。
- `correction_pattern` 给出**积极信号**：`x=1` 被划掉后补回 `±`，说明写到那一步时自己回头核对过——写进 `positive`。
- `skipping` 判为跳步明显（`3x²=3` 直接到 `x=±1`，跳过了 `x²=1`），但**不写进 `errors`**（跳步不是错误）。
- 恰好 3 条习惯，`training` 都是下一道题能执行的动作（如"开方那一步单独写一行"）。
- 过门：`validate` 退出 0，`audit --strict` 退出 0。交付时附真实输出。
- 完整卡片见 [`example/high_school_cubic.json`](example/high_school_cubic.json)，逐份说明见 [`references/examples.md`](references/examples.md)。

## Example 2: Ambiguous input（信息不足，先澄清）

Input:

```text
老师，帮我看看我这张草稿写得怎么样。

草稿：整张草稿纸上只有零星几个记号：偏左写了一个数字 3，右上角写了 12，
中间单独画了一个圆圈，圆圈的右下角写了一个等号「=」，
此外没有任何文字说明、没有完整式子、没有图形标注。
```

Expected behavior:

- 草稿太简略、连"在算什么"都看不出来 → **先追问**，不产出卡片（`card` 为 `null`）。
- 追问要问到点上：这道题要求什么、这几个记号各代表什么、圈住的是哪一步。
- **不硬凑六个维度评分**，也不凭空编一处"错误"。
- 判据与标准答案见 `evals/cases.jsonl` 的 `BOUND-03`（`expected_action: clarify`）。
- 同类情形：一张纸上有两块内容但看不出各属哪道题（`CPLX-02`）→ 先分块并让学生确认归属，**不要自己硬认**。

## Example 3: Out-of-scope request（不归本技能）

Input:

```text
这道题我算完了，不用看对错。帮我出三道同类型的变式题练练，
再给我排一个两周的复习计划，顺便按百分制打个分。

草稿：第一行 2(x+3)-4；第二行 2x+6-4=2x+2。
```

Expected behavior:

- 要变式题 / 复习计划 / 打分**都不在本技能范围内** → `refuse --reason out_of_scope`（退出码 **1**）。
- 注意退出码的含义：**1 = 草稿没问题，但这个问题不归本技能管**（区别于 2 = 草稿本身不能当证据）。
- 草稿本身是正确的（`2x+6-4=2x+2` 无误）。若选择照查草稿再婉拒越界部分，也必须**真的不产出**变式题、计划与分数——`audit` 的 `A_VARIANT` / `A_PLAN` / `A_SCORE` / `A_CAUSE` 就是冲这些来的。
- 判据见 `evals/cases.jsonl` 的 `BOUND-05`。

## Example 4: 反例（不要这样做）

Input：同 Example 1 的草稿，但卡片里报了一条**草稿里根本没有的**错误（"草稿下面还写了一行 48÷4=12"），并把 `observation` 写成"你的思维比较混乱"、把 `training` 写成"连续做 10 道解方程题"。

Expected behavior:

- 这是**本技能最严重的失误**：报了一处草稿里找不到证据的错误。
- 实际结果：`validate` 退出 **0**（结构确实齐全），`audit` 退出 **1**——`W_ERROR_NOT_IN_DRAFT` 列出查不到的候选记号（`48` / `4` / `12`），并命中 `A_LABEL`（贴标签）与 `A_PLAN`（题量计划）。
- 教训有两层：**光过结构门不代表卡片没问题，两道门都要跑**；而 `W_ERROR_NOT_IN_DRAFT` **必须人工过目**——它只能发现"草稿里找不到这处"，发现不了"你判错了"。
- 完整输出见 [`example/fabricated_error.json`](example/fabricated_error.json)。

## Example 5: 只有照片，没有文字描述（版面卡）

Input:

```text
（学生发来一张草稿纸照片，没有写任何文字说明）
```

Expected behavior:

- **不许自己读字符。** 版面看得清 → 直接出**版面卡**，不等学生补文字：`analysis_basis: "layout_only"`、`draft_source: "image_description"`、`errors: []`。
- `scope` 写明「内容未经学生确认，因此不含任何计算错误的判断」；交付时这句话要原样告诉学生。
- 三维给真实评分：组织度、涂改模式、图形使用（**无图且题型判不了**时才可标 `不适用`）；跳步、试错、草稿利用率必须 `不适用`，用「本卡只依据版面，未取得草稿内容，这一维无从判断」这类措辞。
- 习惯只写版面能支撑的，**1–3 条**，不凑数。
- `audit --draft` 传你自己的**版面描述**：能写「第三行后半段被划掉，旁边补写了一小段」，不能写「第三行原来写的是 x=1」。
- 过门：`validate` 退出 0，`audit --strict` 退出 0。
- 完整卡片见 [`example/layout_only_photo.json`](example/layout_only_photo.json)。

## Example 6: 关键记号拿不准（先问，再补文字）

Input:

```text
（学生发来照片，并说）最后一行好像有个不等号，我忘了是 < 还是 ≤。
```

Expected behavior:

- **不要猜，也不要让他重打整页。** 只有一处会改变结论（端点是否取到），就只问这一处：跑 `clarify`，`questions` 里放一项 `location` / `question` / `candidates` / `affects`。
- `candidates` 只在学生**自己点过名**的角色上给（他说了"不等号"）；如果学生没点名，只能开放式问"这一处写的是什么"。
- **这一轮不产出分析卡**，交付的就是问题单（[`example/clarify_marks.json`](example/clarify_marks.json)）。
- 学生答「是 ≤」后：把原话追加进草稿文字——
  `【学生补充·原话】位置：最后一行右端｜问题：是 < 还是 ≤？｜学生答：是 ≤`
  ——`audit --draft` 传"原文 + 补充"，`scope` 写明补充存在，然后从第 2 步重跑。
- **不许**把回答替学生改写成 `x≤1`，也不许把没问的记号当成默认值。

## Example 7: 机器先读，学生全文核对

Input:

```text
（学生发来照片，并说）我不太想打字，你直接读吧，读完给我看。
```

Expected behavior:

- **机器可以出候选，但候选不是证据。** 跑 `transcribe` 输出整份候选 + 至多 5 处 `uncertain`（形状见 [`example/transcribe_candidate.json`](example/transcribe_candidate.json)）；`message` 里明说"你确认之前我不会用它判断对错"。
- 学生要**逐行**核对整份候选（不是只看 `uncertain`）；他更正的地方原样采用，不替他润色。
- 确认后：确认稿作 `--draft`，`draft_source: "machine_transcription"`，`scope` 写"机器转写，学生已逐行核对，更正 N 处"；然后从第 2 步重跑。
- **学生没核对就只出版面卡**，`scope` 写明"机器转写未经确认"；不许把"他没反对"当成确认。
- 转写准确率**不作任何保证**：本流程只保证"未确认的读数不进结论"，不保证机器读得对。
