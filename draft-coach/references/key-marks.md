# 关键记号：只补几处，不要重述整页

本文是「拿不准的记号怎么办」的真源。它接着 [image-intake.md](image-intake.md) §4 往下写：那里说易混记号**不许单独支撑一条错误**，这里说**那么该怎么问、问完怎么办**。

一句话：**学生打字很贵，挑真正会改变结论的那几处问；问完把原话补进文字，再重跑。**

## 零、一条总则：问的是"角色"，不是"字形"

**候选选项本身可能就是内容推断。** 你从照片上看出"这是一个不等号"，已经是在读字符了——那正是本项目禁止的事。

所以：

| 合法 | 非法 |
| --- | --- |
| 学生文字里说「最后有个不等号，没写清是哪个」→ 你问「是 `<` 还是 `≤`？」 | 你从照片上认出一个符号的形状，然后问「这个是 `<` 还是 `≤`？」 |
| 版面上看到"这一行开头有一个记号"，但不知道是什么 → 你问「这一处写的是什么？」（**不给候选**） | 版面上看到一个小符号，你推断"它可能是不等号"，给出候选 |
| 学生说「那一行我划掉了」→ 你问「划掉的是整行还是后半段？」 | 你读出手写的字，再让学生"确认"你读的对不对 |

判据：**这个角色是不是学生自己的文字点过名的？** 点过名，才可以给候选；没点过名，只能开放式地问"这里写的是什么"。布局上"有一个记号"是版面事实，可以说；"这个记号是不等号"是内容，不可以说。

> **别把它和 `transcribe` 的 `readings` 混起来。** 那一份是机器先读整页时给出的"可能读法"，属于候选转写的一部分（见 [transcription.md](transcription.md)），**不是** `clarify` 的候选。机器读法不能替学生点名角色，也不许复制进 `candidates`。

## 一、哪些记号值得问

只问那些**换一种读法就会改变一条结论**的记号。常见清单：

| 记号 | 常见混淆 | 会变哪条结论 |
| --- | --- | --- |
| `≤` / `<`、`≥` / `>` | 端点开闭、不等式方向 | 解集端点、取值范围 |
| `±` / `+` | 漏解与多解 | 根的个数 |
| 负号 / 减号 / 连字符 | 符号与运算 | 这一项的正负，后面几行跟着变 |
| `6` / `8`、`1` / `7`、`0` / `6` | 系数与指数 | 计算结果 |
| 小数点位置 | `5.5` 与 `55` | 数量级 |
| 上标 / 下标位置 | `x^2` 与 `x_2` | 次数与下标 |
| 分式横线的长度 | 分子分母各包含哪些项 | 整个式子的含义 |
| 根号覆盖的范围 | 根号下包含哪几项 | 运算对象 |
| 括号是否配对 | 缺右括号、嵌套层数 | 运算顺序 |
| 度符号 `°` | 角度制与弧度 | 三角函数值 |
| 向量箭头 | 向量与标量 | 方向与数量 |
| 绝对值竖线 | 绝对值与括号 | 取值范围 |
| 变量名 `c`/`e`、`u`/`v`、`i`/`j` | 是不是同一个字母 | 是否同类项、下标是否对得上 |

清单不封闭：判据始终是"**没有这一处，你要交付的那条结论还立不立得住？**"立不住就问；立得住就不问，写进 `error_check.scope` 的未核对项即可。

## 二、什么时候问，什么时候不问

| 情形 | 怎么办 |
| --- | --- |
| 不同读法会改变一条**要交付的结论**，且学生在线 | 走 `clarify` 问这一处 |
| 不影响任何结论 | 不问，也不必写进卡 |
| 学生不在线 | 不问；写进 `error_check.scope` 的未核对项，出**保守卡**（依赖这处的结论不报） |
| 整页都认不出 / 模糊反光 | `refuse --reason unreadable`，**不要用问题单代替转写** |
| 学生文字里根本没提过这一类内容 | 只能开放式问"这里写的是什么"，不许给候选 |

**问的前提是"缺的是记号，不是内容"。** 如果缺的是整段推导，或者要问的地方超过几处，正确的动作是请学生把草稿文字发过来（`draft_source: "text_reconstruction"`），不是把问卷拉长。

## 三、一轮问几处

**最多 5 处**（`CLARIFY_MAX_QUESTIONS = 5`，脚本会拦）。超过时按顺序选：

1. 拆题：只分析当前这一道 / 这一块；
2. 请学生直接补文字描述；
3. 出更保守的卡：只报不依赖那些记号的结论。

**不许把整页变成问卷。** 连续两轮、累计超过 8 处还没问完，就说明这条路不适合这道题——改请学生补文字，或只出版面卡。

## 四、怎么问：`clarify` 出口

`clarify` 和 `refuse` 一样，是**本轮不产出分析卡的出口**。输入是一张问题单，脚本校验后原样输出，宿主可以直接渲染成"点几处 / 选一下"的界面。

```bash
python3 scripts/audit_output.py clarify --input questions.json
```

输入：

```json
{
  "message": "这张草稿里有 2 处会改变结论，只需要你补这两个记号，不用重打整页。",
  "questions": [
    {
      "location": "第二块最后一行右端",
      "question": "你提到那里有个不等号但没写清：是 < 还是 ≤？",
      "candidates": ["<", "≤"],
      "affects": "解集的右端点是否取到；如果和上一行的写法不一致，这里就自相矛盾"
    },
    {
      "location": "左边第一行开头",
      "question": "那里有一个记号，写的是什么？",
      "affects": "它决定这一项的正负；读错会让后面几行的结果都跟着变"
    }
  ]
}
```

字段要求：

| 字段 | 要求 |
| --- | --- |
| `message` | 非空；直接给学生看，一句话说清"只要补这几处" |
| `questions` | 1–5 项；问题不重复 |
| `location` | 点名位置（"第二块最后一行右端"），不要写"某处" |
| `question` | 一个问题只问一处；用学段能懂的话；候选只在角色被学生点名时给 |
| `candidates` | **可选**；给了就是 2–4 个互不重复的选项，学生可以点选 |
| `affects` | 说清**哪条结论**会跟着变；这是学生判断值不值得回答的依据 |

退出码：**0** = 问题单有效并已输出；**1** = 问题单不合格；**2** = 输入非法。**调用方看 `action`（`clarify`）判断本轮有没有卡片，不要把 0 当成"卡片已就绪"。**

## 五、学生回答后：补充文本怎么落

学生的回答是**新的学生原话**，不是你对照片的解释。规矩三条：

1. **原话不可改写。** 学生说「是 ≤」，你就记「是 ≤」，不要替他补成 `x≤1`，也不要顺手把整行"还原"出来。
2. **追加，不合并。** 在草稿文字末尾追加分隔块：

   ```text
   【学生补充·原话】位置：第二块最后一行右端｜问题：是 < 还是 ≤？｜学生答：是 ≤
   ```

3. **`audit --draft` 传"原文 + 补充"。** 补充块在 `--draft` 里，`W_ERROR_NOT_IN_DRAFT` 才能把依据和它对上；卡片 `scope` 里写明"已收到学生对 N 处记号的补充，原话见草稿补充块"。

**答案不进卡片。** 卡片不是学生文字的副本——它只保留结论、证据与边界。把回答塞进卡片会造出第二个真源，`W_ERROR_NOT_IN_DRAFT` 也就失去了意义。

落完补充后**重跑 `validate` 与 `audit`**；依赖这些记号的结论这时才可以进 `errors`。

### `draft_source` 怎么填

补充文本仍然是对**照片内容**的描述，所以 `draft_source` 保持 `image_description`；只有当学生重新打了一份完整草稿文字时，才改成 `text_reconstruction`。`analysis_basis` 是否从 `layout_only` 变成 `full`，只看**学生给的文字是否足以支撑每一条要交付的结论**——补了两处记号不等于补了整份草稿。

**如果整份文字来自机器候选**（`transcribe` → 学生逐行核对），来源是 `machine_transcription`，不是 `image_description`；协议与边界见 [transcription.md](transcription.md)。两种流程可以先后发生：先 `transcribe` 得到确认稿，再对个别记号用 `clarify` 追问。

## 六、不许做什么

- **让学生把整页重打一遍**，再从中挑几处问。
- **读字形猜记号**，或者从字形推断出"这是哪一类符号"再给候选。
- **把候选当成已确认**：学生没选之前，候选只是问题的一部分。
- **用问题套取内容**：一连串"这里写的是什么？"问到把整份草稿问出来，和全文转写没有区别。
- **把没答的问题悄悄当成默认值**；没答就是没答，写进 `scope` 的未核对项。
- **在问题单里越界**：诊断知识漏洞、贴标签、排复习计划、出变式题、给完整解答、评分——`clarify` 的措辞与卡片同标准，脚本会按同一套 `A_*` 规则扫描。
- **把 `transcribe` 的机器读法当成 `clarify` 的候选**：机器读法不是学生点过名的角色，复制过来就绕过了第零条。

## 七、交卡前自检

- [ ] 我提的每一处，换一种读法**确实会改变一条结论**；不影响结论的没有问。
- [ ] 候选只出现在**学生文字点过名**的角色上；没点名的都是开放式问题。
- [ ] 问题 ≤ 5 个；没有把"补几处"做成"重述整页"。
- [ ] `clarify` 跑过，退出码 0；`location` / `question` / `affects` 都具体。
- [ ] 学生回答后：原话原样追加、`--draft` 传了原文 + 补充、`scope` 写明了补充、两道门重跑过。
- [ ] 没答的仍留在 `scope` 的未核对项里，没有当成默认值。
