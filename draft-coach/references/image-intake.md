# 图片与笔迹草稿的入口流程（两条流）

`draft_source` 是 `image_description` 或 `stroke_data` 时读这一份。**核心是把两件事拆开做，并且不许互相越界**：

| 流 | 干什么 | 靠什么 | 不许干什么 |
| --- | --- | --- | --- |
| **内容流** | 读出**写了什么**：式子、数字、文字 | **转写技能**（OCR） | 不许自己用视觉读字符 |
| **版面流** | 看出**长什么样**：分了几个区、哪一处被划掉、旁边补了什么、有没有图形、行序与密度 | **自己看图** | 不许据版面观察断言某个字符是什么 |

两条流**平行进行、分开陈述**。合并成一句话（"左上角那行算错了"）就会丢掉"这句话是看出来的还是认出来的"，而那正是这份卡最容易被冤枉学生的地方。

## 一、内容流：转写必须来自转写技能

**手写照片 / 扫描件**：先调 **`glmocr-handwriting`** 技能；**公式密集**时并调 **`glmocr-formula`**，拿它的 LaTeX 输出核对式子结构。**笔迹数据**（`stroke_data`）先按坐标还原成图像再走同一条路。

三条硬约束：

1. **不许自己用视觉读字符。** 转写技能的规则写着 `NEVER parse handwriting yourself`——这不是客套。**你读错一个数字，就会变成一条凭空指控学生的错误，而两道门都拦不住**（结构门不查数学，`W_ERROR_NOT_IN_DRAFT` 只能发现"草稿里找不到"，发现不了"你读错了那个数字"）。
2. **不许把"两个技能都这么读的"当成验证。** 实测 `glmocr-handwriting` 与 `glmocr-formula` 的脚本**逐字节相同**（同一端点、同一模型），跑两遍是同一次调用跑两遍。两份结果一致**不构成**识别正确的证据。
3. **API 失败就停，不许视觉兜底。** 转写技能拿不到结果（未安装 / 无 key / 报错）时：
   - 学生还在线 → 请他重拍或口述，或按 `refuse --reason unreadable` 走标准出口；
   - 学生不在线、但版面看得清 → 走下面第五条"只出版面维度的降级卡"。
   **任何情况下都不要"我先估着读"。**

转写产物要**存下来**（文件名带日期与来源），后面 `audit --draft` 传的就是**它**，不是你自己复述的版本。这样"证据在不在草稿里"就变成了机器能查的事。

## 二、版面流：自己看图，只判几何与痕迹

版面**不是**文字识别，可以也必须自己看。要产出的三层描述里，**位置与涂改这两层全部来自这里**：

- **分区**：纸上有几块？块与块之间有没有分隔（横线、留白、题号）？哪块属于哪道题？
- **涂改**：哪一处被划掉？划线之后旁边补写了没有？补写的大致是几个字？有没有反复涂改？
- **图形**：有没有画图？标了什么？画在计算的哪一步之前还是之后？
- **行序与密度**：一行一步还是挤在一起？有没有大段空白跳过去？

**唯一越界的是内容**：可以写「第 3 行被划掉，旁边补写了一小段」，**不能**写「第 3 行原来写的是 x=1，改成了 x=±1」——后半句是内容，必须来自内容流。

## 三、核对：念给学生确认的是"写了什么"

把**转写文本**念给学生核对，尤其是涂改与分区这两块。核对不是让他判对错，是让他确认**你读到的和他写的是一样的**。

**"看起来读得清"不等于读清了。** 最危险的错不是"我看不清这个字"，而是**我以为我看清了**。所以核对要念的是转写**全文**，不是只念"我不确定的那些"。

## 四、易混记号：不许单独支撑一条错误

手写里形近的字，**只要是从图片读来的，就不能单独把一条错误立起来**：

| 易混 | 典型混淆 |
| --- | --- |
| `≤` / `<`、`≥` / `>` | 端点开闭、不等式方向 |
| `±` / `+` | 多解与漏解 |
| `6` / `8`、`1` / `7`、`0` / `6` | 系数与指数 |
| `c` / `e`、`u` / `v`、`i` / `j` | 下标与变量名 |
| 小数点位置、上标位置 | `x^2` 与 `x_2`、`5.5` 与 `55` |

判据是**"这条错没它就立不住吗"**：立不住，就**不要报进 `errors`**，改成写进 `scope` 的未核对项：

> 「5(2) 最后两行的端点符号请你对着原纸看一眼：如果上一行是 `<`、下一行是 `≤`，这两行就自相矛盾；如果两行一致，这里没有问题。」

这比硬报一条错有用得多，而且不会冤枉人。门脚本会对图片来源的卡片上带比较符号的证据报一条 `W_MIXED_SYMBOL_EVIDENCE` 提醒——它只是提醒，不是判决，但出现时你**必须真的回原图看一遍**再决定报不报。

## 五、降级矩阵

| 情形 | 怎么办 |
| --- | --- |
| 转写技能可用，图也清楚 | 正常走：内容流 + 版面流 + 核对 → 出完整卡片 |
| 转写技能不可用（未装 / 无 key / 报错） | **停在内容流**：不许自读字符。学生在线 → 重拍 / 口述；不在线 → 只出版面维度的降级卡（下一条） |
| 图太模糊 / 反光 / 整片认不出 | `refuse --reason unreadable`，不要硬猜 |
| 局部认不出（如某一段反光） | 认得出多少写多少；认不出的那几处**逐处点名**写进 `scope`，并说明"这几处如果读错，哪条结论会跟着变" |
| 题号 / 分块归属定不下来 | 按 SKILL.md「分块确认不了时怎么办」：整张纸层面的卡，错误清单留空或只报完全落在单一连续区域内的；试错那一条主动声明不可靠 |

## 六、只出版面维度的降级卡

转写拿不到、但版面看得清时可以出这样一张卡，三条要求：

1. **交付时明说**：本卡的转写未经识别技能、也未经学生核对，**因此不含任何计算错误的判断**；
2. `error_check.errors` **留空**，`scope` 写明原因；
3. 六维里**只给版面能支撑的那几维**：组织度、涂改模式、图形使用可以给；跳步模式、试错痕迹、草稿利用率需要内容或最终解答，给不出就按各维规则标 `不适用`/说明，**不许为凑齐六维硬评**。

## 七、交卡前的自检

- [ ] 每条 `evidence` 里的记号，都能在**转写技能的文本**里逐字找到（`audit --draft` 传的是它，跑一遍就知道）。
- [ ] 没有一条错误是**只**靠一个易混记号立起来的。
- [ ] 版面类结论（分区、涂改、图形）与内容类结论（式子、数字）在文字里能分清来源。
- [ ] `scope` 里写明了：转写来自哪个技能、哪些记号读不准、哪些结论会因它改变、核对做没做。
- [ ] 交付给学生的话里**没有**把"我没核对过的"说成"我检查过了"。
