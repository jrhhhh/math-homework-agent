# 图片草稿的入口流程（两条流）

`draft_source` 是 `image_description` 时读这一份。**核心是把两件事拆开做，并且不许互相越界**：

| 流 | 干什么 | 靠什么 | 不许干什么 |
| --- | --- | --- | --- |
| **内容流** | 读出**写了什么**：式子、数字、文字 | **学生自己写下来 / 口述的文字** | 不许自己用视觉读字符 |
| **版面流** | 看出**长什么样**：分了几个区、哪一处被划掉、旁边补了什么、有没有图形、行序与密度 | **自己看图** | 不许据版面观察断言某个字符是什么 |

两条流**平行进行、分开陈述**。合并成一句话（"左上角那行算错了"）就会丢掉"这句话是看出来的还是认出来的"，而那正是这份卡最容易被冤枉学生的地方。

## 一、内容流：只能来自学生，不能来自你

**本项目不含任何转写（OCR）技能。** 手写照片的**内容**只有一个合法来源：
**学生自己把纸上的东西写下来或说出来**。他给的这份文字就是 `image_description` 的内容，
存盘（文件名带日期与来源），`audit --draft` 传的是它，不是你复述的版本。

三条硬约束：

1. **不许自己用视觉读字符。** **你读错一个数字，就会变成一条凭空指控学生的错误，而两道门都拦不住**（结构门不查数学，`W_ERROR_NOT_IN_DRAFT` 只能发现"草稿里找不到"，发现不了"你读错了那个数字"）。
2. **不许把"我看了两遍"当成验证。** 你自己看图读出来的内容，与你自己出的卡同源，**在结构上等于自己给自己作证**。这不是"可能不准"：`W_ERROR_NOT_IN_DRAFT` 的判据是"这条证据的记号在不在 `--draft` 里"，而 `--draft` 就出自你自己的转写，于是**这条检查在此前提下恒真**——做过一次对照实验，在卡片里故意加一条只靠低把握读数的错误，`audit --strict` 照样退出 0、零告警。
3. **没有学生的文字描述就停，不许兜底。** 学生在线 → 请他重拍、打字或口述（口述即 `text_reconstruction`）；不在线、但版面看得清 → 走下面第五条"只出版面维度的降级卡"。**任何情况下都不要"我先估着读"。**

## 二、版面流：自己看图，只判几何与痕迹

版面**不是**文字识别，可以也必须自己看。要产出的三层描述里，**位置与涂改这两层全部来自这里**：

- **分区**：纸上有几块？块与块之间有没有分隔（横线、留白、题号）？哪块属于哪道题？
- **涂改**：哪一处被划掉？划线之后旁边补写了没有？补写的大致是几个字？有没有反复涂改？
- **图形**：有没有画图？标了什么？画在计算的哪一步之前还是之后？
- **行序与密度**：一行一步还是挤在一起？有没有大段空白跳过去？

**唯一越界的是内容**：可以写「第 3 行被划掉，旁边补写了一小段」，**不能**写「第 3 行原来写的是 x=1，改成了 x=±1」——后半句是内容，必须来自内容流。

## 三、核对：念给学生确认的是"写了什么"

把**内容全文**念给学生核对，尤其是涂改与分区这两块。核对不是让他判对错，是让他确认**你手上的和他写的是同一个东西**。

**"看起来读得清"不等于读清了。** 最危险的错不是"我看不清这个字"，而是**我以为我看清了**。所以核对要念的是**全文**，不是只念"我不确定的那些"。

## 四、易混记号：不许单独支撑一条错误

手写里形近的字，**只要这份内容是从图片来的，就不能单独把一条错误立起来**：

| 易混 | 典型混淆 |
| --- | --- |
| `≤` / `<`、`≥` / `>` | 端点开闭、不等式方向 |
| `±` / `+` | 多解与漏解 |
| `6` / `8`、`1` / `7`、`0` / `6` | 系数与指数 |
| `c` / `e`、`u` / `v`、`i` / `j` | 下标与变量名 |
| 小数点位置、上标位置 | `x^2` 与 `x_2`、`5.5` 与 `55` |

判据是**"这条错没它就立不住吗"**：立不住，就**不要报进 `errors`**，改成写进 `scope` 的未核对项：

> 「5(2) 最后两行的端点符号请你对着原纸看一眼：如果上一行是 `<`、下一行是 `≤`，这两行就自相矛盾；如果两行一致，这里没有问题。」

这比硬报一条错有用得多，而且不会冤枉人。门脚本会对 `image_description` 来源的卡片上带比较符号的证据报一条 `W_MIXED_SYMBOL_EVIDENCE` 提醒——它只是提醒，不是判决，但出现时你**必须真的回原图看一遍**再决定报不报。

## 五、降级矩阵

| 情形 | 怎么办 |
| --- | --- |
| 学生给了文字描述，图也清楚 | 正常走：内容流 + 版面流 + 核对 → 出完整卡片 |
| 学生没给文字描述 | **停在内容流**：不许自读字符。学生在线 → 请他打字 / 口述 / 重拍；不在线 → 只出版面维度的降级卡（下一条） |
| 图太模糊 / 反光 / 整片认不出 | `refuse --reason unreadable`，不要硬猜 |
| 局部认不出（如某一段反光） | 认得出多少写多少；认不出的那几处**逐处点名**写进 `scope`，并说明"这几处如果读错，哪条结论会跟着变" |
| 题号 / 分块归属定不下来 | 按 SKILL.md「分块确认不了时怎么办」：整张纸层面的卡，错误清单留空或只报完全落在单一连续区域内的；试错那一条主动声明不可靠 |

## 六、只出版面维度的降级卡

学生没给文字描述、但版面看得清时可以出这样一张卡，三条要求：

1. **交付时明说**：本卡的内容未经学生文字确认，**因此不含任何计算错误的判断**；
2. `error_check.errors` **留空**，`scope` 写明原因；
3. 六维里**只给版面能支撑的那几维**：组织度、涂改模式、图形使用可以给；跳步模式、试错痕迹、草稿利用率需要内容或最终解答，给不出就按各维规则标 `不适用`/说明，**不许为凑齐六维硬评**。

## 七、交卡前的自检

- [ ] 每条 `evidence` 里的记号，都能在**学生给的那份文字**里逐字找到（`audit --draft` 传的是它，跑一遍就知道）。
- [ ] 没有一条错误是**只**靠一个易混记号立起来的。
- [ ] 版面类结论（分区、涂改、图形）与内容类结论（式子、数字）在文字里能分清来源。
- [ ] `scope` 里写明了：内容来自谁、哪些记号读不准、哪些结论会因它改变、核对做没做。
- [ ] 交付给学生的话里**没有**把"我没核对过的"说成"我检查过了"。
