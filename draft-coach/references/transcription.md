# 机器转写：候选 → 全文核对 → 确认稿

本文是「机器能不能先读一遍」的真源。2026-10-17 曾把整条转写层删掉，理由是结构性的：`audit` 的 `W_ERROR_NOT_IN_DRAFT` 判的是"证据记号在不在 `--draft` 里"，如果 `--draft` 由同一个助手转写，这条检查恒真——**自己给自己作证**。

现在重开的条件不是"换了更强的模型"，而是**把独立性放回流程**：机器产出的是**候选**，只有学生逐行核对之后，它才成为 `--draft`。独立性来自学生的确认，不来自模型。

## 一、一句话

**机器可以读，但它读出来的东西在你确认之前不是内容。**

| 状态 | 叫什么 | 能干什么 |
| --- | --- | --- |
| 机器刚读出来 | **候选转写** | 只能拿去给学生看；不能进 `errors`，不能当 `--draft` 的依据 |
| 学生逐行核对/更正后 | **确认稿** | 就是 `--draft`；可以像学生自己写的一样用于分析 |
| 学生没核对 | 候选 | 退回版面卡或 `clarify`，不许默认采信 |

## 二、核对必须是全文，不是抽查

**机器在"很自信"的地方读错，学生不会看到**，那条错误就会变成一条凭空指控。`image-intake.md` §3 那句"看起来读得清 ≠ 读清了"对机器同样成立，而且更危险：机器不会告诉你它没把握。

所以：

- 学生要**逐行看过整份候选**，不是只看你标出来的"不确定处"；
- 界面可以分块呈现、一次一块，但**每一块都要过目**；
- `uncertain` 列表只是"先看这几处"的提示，**不是核对范围**。

## 三、怎么呈现：`transcribe` 出口

```bash
python3 scripts/audit_output.py transcribe --input candidate.json
```

输入：

```json
{
  "message": "下面是我从照片转写的草稿，共 3 行。请逐行核对：不对的地方直接指出来；你确认之前我不会用它判断对错。",
  "candidate": "第一行 2x+3=7\n第二行 2x=7+3=10\n第三行 x=5",
  "uncertain": [
    {"location": "第二行", "question": "等号右边是 7+3 还是 7-3？",
     "readings": ["7+3", "7-3"], "affects": "移项是否变号；这会决定 x=5 还是 x=2"}
  ]
}
```

| 字段 | 要求 |
| --- | --- |
| `message` | 非空；直接给学生看，说清"这是候选，确认前不作数" |
| `candidate` | 非空；整份转写，**原样**，不要先替学生改好 |
| `uncertain` | 可选，最多 5 项；每项 `location` / `question` / `affects` 必填，`readings` 可选（2–10 个机器读法） |

**`readings` 与 `clarify` 的 `candidates` 不是一回事。** `clarify` 的候选只能来自**学生自己点过名的角色**（"有个不等号，没写清"）；`readings` 是**机器认为可能的读法**，它本身还不算证据。**不许把 `readings` 复制进 `clarify` 的 `candidates`**——那等于让机器替你点名角色，绕过了 `key-marks.md` 第零条。

校验只查形状与措辞：`message` 与 `uncertain` 里的**助手措辞**（`location` / `question` / `affects`）按 `A_*` 越界扫描；**`candidate` 与 `readings` 不扫**——那是引用的学生材料，不是助手的建议。也不要把 `candidate` 整段抄进 `message`，否则学生自己写的"复习计划"会变成助手的越界。

输出带 `status: "awaiting_student_confirmation"` 与 `confirmation_scope: "full"`：**它明确表示"还没确认"**。退出码 **0** 有效 / **1** 不合格 / **2** 输入非法；**调用方看 `action`（`transcribe`）与 `status`，0 不表示有卡片，更不表示学生已确认。**

`uncertain` 超过 5 项会被脚本拒绝。这不是让你删问题：**说明这份候选还不适合直接进分析**，改走 `clarify`（学生自己给文字）或只出版面卡。

## 四、学生确认后：确认稿怎么落

1. **确认稿就是 `--draft`。** 学生确认或更正后的文字，原样使用；不要把他改的地方再"润色"回去。
   - **局部更正仍算 `machine_transcription`**：在机器候选上改了几处字，基底仍是机器转写，`scope` 写明"更正 N 处"。
   - **整份重写才算 `text_reconstruction`**：学生自己从头打了一遍（不再依赖机器候选），那才是学生自己的文字。
2. **卡片写 `draft_source: "machine_transcription"`。** 这个值就是在说"机器读过、学生确认过"，读者一眼能看出 provenance。**它比 `text_reconstruction` 弱一档**：学生读的是机器给的框架（锚定效应），即使确认是真诚的，也不等于他自己写出来的。
3. **`scope` 必须写明**，否则审计报 `W_TRANSCRIPTION_SCOPE_SILENT`：

   > 「机器转写，学生已逐行核对，更正 2 处。」

4. **`analysis_basis` 仍按内容判断**：确认稿足以支撑每一条要交付的结论才是 `full`；只确认了几行、其余仍缺，就还是 `layout_only` 或不出完整卡。

> **`machine_transcription` 与 `layout_only` 互斥。** 版面卡没有内容；机器转写意味着已经有内容。同时出现会被结构门判 `E_BASIS_SOURCE`。

## 五、学生没核对怎么办

| 情形 | 怎么办 |
| --- | --- |
| 学生在线但还没回 | **不出完整卡**；等他核对，或先出这轮该出的 `clarify` / 版面卡 |
| 学生不在线 | 候选稿存档，但只能出**版面卡**；`scope` 写明"机器转写未经确认，不含计算错误判断" |
| 学生明确不愿核对 | 同上。**不许把"他没反对"当成确认** |
| 学生只改了几处、没看别处 | 这不算全文核对；按未确认处理，或请他看完整份 |

## 六、诚实边界（别把它当保证）

- **确认是否真的发生，脚本验不了。** 门只能查卡片有没有声明"学生已核对"，查不了学生是不是逐行看过。provenance 仍然靠人守。
- **转写准确率没有保证。** 本命令只校验形状；它不评估识别质量。**在真实手写数学草稿上验证之前，这条路是实验性的、不是默认路径**——2026-10-17 的教训就是：渲染字形和印刷体上的成绩不能代替真实手写。
- **橡皮图章式的确认是这条路的头号风险。** 学生为了省事直接说"对"，错误就照样进清单。能做的是：让学生自己指出要改的地方、把 `uncertain` 放在最前面、不把确认做成一个默认勾选。
- **锚定效应。** 学生读一份看起来合理的候选，比从零自己写更容易点头。所以 `machine_transcription` 的可信度低于 `text_reconstruction`，文档和卡片都不许把它们说成等价。
- **确认疲劳和"全文核对"是矛盾的。** 长页面上学生很难逐字盯住。硬规则：**一次只核对一道题的一块**；这一块长到无法逐行确认，就不要走机器转写——改用 `clarify` 或只出版面卡。
- **已确认的误读，门照样放行。** 故意在候选里注入一个错的记号、再让它"被确认"，`audit --strict` 依然退出 0。这不是缺陷，是**已知限制**：门验的是"证据在不在 `--draft` 里"，验不了"`--draft` 是否真的对"。这条要和 `image-intake.md` §1 那次对照实验放在一起读。
- **形近记号提醒不再对机器转写触发。** 那条提醒（`W_MIXED_SYMBOL_EVIDENCE`）针对的是"学生自己描述照片"时的形近字；机器转写已经过逐行确认，再报它会让所有不等式题永远过不了 `--strict`。代价是橡皮图章式的 `≤`/`<` 误读不会被提醒——没有脚本能补这个洞。

## 七、不许做什么

- **把候选当确认稿直接分析**（`errors` 里出现只靠候选支撑的结论）。
- **只核对不确定处**就宣称全文已确认。
- **替学生改写确认稿**：学生说 `7-3`，你就写 `7-3`，不要顺手补成整行推导。
- **把"没回复"当默认同意**。
- **用转写准确率做承诺**，或用印刷体 / 渲染字形的测试结果代替真实手写验证。
- **把 `transcribe` 和 `clarify` 混用**：`clarify` 是学生自己给文字时只问几处；`transcribe` 是机器先给整份候选、学生全文核对。两者可以先后用，但不要用前者替代后者的核对。
- **把 `readings` 复制进 `clarify` 的 `candidates`。** `clarify` 的候选只能来自学生点过名的角色；机器读法不能替你点名。
- **把 `candidate` 整段抄进 `message`。** 学生自己写的词会被当成助手的措辞扫描。
- **把 `machine_transcription` 说成和 `text_reconstruction` 一样可靠。** 一个是学生手写，一个是学生核对机器稿；锚定效应不同。
