# 六维习惯分析规则

本文展开 `SKILL.md` 的「六维评分尺度」「学段适配指南」「只给草稿、不给原题」「一整张草稿纸」四节，并把散落的判定细节补全，供独立阅读。**规则本身以 `SKILL.md` 为准**；机器可读常量（维度键名、评分取值、学段表）以 `scripts/_rules.py` 为准，两处不一致时以脚本常量为准。

本技能**首要查错**（`error_check`），其次看六维过程习惯。六维评分是**观察的结论，不是配齐的配额**——看不出就说明看不出，不要硬给一个分数。

## 六维总览

| 键名 | 中文 | 作用域 |
| --- | --- | --- |
| `organization` | 组织度 | 整张纸 |
| `skipping` | 跳步模式 | 单题内 |
| `correction_pattern` | 涂改模式 | 局部 |
| `trial_and_error` | 试错痕迹 | 单题内 |
| `graphic_use` | 图形使用 | 局部（"该不该画图"仍需题型） |
| `draft_to_solution` | 草稿利用率 | 单题 |

键名固定、顺序固定，**不新增不细分**。每个维度给四个字段（`score` / `observation` / `evidence` / `risk`）；只有 `correction_pattern` 可以另加一个 `positive`，其余维度的积极信号写进 `observation`。字段约束见 [output-schema.md](output-schema.md)。

## 通用判定约定

- `score` 取 高 / 中 / 低。**「不适用」的适用范围由 `analysis_basis` 决定**：完整卡（`full`）里只有 `draft_to_solution` 在**缺少最终解答**时可用；版面卡（`layout_only`）见下一节。
- `observation` 一句话观察；`evidence` 点名草稿里的具体位置或记号；`risk` 只能是「若…可能…」的假设句（写成已经出错的断言会被审计的 `W_RISK_UNHEDGED` 拦下）。
- **完整卡六个维度都要给评分**，不能因为关键词没命中就跳过某一维。
- 肯定积极信号是对事不对人的要求：涂改后能自我纠正、有多路径尝试、画图时机对，都要写出来；否则学生只感到被批评。

## 1. organization 组织度——草稿是否分区、有序、可追溯

| 评分 | 尺度 |
| --- | --- |
| **高** | 有明确分区，计算 / 推理 / 验证各有区域，回头能找到每一步。 |
| **中** | 有基本顺序，但没有分区，不同运算混在一起。 |
| **低** | 东写一块西写一块，无法追溯思考路径。 |

观察点：草稿纸有没有被划成不同区域？已知条件、推导过程、计算结果有没有分开写？回头检查时能不能快速定位某一步？

风险信号：不同运算挤在同一片区域 → 回头只能从头重看；已知条件、结果、验证混写 → 分不清哪一行是依据哪一行是结论。

积极信号（写进 `observation`）：有分区或标号，已知 / 推导 / 结果各归其位。

## 2. skipping 跳步模式——哪些步骤在草稿里消失了

| 评分 | 尺度 |
| --- | --- |
| **高** | 关键步骤全部落笔，可以逐步复核。 |
| **中** | 偶尔跳步，跳的是简单步骤。 |
| **低** | 跳步严重，心算过多，关键步骤不落笔。 |

观察点：从 A 到 B 之间省略了哪些必要步骤？哪些是心算完成的？跳步有没有伴随涂改？

风险信号（按跳步类型）：解方程跳步 → 漏根；代数变形跳步 → 符号错；代入计算跳步 → 算术错；分类讨论跳步 → 漏情况。

积极信号（写进 `observation`）：代入、展开、求解每一步都在草稿上，能逐步复核。

### 跳步不是错误

**跳步本身不是错误，它只是"没落笔"。** 同一处既可能被记进 `errors`（结果确实错了），也可能只记进 `skipping`（结果对，但过程没法复核）——两处都写时要分清：

- 结果对、只是没写中间步骤 → 只进 `skipping`，不进 `errors`。
- 结果错，且错在跳掉的那一步 → 进 `errors`（引原式作证据），同时可在 `skipping` 里观察跳步模式。

把"跳步"直接当成"算错"来报，就是本技能最严重的失误之一（凭空指控）。反过来，已经确认算错的地方，也不能只写成"跳步"而漏报错误。

## 3. correction_pattern 涂改模式——涂改的频率、位置、类型

| 评分 | 尺度 |
| --- | --- |
| **高** | 极少涂改，或涂改有明确标记和理由。 |
| **中** | 有涂改，但能看出修改意图。 |
| **低** | 涂改频繁，或涂改后没有留下修改理由。 |

观察点：是"想清楚了再改"还是"写着写着发现不对"？改的地方有没有标注为什么改？涂改集中在哪一类步骤？改完有没有保留原思路的痕迹？

风险信号：反复涂改同一处 → 犹豫；大面积划掉 → 方法选择反复；涂改无痕迹 → 无法复盘。

积极信号（**只有本维度可写 `positive`**）：涂改后能自我纠正 → 有检查意识；改处有标注 → 有反思习惯。

> 草稿里有涂改痕迹、却没指出任何积极信号时，审计会报 `W_POSITIVE_ABSENT`——不是错误，但值得补上。

### 涂改状态决定一条算不算错

涂改痕迹不只是"组织度"的证据，它直接决定**这一处要不要进 `errors`**。只看草稿的可见状态，三态分清：

| 草稿状态 | 进 `errors` 吗 | 该写在哪 |
| --- | --- | --- |
| 划线 **+** 旁边补写正确式子 | **否** | `correction_pattern.positive`（自我纠正），必要时在 `observation` 里说明 |
| 划线 **+** 没有补写（放弃的备选路径） | **否** | `trial_and_error`（试过又放弃）、`correction_pattern`（划改状态） |
| 有划线，但后续**仍沿用旧值** | **是** | `errors`，引旧值那处作证据 |

判据是"学生**当前**在用哪个式子"，不是"哪个式子最漂亮"。已经放弃的路径即使写得不完整——少一个根、少一步、算错一个中间值——**都不是现存错误**：学生自己已经划掉了它，把它报出来是指控一个他没在用的式子。

> 这正是"宁可少报，不可误报"的适用面：**进错误清单的必须是草稿上当前仍生效的式子**。分不清某处是否已放弃时，不报：学生在线就走 `clarify` 问清"这一处是放弃的备选还是仍在用"，不在线就在 `scope` 的未核对项里写明（协议见 [key-marks.md](key-marks.md)）。

## 4. trial_and_error 试错痕迹——有没有多路径尝试

| 评分 | 尺度 |
| --- | --- |
| **高** | 主动尝试多种方法，标注哪条走通。 |
| **中** | 偶尔尝试备选路径。 |
| **低** | 一条路走到黑，没有备选方案。 |

观察点：草稿里有没有"另一条路"的痕迹？换了方法吗？第一条路走不通时有没有换？多路径尝试有没有标号区分？

风险信号：只用一个方法，出错就没有退路；尝试了多路径却没标注，无法判断哪条走通。

积极信号（写进 `observation`）：有第二条路的痕迹，并标了哪条走通。

> 已知脚本边界：草稿里用「方法① / 方法②」给**同一道题**的两条路径标号时，题号标记正则会把带圈序号当成题号，从而在 `audit` 触发 `W_MULTI_PROBLEM_DRAFT`（`--strict` 下会让一张正确的卡判为不过）。这是脚本边界，不是卡片问题，人工复核时按实际情况处理。**版面卡不触发这条**：版面描述常用 ①②③ 标块，审计对 `layout_only` 跳过该项。

## 5. graphic_use 图形使用——有没有画图、画了什么图、什么时候画的

| 评分 | 尺度 |
| --- | --- |
| **高** | 主动画图辅助理解，图形清晰、标注完整。 |
| **中** | 偶尔画图，但不够完整或不够及时。 |
| **低** | 完全不画图，纯代数硬推。 |

观察点：草稿里有没有图形？图形有没有帮上理解（标了关键点、区间）？画图时机对不对（是否在动笔计算前就画了）？

适用题型：函数题 → 函数图像；几何题 → 辅助线；应用题 → 关系图；概率题 → 树状图或韦恩图；数列题 → 项的变化趋势。

积极信号（写进 `observation`）：动笔计算前就画了图，并标出关键点或区间。

> 缺原题时这一维最容易被说过头：判断"该不该画图"需要题型。题型能从草稿内容认出来（出现 sin/cos 就是三角，出现三角形或辅助线就是几何，出现求和号就是数列）就照常评分；认不出来时把观察限定在草稿内部——说"有图但三个顶点都没标注"，不说"该画图却没画"。
>
> **版面卡**里没有内容，题型通常认不出来。有图就按图本身评；**草稿上无图、又判不了题型时标「不适用」**，别硬给「低」——那等于说"该画图却没画"，需要题型才成立。

## 6. draft_to_solution 草稿利用率——草稿到正解的转化率

| 评分 | 尺度 |
| --- | --- |
| **高** | 草稿中的计算结果全部用上了，草稿即检查。 |
| **中** | 草稿部分被利用，部分白打。 |
| **低** | 草稿和正解脱节，草稿白打。 |
| **不适用** | 没有提供最终解答，无法判断转化率。宁可标不适用，也不猜一个分数。 |

观察点：草稿算出的结果有多少进入了最终解答？草稿里的检查步骤有没有帮助发现前后不一致？草稿是"思考工具"还是"废纸"？

风险信号：草稿算出的结果没有进入正解 → 白打；草稿与正解不一致却没人发现 → 失去最后一次核对机会。

积极信号（写进 `observation`）：草稿中算出的结果全部进入正解，草稿本身充当了检查环节。

> 已提供最终解答却把这一维标成「不适用」，审计会报 `W_UTILIZATION_UNAVAILABLE`。

## 版面卡：只依据版面时六维怎么给

`analysis_basis: "layout_only"` 的卡没有确认过的内容，六维按下表给，**不许为了凑齐而硬评**：

| 维度 | 怎么给 |
| --- | --- |
| `organization` 组织度 | **必须给真实评分**。分区、块与块之间的分隔、行序与密度都是版面上直接看得见的。 |
| `correction_pattern` 涂改模式 | **必须给真实评分**。哪一处被划掉、旁边补没补、补写有没有标注，都是版面事实；有涂改痕迹就在 `positive` 里写积极信号。 |
| `graphic_use` 图形使用 | 有图就按图本身评；**无图且题型判不了时标「不适用」**（见上一节）。 |
| `skipping` 跳步模式 | **必须「不适用」**。没有内容，看不出哪一步落了笔、哪一步跳了。 |
| `trial_and_error` 试错痕迹 | **必须「不适用」**。看不出每段在算什么，分不清备选路径与并列步骤。 |
| `draft_to_solution` 草稿利用率 | **必须「不适用」**。没有内容，也没有最终解答可对照。 |

三条落地要求：

1. 标 `不适用` 的维度仍要填满 `observation` / `evidence` / `risk`，**写清版面为什么不支撑这一维**。标准措辞：「本卡只依据版面，未取得草稿内容，这一维无从判断。」
2. **别写「知识漏洞」「粗心」「基础差」**——这些词会命中越界审计的 `A_CAUSE` / `A_LABEL`，把一张诚实的卡判成越界。
3. `top_3_habits` 允许 1–3 条，只从组织度、涂改模式、图形使用里出。

## 学段适配表

学段切换的是**用词，不是结构**——六个维度、错误清单、三段输出在任何学段都一样。

| 学段 | 语言风格 | 训练动作 | 重点维度 |
| --- | --- | --- | --- |
| 小学 | 简单、具体、像口令 | 折纸分区、每步落笔、画图 | 组织度、跳步 |
| 初中 | 清晰、鼓励、可操作 | 先观察再选方法、草稿标号 | 跳步、试错 |
| 高中 | 简洁、策略导向 | 先画图再算、多路径标号 | 图形使用、试错 |
| 大学 | 平等、元认知导向 | 探索路径标注、草稿即检查 | 草稿利用率、组织度 |

用词示例：小学说"把草稿纸折成四格"，初中说"先看系数再选方法"，高中说"先画图再算"，大学才谈"多路径探索时标号"。

**机器可读版本在 `scripts/_rules.py` 的 `GRADE_TABLE`，两处不一致时以脚本常量为准。**

小学 / 初中不该出现「元认知 / 策略导向 / 路径标注 / 方法比较」这类措辞，否则审计报 `W_GRADE_MISMATCH`。默认高中学段。

## 只给草稿、不给原题——可以，但查错降级

**必需输入仍然只有草稿。** 原题、最终解答都是可选的，别因为缺原题就拒绝分析。没有原题时，"查计算错误"只能降级为"查草稿内部自洽"，这一点必须在 `scope` 里对学生讲清楚：

| 有原题 | 只有草稿 |
| --- | --- |
| 逐步核对每一步是否成立 | 只能查：同一量前后是否矛盾、等式两边是否对得上、代回是否成立、推导链是否断掉 |
| `scope` 写"逐步核对了全部可见步骤" | `scope` 必须写"只有草稿、没有原题，只核对了草稿内部的自洽性，未核对题意是否抄对、未核对解题方向是否正确" |

**不要把"草稿内部自洽"说成"我检查过了"。** 缺原题时，**方向性错误（列错了式子、用错了定理）基本查不出来**，只能查算术和变形。

草稿本身通常自带题意：学生抄下来的条件、最后一行要求的东西，足够重建"他在算什么"。据此分析即可，但**证据仍然只能来自草稿**；有了原题也不要拿它补草稿里没有的东西。

## 一整张草稿纸：先分块，再逐题分析

现实里的草稿纸又乱又多题。整张发过来可以，但**分块必须是显式的一步，而且分完要让学生确认**。

**分析单位是一道题，不是一张纸。** 把两道题的计算当成一份草稿去打分，会把"两队人马挤在一起"误判成**组织度低**，把"步骤写到别题区域去了"误判成**跳步**。更要紧的是查错：把甲题的条件和乙题的结果对在一起，会报出一堆根本不存在的错误。

流程：

1. **分块**——按空间位置把整张纸切成若干块，逐块写出内容，并说明这块在算什么。
2. **归属**——给每块标上属于哪道题。**没有题号、没有明显边界的，不要硬认。**
3. **核对**——把"这块是第几题"念给学生确认。**这一步没做完不许往下走。**
4. **逐题出卡**——一块一道题一张卡。过门时 `--draft` 传**那一块**的内容，不是整张纸。归属分不清的块如实说明"这块归属不明，没有纳入"，**不要凑进任何一道题里**。

给学生的现实建议：能分开拍就分开拍；非要一张纸，就在纸边写个题号——**这本身就是"组织度"的一部分**。

`audit` 会对草稿里出现两个以上题号标记的情况报 `W_MULTI_PROBLEM_DRAFT`（只认 `第一题`、`（2）`、`①`、段落起首的 `1、` 这类题号，不认 `f(1)=-2` 这样的函数记号）。

### 分块确认不了时怎么办

学生常常自己也说不清那张纸上到底有几道题。**不要逼他猜，也不要自己硬认。** 六个维度对"边界"的依赖并不一样：

| 维度 | 作用域 | 分块定不下来时 |
| --- | --- | --- |
| 组织度 | 整张纸 | **不受影响**——整张纸层面本来就是它的主战场 |
| 涂改模式 | 局部 | **不受影响**：涂改痕迹落在哪一格都算数 |
| 图形使用 | 局部 | **不受影响**（"该不该画图"仍需题型才能判） |
| 跳步模式 | 单题内 | **收缩到连续区域内部**："这一段里从 A 直接到 B"成立；"这一步跑到别的题去了"不成立 |
| 试错痕迹 | 单题内 | **受影响最大**——分不清"同一题的另一条路"和"另一道题"，这一条最不可靠 |
| 草稿利用率 | 单题 | 缺最终解答时标不适用 |

**但 `error_check` 比这六条都更依赖边界**：归属错了，报出来的"错误"就是假的。所以分块确认不了时，**错误清单要么留空并写明原因，要么只报那些完全落在单一连续区域内部的错误**，并在 `scope` 里说清。**宁可少报，不可误报。**

允许出一张"整张纸"层面的卡，三条要求：交付时明说"本卡题目边界未确认"；跳步只写连续区域内部的观察；**试错那一条主动声明不可靠**。这时 `--draft` 传整张纸的转写。

## 草稿太简略时：先追问或 refuse

草稿太简略、连"在算什么"都看不出来时（只有几个孤立的数字、没有目标），**先问一句，或者退 `refuse`**，不要为了凑满六个维度硬给评分。评分是观察的结论，不是配齐的配额。凭空编一处错误来填 `errors` 同样越界——那属于"报一条草稿里找不到证据的错误"。

没有草稿（只给题目、只给最终答案或只有答卷）时，用 `refuse --reason empty`，不要从最终解答倒推草稿。
